# Compare saved construction locality on the retained tiny prefix

This package runs the ordinary parallel reference constructor and the combined owner constructor on the same8,192-vector prefix, then measures where their exact nearest neighbors reside in their saved leaves. The owner policy enables grouped scrub validation and immutable predicate batches, keeps direct current reads disabled, and moves branches only at joined construction boundaries. This is a locality diagnostic, not ANN recall, search latency, physical actor fanout or an industry comparison.

The controller reuses the accepted940-file source archive and offline build recipe unchanged. The exact new Linux binary must be supplied by its external build receipt. The source archive is byte-identical to `consolidated-owner-construction-v1`; no Rust changes or accepted source-test repeats occur. The shared configuration uses four threads, two logical balance cuts at4,096/8,192, four owner slots, a1,024-vector placement threshold, explicit FP navigation/NPA, branching4/split256/merge64. These are diagnostic thresholds rather than a representative quality configuration. The owner arm must actually exercise multiple scheduler regions, placement and both batching mechanisms; a missed shape gate fails without retry or scale growth.

Setup has at most60seconds. It copies only25,165,824bytes into an evaluation-prefix file, hashes that copy and recomputes exact top100 for the frozen sixteen query vectors with the existing blocked FP64 NumPy engine. The engine derives corpus extent from its input file, so the one prefix copy is necessary without changing it. Setup records prefix copy/hash and GT elapsed separately. It never filters the two-million-vector GT, copies the full corpus, embeds new queries or downloads data. The source's whole SHA relies on the pinned accepted restore receipt, while each construction verifies the consumed prefix hash again. The controller verifies all source pins before the scientific-stage timer starts; that admission verification is not hidden in GT/kernel timing.

The two construction children have at most30seconds each and60seconds together. Each writes its original create-new checkpoint and streamed generation-local map. Each must pass its full saved census and full-ID exact FP distance-bit proof. The controller pins the manifest and map before diagnosis and verifies their exact bytes afterward. The existing GT command has at most30seconds per arm and60seconds together. Complete unique top100 coverage and the4,096-leaf cap remain mandatory. All scientific stages fit within180seconds and the externally fixed absolute deadline, whichever expires first. There are no retries or deadline extensions. Child timeouts do not independently enforce descendant/RSS limits; the external operator owns the existing guard and resource admission.

Map payload accounting is explicit per arm. The native publisher writes65,536bytes and verifies65,536bytes. Controller pre/post hashes read131,072bytes; the unchanged diagnostic reports its own map read count, expected65,536bytes. These are successful logical payload reads/writes, not physical I/O or network bytes. Metadata has a50MiB observed limit; the separately charged evaluation-prefix file and saved stores are excluded from that metadata tally and reported separately. The existing full embedding cache, global metadata, whole-leaf snapshots and full joined publication/audit remain.

The frozen queries have SHA`59d9a8401439ee7ff255268bcd961280bbbed8d95446c4cbc89a385cdce80b57`. They are the existing test-labelled cohort and are not a fresh untouched holdout. Query-row publisher offsets and `v2.1:test` IDs are not identifiers in the dense corpus namespace, so these artifacts cannot prove corpus/query disjointness. Any available explicit canonical-global query ID within0–8,191 rejects setup. The controller makes no stronger non-overlap claim. Exact query order, finite dimensions, source/config/query/restore hashes and the actual saved manifest are bound before interpretation.

Four local wiring tests pass. They exercise the unchanged exact engine on an eight-row fake source, independent IP/tie ground truth, explicit overlap rejection, fixed budgets, complete fake five-child pipeline success, setup/construction/diagnosis failures, shape failure and invalid diagnostic rejection. The fake transport never executes a native child, accesses AWS/network or reads real corpus data. Two failed fixture attempts remain preserved: a resolved-versus-unresolved macOS temporary path comparison affects the fake test only. The accepted native/source correctness proof remains in the parent milestone and is not repeated.

The package is ready for an external fresh window only after the parent supplies an exact Linux binary descriptor, extracted source path, output path and fixed deadline, verifies dependencies and the accepted guard/resource approval, and admits transfer normally. This package performs no lifecycle action. The example command is `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python3 run-quality.py --spec filled-runtime-spec.json`. The external window must include separately accounted offline build time in addition to the180-second scientific bound; it cannot extend a closed window.
