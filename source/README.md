# Test one existing compressed centroid scorer

This diagnostic asks whether the existing four-bit centroid scorer retains the leaf-coverage gain observed with full-precision scoring while keeping substantially less additional centroid payload. It uses one prespecified candidate, the existing Code4 RaBitQ implementation. It introduces no quantizer format, dependency change or bit-width sweep. The saved index remains unchanged; its existing one-bit node codes remain resident. The extra diagnostic cache contains four-bit codes instead of FP32 centroid vectors.

The reader loads the same validated persisted FP centroids through the accepted bounded preparation path, then quantizes each centroid relative to a zero origin. The existing code stores correction, norm and radial terms in a twelve-byte header and pads dimensions to multiples of256 before packing four-bit values. At768 dimensions this is396 bytes per node, compared with3072 bytes of FP payload. Reference104-node and owner95-node caches therefore retain41184 and37620 code bytes, compared with319488 and291840 FP bytes. This is a7.76-fold reduction in that additional payload, not in the whole reader or saved index.

Scoring calls the existing Code4 distance_query routine with the actual FP query, zero origin norm/dot terms and the existing query norm. It preserves that routine’s metric correction and arithmetic. Length, finite header values, positive correction, nonnegative norm and zero radial term are checked before scoring. The cache remains private and bound to the exact opened reader identity. It reuses root visibility, finite dimension validation and caps of256 nodes,768 dimensions and1MiB source FP payload. Default one-bit scoring and the FP control remain available unchanged.

Preparation temporarily owns all validated FP centroids and the growing code cache together. The report separately charges source FP loading, retained code bytes, the zero-origin vector and one duplicate returned code buffer. Its accounted payload high-water is not an allocation or RSS bound: the existing quantizer also allocates residual, absolute-value, integer-grid, critical-point and packing scratch. Each distance call unpacks an integer grid and an FP grid; at768 dimensions their logical payload high-water is6144 bytes, excluding allocator overhead. Existing provider buffers/cache, original FP storage and one-bit node codes remain present. Dropping owned FP vectors does not remove stored FP objects or their read cost.

The same per-level beam32 policy and shared traversal, sorting and ties apply to all three scorers. Posting scoring, candidate trimming to200 and exact reranking to100 remain unchanged. The retained tiny trees expand all49/42 internal nodes and evaluate all103/94 nonroot centroids under the preceding controls, so this fixture tests leaf ranking after full internal expansion. It does not demonstrate deeper pruning. Actual leaves, evaluations and posting rows must still be reported rather than assuming matched work.

Two focused local tests pass. They compare raw score bits with the existing Code4 kernel for dimensions1,31,32,255,256,257 and768 across Euclidean, inner-product and cosine metrics; they cover zero/signed-zero values, padding, malformed lengths/headers, query shape, reader identity and saved old-reader results. Eight native readers compare default, one-bit, FP and four-bit policies on two saved64-row fixtures with full candidate coverage. All returned IDs/bits and unchanged control work match; saved files remain exact. Three wiring methods cover native results and the existing GT join, prescribed policy/budgets and six-cell success/failure. The first padding test’s1KiB block-target save failure occurs before scorer assertions and remains retained; a16KiB test-only block target admits wide vectors without production storage changes.

The proposed runtime reuses the exact saved8192-row trees, frozen16 queries, prefix GT, original manifests and maps. Six ten-second cells compare one-bit, FP and four-bit on both trees, with sixty seconds shared, one warm-up pass and one retained pass. This is a plan, not cloud admission. Preparation and cache metadata are charged once per reader, separately from trace-perturbed query elapsed time. All paths retain the shared quantized-query setup; Code4 additionally performs per-evaluation unpacking, so no speed advantage is assumed. The reused cohort and unknown corpus/query disjointness remain; there is no ANN generalization, physical I/O, network, actor-fanout or scale claim.
