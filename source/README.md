# Reference-tree leaf selection at two million rows

This package builds a new bounded diagnostic reader and then measures leaf selection and candidate trimming on the existing two-million-row reference tree. It does not rebuild the index or change search decisions. The retained binary rejects floating-point navigation above 16,384 rows and centroid preparation above 256 nodes. The new explicit reader path accepts at most 4,096 nodes and 16 MiB of copied centroid payload, retains existing defaults for existing callers and observes only intersections with the supplied 100 exact-neighbor IDs. It does not copy all candidate IDs or scores.

The saved reference has 1,780 nodes and 1,752 leaves. Its 28 internal nodes do not by themselves establish pruning or its absence because frontiers mix internal and leaf candidates. Actual depth, offered and retained frontier counts and expanded internal work come from the reader. The question is leaf-selection and candidate economics, not distributed capacity or a promised internal-pruning result.

The read-only bridge validates the original construction manifest, all five immutable block roots, effective construction defaults and dense identity-map bytes. It opens the existing store without rewriting its manifest. The controller calculates new float64 exact top-100 references over all two million canonical vectors for the same 16 previously consumed text queries. It runs 16 warmup and 16 retained requests at fixed floating-point navigation beam 32, tau 2, 100 returns and rerank factor 4 (400 candidates). This is exploratory diagnosis, not a fresh held-out quality test.

One fresh machine window is limited to 1,500 seconds and $0.25 compute on the existing sandbox driver. The pinned offline optimized build has a 600-second cap, informed by recent 126.8–190.4-second builds. Scientific work has a 240-second bound, while the controller preserves at least 180 seconds before the independent external stop. Input verification, bridge scanning and exact-reference computation run in deadline-bounded subprocesses; timeout cleanup always kills and joins owned children. No retries, reconstruction fallback, tuning or larger prefix follows a failure.

All 32 replies bind the supplied ground-truth IDs, query identity and snapshot hash. Reported reached, retained and returned subsets must agree with actual returned IDs and missing-neighbor arithmetic. Original map and manifest pins are rechecked afterward. The centroid report explicitly retains whether its bounded access observer is complete. An incomplete map supports no total traffic or decode claim. Copied centroid payload is distinct from provider cache, topology, allocator overhead and total resident memory; the process has a separate 32 GiB address-space cap.

Only bounded vector-free results, ground-truth IDs and distances, bridge manifests, reader replies and small process/build receipts may be retrieved. Query or request vectors, corpus vectors, blockfiles, source corpus and binaries remain remote. The source archive is the accepted immutable 944-file construction closure; exact reader, driver and Cargo bytes are checked against it. No cloud action is performed by package preparation.

`RUN-COMMANDS.json` gives the pinned Linux build and run commands. Fill only `deadline_unix` and `output` in `runtime-spec.template.json`. The controller binds the resulting binary to its compiler and source-manifest receipt automatically. Local admission, manifest bridge and controller integration tests pass, including mock stage timeouts, malformed warmup replies, cap failures and child cleanup. Local native driver compilation passes; the optimized Linux build and actual execution remain pending admission.
