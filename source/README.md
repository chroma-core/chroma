# Account for serial balance before changing its scheduler

One opt-in observation divides coordinator balance elapsed time into disjoint categories. It changes no routing, clustering input, random-number input, mutation order, validation or saved representation. The diagnostic runs one authoritative construction on the same retained 8,192-row prefix, with explicit one-worker split preparation, construction phases, current embedding view and both accepted lazy trace policies. A single stochastic arm identifies where elapsed time accumulates; it does not measure a causal speedup.

The observer maintains a stack of active stages. Entering a nested stage charges time to its parent up to that entry, then pauses the parent until the nested stage exits. A recursive split inside registration or merge therefore contributes its input and clustering time to those categories, rather than counting that time twice. Seven numeric buckets and a maximum 128-entry stack are retained; overflow, out-of-order exit or outstanding scopes invalidates the report. There is no event-per-vector timing history.

The categories describe elapsed context, including owner calls and their waits. Split input preparation includes the complete source-owner command, while the existing preparation timer separately measures its internal capture, worker setup, fetch, copy and revalidation. Clustering covers the shared split function for leaf and internal splits. Neighbor discovery covers source-neighbor navigation. Eligibility covers scrub, trace preparation, current-version checks, source vector lookup, predicate evaluation and deduplication. Rerouting and registration cover global destination navigation, owner-versioned registration and location updates. Structural installation and merge cover the surrounding leaf/internal/parent/root edits and merge work. Residual other time includes sweeps, loop control and checks outside those spans. A category excludes all of its nested categories. These are not pure distance-computation or CPU-time measurements.

The exclusive buckets sum exactly to the observed window. The existing command timer starts just after the observation starts and stops just before it ends. The report retains that signed boundary difference: exclusive sum equals command balance wall plus the boundary difference. Shape and report collection follow the observed window. Input loading, genesis, reservation, add, current-view publication, reshard, save and final audit retain separate timings. Instrumentation overhead is included; this package does not subtract an estimated cost.

The report retains stage entry counts, construction event-count differences, root-reachable node count, depth, internal child counts, per-leaf live occupancy and branches per owner. Shape collection uses coordinator metadata after timing ends; it performs no embedding reads. Existing owner counters and final saved census separately retain physical, current and stale counts. Existing reader and LocalStorage observers retain root opens, reader-map clears, provider hit/miss, successful encoded returns and storage-origin decodes. Their scope and cache initial conditions remain explicit. Encoded returns are not physical I/O, and cache reconstruction/root opening are not silently classified as block decode. Concurrent fetch spans and cumulative vector timers are not additive CPU fractions.

The local proof uses the existing 225-row fixed-decision construction sequence. Observation is off for the legacy/one-worker controls and on for the two-worker control. Normalized reference boundary events, every phase's tree shape, internal/root/merge behavior, cross-owner reassignment, immediate version visibility, complete saved postings/codes/versions/vector bits and old-reader results remain equal. This is reference-tape equivalence, not independent stochastic tree equality. Two deterministic clock tests prove nested recursive accounting and invalid ordering. The actual native 64-row entry performs real split, scan and NPA work, verifies the full saved census and exact timing reconciliation. Two report tests use that native output and reject changed clocks, missing work and invalid profiles. The initial syntax failure and empty-phase assertion failure remain retained.

The optional `balance_cost_observation` field defaults to false and is omitted from the consumed-spec echo when false. It requires the authoritative diagnostic arm. Without an observation, no clock or stack is allocated; the integration performs only an absent-option check at the timing seams. Default construction rules remain unchanged. The prior split-preparation worker-job counter is exact for the intended one/two-worker comparison but can overcount actual contiguous jobs above two; this experiment fixes it to one.

The existing one-arm harness checks the restored input receipt, reads and hashes only the retained prefix, binds the consumed native spec and checks saved census, stage work, shape and clock reconciliation. It limits the native child to 30 seconds and records at most 50 MiB of metadata; retained stores are reported separately. Build time is separate and uses the existing pinned offline two-job recipe. The runtime template deliberately leaves the future Linux binary descriptor and external absolute deadline unset. No launch, transfer, budget extension or cloud authorization is supplied. The concrete command after those external bindings are filled is `python3 run-balance-cost.py --spec runtime-spec.json`.
