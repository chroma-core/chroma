# Count actual saved-query work before trimming

The ordinary saved-reader query can report the work it performs without changing its navigation, scoring, trimming, exact distances or tie ordering. Start the existing reader with `read --checkpoint-dir STORE --profile-query-work`. The flag defaults off. Existing response fields, including the clamped `actual_candidate_count`, retain their meanings. The opt-in response adds `query_work_policy="ordinary-query-work-v1"` and a `query_work` object.

The object reports the following successful-operation counts. `selected_leaves` is the navigation output length; it is a leaf-selection proxy, not a count of centroid distances or internal expansions. `nonempty_leaves_scored` counts the nonempty loaded leaf payloads actually processed. `posting_rows_scored_before_dedup` counts actual one-bit distance emissions for loaded current posting copies before duplicate global IDs are reduced; it is not physical disk rows or raw-version lookups. `distinct_candidates_before_trim` counts the minimum-distance map before the candidate budget applies. `candidates_after_trim` counts retained candidates after the unchanged trim. `exact_embedding_gets` counts the exact candidate fetch futures in a successful lazy query. `exact_vectors_reranked` counts actual exact-distance results before final k truncation. `returned_results` and `returned_distance_bits` record the final result count and FP32 bits in response order. Partial failed-operation counts are not reported.

Existing stage timers accompany these counts: navigation, per-leaf query quantization, approximate distance scoring, deduplication/selection sorting and exact reranking. Exact reranking includes vector loading, copying, distance calculation and final sorting. The stages omit posting preparation and response mapping; their sum is not total operation latency or CPU. Ordinary-query FP32 approximation, distance sorting and cutoff tie behavior remain unchanged. Recall is compared against the frozen FP64 exact-prefix top 100 with global-ID tie ordering; differences in numerical precision and equal-distance ordering remain interpretation limits rather than silently changing the algorithm.

The runtime plan also enables the existing `--profile-rerank-pins` observer. Its successful encoded returns and storage-origin decode counts cover vector-block access only, excluding posting/scalar paths and root opening. Provider hits and already warm vectors can produce zero encoded returns. They are not physical I/O, network bytes or process memory bounds. The request-owned sequential query loop joins its futures before each observer reset. Overflow invalidates the measurement.
