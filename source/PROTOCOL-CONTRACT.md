# Explicit navigation policy

The existing read command accepts `--query-navigation one-bit` or `--query-navigation fp`. Omission preserves one-bit scoring and omits the new policy metadata. An explicit policy requires `--profile-query-work`; FP also requires a saved snapshot of at most 8,192 vectors. Both policies keep the same per-level beam semantics and downstream query code. There is no final leaf truncation.

An explicit response echoes `query_navigation_policy`, `query_navigation_snapshot` (generation, source ID, dimension, metric and root reference), and `query_reader_open_seconds`. The FP response also contains `fp_navigation_cache`; the one-bit response uses null. Cache metadata includes the root node, visible node count, payload and cap values, centroid-bit digest, preload elapsed time and vector-access counters. It repeats across responses but represents one reader preload. The harness checks the snapshot echo against the original admitted manifest and checks the loaded node count against the existing saved diagnostic. Missing, corrupt, out-of-bound or wrong-reader centroids fail closed.

The runtime template pins all original input descriptors and selects only beam32/k100/rerank2 and the two explicit policies. The operator supplies a separately verified Linux binary descriptor and an absolute deadline; missing values do not grant execution. After compiling the frozen source with the existing pinned offline two-job tool, the command is `python3 run-queries.py --spec FILLED_SPEC.json`. Four cells have ten seconds each and forty seconds total. The template is not a cloud admission or a controller.

Each cell runs the same sixteen warm-up and sixteen retained requests. Existing bounded stage traces collect actual selected leaves, pretrim IDs, retained candidates and returns; GT joins occur outside the timed native query. Navigation work counts actual internal expansions and centroid distance evaluations. Selected-leaf count is the exact oracle-join input, not the configured beam. Provider bytes exclude physical I/O; overlapping timers and trace overhead do not establish CPU fractions or causal latency gains.
