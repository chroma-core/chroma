# One 16K comparison under the scale authorization

This package compares an ordinary parallel tree with the same global tree kernel using one or four local authoritative owners. The exact human authorization is retained in SCALE-AUTHORIZATION.json. It permits this larger input while preserving the sandbox, protected resources, cumulative $1,000 budget, guarded window, upload review and shutdown controls. The worker performs no cloud actions.

The input contains the first 16,384 rows of the admitted restored 2M canonical file, in their original order, with 768 coordinates and inner-product distance. Preparation copies 50,331,648 bytes once, hashes the consumed prefix, rejects exact FP32 query-vector duplicates and declared canonical-global ID overlaps, and recomputes the top 100 neighbors using the existing FP64 blocked engine. It never filters a 2M ground-truth list. All 100 retained queries are copied in their original order and bound to their hash. They are reused research queries; their publisher and query IDs do not prove corpus exclusion. Disjointness remains unknown after duplicate checks. No corpus is downloaded to the Mac.

All three arms use four add threads, four balance threads, explicit FP write navigation and FP neighbor eligibility, branching factor 4, split threshold 256, merge threshold 64 and common balance cuts every 4,096 rows. The native input reader reads chunks of 8,192 rows into the same bounded full-prefix buffer. These reads do not introduce balance or placement boundaries. The effective configuration also records one current copy and empty per-level write overrides, as enforced by the existing explicit-FP decoder.

The one-owner arm skips migration and must report zero moves. The four-owner arm starts with one owner, places branches only after joined balance, and must finish with four populated owners and positive moves at threshold 4,096. This threshold controls placement rather than topology. The reference kernel and accepted owner policies remain intact: grouped scrub validation and immutable predicate batching are enabled for the owner arms, while direct-current reads remain disabled.

The source changes raise only the bounded experimental row and stage-ID caps to 16,384. The owner state and node structures remain process-local. Full vector caching, joined save, map generation and saved census remain charged. The Code4 centroid cache retains its 256-node and 1 MiB FP-payload caps. Observer and stage bounds remain enforced; an over-cap tree stops rather than increasing a cap. Split initialization uses existing uncontrolled randomness, and thread schedules remain nondeterministic. These limitations are recorded explicitly. Independently built trees do not support seeded or fixed-work causal timing comparisons.

Each arm publishes its original create-new manifest and streamed identity map. Map write and verification each account for 131,072 bytes per arm. Controller and diagnostic map reads are additional. The native operation performs the full saved current-membership census, verifies all saved vector bits, and reports all-ID exact-distance bits. All three exact-distance outputs must agree. This does not imply identical trees or ANN quality. The original manifests and maps are hashed before and after later stages and are never rewritten downstream.

The unchanged ground-truth diagnostic runs seven batches of at most 16 queries per arm. Each batch preserves the existing 1,600-ID union bound and charges its full saved census and map work. All 100 queries must cover exactly 100 expected true neighbors and report the exact no-replication leaf and weighted-row oracles. The controller merges only the per-leaf ground-truth ID sets for later query-stage joins. These sets do not change search decisions or the saved index.

One fresh Code4 reader per arm receives one warm-up pass and one retained pass. Each uses the same per-level minimum and maximum beam of 32 with the accepted tau of 2.0; there is no final leaf truncation. The posting scorer, candidate trim of 200 and FP32 exact rerank of 100 remain unchanged. Every query arm uses 256 soft block-capacity units, 4,096 root entries, one cache shard and no provider clear after each operation. This changes both cache partitions relative to the historical 64-shard observations and applies equally to the new arms. It is not a production-default recommendation or a measured cache fix.

Structural admission uses actual retained-query traces. A complete trace must reconcile the internal and leaf partitions, retained-to-next-expansion counts, centroid evaluations and expanded internals against the exact saved-generation census. In every arm, at least 80 of the 100 retained queries must discard an internal candidate and expand fewer internals than the saved total. Failure yields structurally-insufficient, preserves the result and stops the fixed attempt. No resizing, threshold changes, seed searches or retries occur. Equal beam settings do not establish matched recall; unequal-recall points cannot rank latency or byte efficiency as matched-recall performance.

The scientific budget is at most 780 seconds: 60 for setup; at most 180 per construction, save and census arm, with 540 shared; 90 for all ground-truth diagnoses; and 90 for the three query readers. Build has a separate 600-second cap using the pinned Linux Rust 1.92 compiler, offline dependencies, two jobs and release optimization level 3. The proposed external window is 1,800 seconds with a $0.30 ceiling on the retained driver. The sole operator supplies the actual resources, absolute deadline, guard and binary descriptor. The package neither infers nor extends them. Each operation uses the minimum of its phase time, scientific time and external deadline remaining.

The disk free floor is 20 GiB. Retained store payload is limited to 512 MiB per arm, metadata to 128 MiB including the final result estimate, and cumulative observed child peak RSS to 8 GiB. These are post-operation observations and stop conditions, not allocation bounds. Child timeouts do not replace the external shutdown guard. Linux child RSS is reported in KiB; the local Mac wrapper normalizes Darwin byte units before applying the same observed limit. The earlier unit-mismatch test failure is retained.

The package records whole-child CPU, context switches and cumulative peak RSS. Disjoint native input, setup, phase, save, audit, publication and residual timers reconcile before serialization. Row-copy, add, balance and reshard timers are nested within phase elapsed time. Reservation remains inside add and is not a separately measured exclusive phase. Whole-process time also includes output serialization and exit. Overlapping actor waits are not CPU fractions. Warm query times include tracing and extra node-kind lookups. Encoded storage returns remain distinct from physical I/O, network traffic or actor fanout. Code4 preload, conversion, retained codes and scratch accounting remain separate.

Local evidence includes one 16K capacity-admission test, five Python wiring methods, and a generated 64-row, 32-dimensional native check of all three arms. The Python checks cover dispatch success, structural failure, stage failure, a small exact-ground-truth oracle and process resource recording. The native checks cover saved census, exact-bit agreement and six real traced Code4 responses. These ARM checks do not execute retained 16K data, establish pruning at beam 32, measure Linux performance or prove distributed execution. Unchanged constituent suites are not repeated. The post-build artifact-copy path error is retained separately; both Cargo stages pass, and the newly linked hashed artifact is retained without rebuilding.
