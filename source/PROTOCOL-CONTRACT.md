# Filter split input on its authoritative owners

This package compares the accepted live-prefix four-owner construction policy with the same policy plus grouped split-input version filtering. Both arms use the retained 16,384-row prefix, four construction threads, explicit FP navigation and NPA, identical configuration and cuts at 4,096, 8,192, 12,288 and 16,384 rows. Both start with one owner and move existing branches only after joined balance at threshold 4,096. Both enable grouped scrub, immutable predicate batching and live-prefix checks, with direct shared-memory current reads disabled. There is no query retuning, corpus increase, third arm or automatic retry.

A split removes its source leaf while holding the existing structural lock. Its new opt-in filter asks authoritative owner actors for at most 64 current versions under sorted existing ID locks. It consumes the original physical order and exact version-byte comparison, including missing-to-zero and deleted-byte behavior. It does not add a new deletion rule or cache current versions. Every guard drops before clustering or installing replacement nodes. Actors only read their own state and never acquire ID, node or structural locks, call peers or wait for coordinator work. Transfers hold the same ID lock from source removal through destination installation and directory update. The filter therefore cannot observe their temporary gap. Broader read windows can change parallel scheduling; independent tree equality is not claimed.

The native spec field batched_split_input_validation defaults to false. Both new controller specs include it explicitly. The policy requires owner treatment and actor-based current reads; invalid combinations reject before input access or output creation. The response adds this defaulted field, so old frozen response-byte validators are not reused with the new binary. The ordinary reference path and mutation rules remain unchanged. Source counters retain logical current-row counts even though the grouped path does not enter the scalar function for each row.

Only split-input checks are tagged. The response reports physical_rows, retained_rows, scalar_current_calls, batches, owner_calls, owner_requested_rows and a bounded 65-bin batch-length histogram indexed by literal row count. Retained rows are version matches before checking embedding availability. The baseline performs scalar current reads; the enabled arm performs grouped owner calls. Other current calls are not attributed to this site. Logical payload estimates count four requested ID bytes and two presence/version reply bytes per owner-requested row; slots, envelopes and serialization are excluded. These are not measured network or physical I/O bytes. Existing live-prefix suffix and predicate work remains charged separately.

The fixed local tape preserves ordered flags and owner code bytes across 135 rows, including duplicates, stale/deleted bytes, missing values and a later ID mutation between groups. Actor current callbacks fall from 133 to 4 on that exact work. A bounded concurrent test holds a real structural guard while waiting across an actual owner transfer gap, then proves opposite-order multi-ID progress. A generated 256-row construction exercises splits, merges and placement, full saved current-membership census, vector bits and an old pinned reader. A generated 64-row native pair checks policy echo, original checkpoint/map integrity and all-ID exact-distance agreement. These are mechanism and wiring proofs, not 16K or distributed performance results.

The controller rehashes the first 50,331,648 bytes of the admitted canonical input without making a new prefix copy. Each native arm independently verifies its consumed prefix. The full source descriptor relies on the accepted immutable restore receipt. Both arms must reach multiple subtree regions, positive movement and four populated owners, finish balance, pass full saved census and vector-bit checks, and agree on all-ID exact distance bits. Original create-new manifests and maps remain unchanged. Actual split, merge, reassignment, stale-row, message, phase, CPU, concurrency and critical-lock work is retained to qualify independent stochastic timing differences.

Prefix hashing has a 10-second cap. Each arm has 30 seconds, both share 60 seconds, and scientific work shares 70 seconds. The offline optimized Linux build is separately capped at 600 seconds with two jobs and pinned Rust 1.92. A proposed fresh 1,200-second/$0.20 window is a parent decision, not a launch instruction or deadline extension. The disk floor is 20 GiB; observed stores are capped at 512 MiB per arm, metadata at 50 MiB and cumulative observed child peak RSS at 8 GiB. These are observed stop conditions, not allocation bounds. Child timeouts do not replace an external shutdown guard. Whole-child CPU and overlapping actor/coordinator intervals are separate.

The implementation remains a local actor POC with process-local ID locks, global routing and structural sequencing, a full immutable vector cache, and full joined publication. It does not implement physical owner transport or distributed transactions. No causal whole-build timing ratio, ANN quality or scale equivalence is claimed. No cloud action occurs in local preparation.
