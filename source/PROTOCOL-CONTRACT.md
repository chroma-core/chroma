# One live-prefix construction comparison

This package compares the accepted four-owner construction policy with the same policy plus live-prefix version batching. Both arms use the same retained 16,384-vector prefix, input order, configuration, four construction threads and balance cuts at 4,096, 8,192, 12,288 and 16,384 rows. Both start with one owner and place branches after joined balance at threshold 4,096. Both keep grouped scrub validation and immutable predicate batching enabled, with direct-current shared-memory reads disabled. There is no query tuning, ground-truth recomputation, corpus growth or third arm.

The native diagnostic accepts the explicit boolean spec field live_prefix_validation. It defaults to false. Both new controller specs include the field explicitly, and the native spec echo and owner report must agree. Enabling it requires owner treatment, immutable predicate batching and actor-based current reads; invalid combinations reject before input access or output creation. The response adds the defaulted field to the serialized spec, so old frozen controller byte-equality checks are not reused with the new binary. Algorithm behavior remains off by default.

The controller rehashes only the first 50,331,648 bytes of the admitted canonical input and requires the exact prefix hash from the reviewed 16K result. It makes no additional prefix copy and never downloads data. Each native arm independently hashes the consumed prefix again. The full canonical descriptor relies on the accepted immutable restore receipt. Source and input provenance are pinned; the new Linux binary must come from the package's source build, not the older binary without this policy.

The two independently scheduled constructions must both reach multiple subtree regions and four populated owners with positive movement, finish balance, and have no central mutable posting or version mirror. Each performs the existing full saved current-membership census, saved vector-bit verification and all-ID exact-distance comparison. The two exact-distance outputs must agree. Each publishes an original create-new manifest and identity map; their hashes remain unchanged after construction. These checks establish completed membership and stored values, not identical trees or ANN quality.

The controller retains all native phase, message, predicate, version, concurrency and structural-lock data. It separately summarizes requested and consumed live-prefix rows, discarded suffix rows, owner request calls, action yields and both bounded length histograms. Actions are eligible yield attempts rather than guaranteed successful reassignment. Repeated predicate and version work in a discarded suffix is charged. Logical payload estimates use four requested ID bytes and two reply presence/version bytes per owner-requested row; positions, envelopes and serialization are excluded. These estimates are not network traffic or physical I/O.

The fixed local tape already proves the dispatch mechanism: actor calls fall from 131 to 5 while a mutation to a later ID is observed after suffix resampling. That causal dispatch result does not make the new build timing causal. Broader per-ID locking changes allowed parallel interleavings; independent trees can have different splits, merges, reassignments and stale rows. The runtime pair reports phase cost and work together and does not attribute the entire prior balance gap to messaging. The local actor POC still uses a process-local lock directory, full immutable vector cache and joined publication. It is not a physical distributed implementation.

Setup has a 10-second hash deadline. Each arm has at most 30 seconds, the pair shares 60 seconds, and all scientific work shares 70 seconds. Every native timeout is also bounded by the externally supplied absolute deadline. The offline optimized build is separately capped at 600 seconds, with two jobs and the pinned Linux Rust 1.92 compiler. A proposed fresh 1,200-second, $0.20 driver window leaves room for build, scientific work, admission and preservation; the sole coordinator chooses the actual guarded window. No existing or closed deadline is extended. Parent budget, sandbox, upload-review, protected-resource and shutdown restrictions remain.

The disk free floor is 20 GiB. Retained store payload is limited to 512 MiB per arm, metadata to 50 MiB including the final result estimate, and cumulative observed child peak RSS to 8 GiB. These are observed stop conditions, not allocation bounds. Whole-child CPU, context switches and cumulative RSS remain separate from overlapping coordinator and actor intervals. Child timeouts do not replace the external shutdown guard. Failure preserves the first arm and all logs; there is no retry, automatic resizing or alternate seed search.

Local readiness checks comprise three wiring methods and a generated 64-row two-arm native check. They verify explicit policy echo, real prefix hashing, suffix and histogram arithmetic, successful dispatch and second-arm failure retention. The native check verifies saved censuses, exact vector-distance agreement, traced query consumers and pre-mutation policy rejection. One test import dependency omission is retained as a setup failure with zero native calls. It is repaired by copying the accepted validator as test support. The accepted four-test algorithm suite is not repeated. No cloud action occurs during preparation.
