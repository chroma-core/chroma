## The pieces

- A logical subtree owns a disjoint set of stable global document IDs and one immutable lower-tree snapshot.
- A placement assigns each logical subtree to one worker that proves it can reopen the exact snapshot and ID map.
- A topology describes the upper routing centroids and their lower subtrees. A split, merge, or reassignment replaces this topology and every affected lower tree together.
- A deployment record binds the tree, placement, parent deployment hash, and increasing fencing token. One locked compare-and-swap publishes the record; stale writers cannot replace a newer record.

Remote workers require verified file-transfer and reader-probe adapters; a local success must not imply an unimplemented distributed consensus service. ## Ownership and routing contract

The explicit ID map is authoritative ownership. A centroid guides approximate traversal; changing a neighboring centroid does not automatically move any document. A stable ownership revision hashes the source identity, logical subtree identity and map hash. The complete tree binds the routing model; each dynamic lower snapshot binds its centroid content independently of its positional index. Converting a static model-file boundary to this contract rebuilds every lower tree once; unchanged snapshot reuse applies after that conversion.

The deployment hash covers the complete tree, placement, parent and fencing token. A placement-only move changes this hash even when the tree hash stays identical. Dynamic publishers never call the static tree publisher. Two actual Linux publishers prepared from the same parent produce exactly one CAS winner.

Generation-specific serving adapters keep separate persistent readers and HTTP endpoints alive until explicitly closed. They do not replace the configuration behind an older reader's endpoint. The local integration adapter demonstrates this lifetime contract; production endpoint supervision and authentication remain separate work.

## Required insertion semantics gap

Current append selects one upper subtree by nearest upper centroid before searching its lower tree. This forces a single ownership choice before lower-leaf distances are available. The benchmark preparation makes the same choice through nearest-centroid partitioning. Neither path implements the unsharded writer's global write-beam traversal across the complete hierarchy, so a lower leaf in another subtree cannot win an ordinary insertion. This is a required architectural gap, not a completed distributed insertion feature.

The required insertion path carries one write frontier across compaction workers. Each round scores the children of selected internal nodes, merges their distances globally, and applies the write policy once to the combined frontier. The final selected leaf determines the single owner; lower-tree placement and any ownership transfer must be recorded in the same complete saved-index transaction. No stored-vector replication is allowed. Retries must bind the same input identity, source values, parent deployment and ownership revision, and stale work must fail publication. A correctness fixture must place a vector whose nearest upper centroid differs from the owner of its winning lower leaf, then compare the distributed write frontier and final owner with a direct execution of the same hierarchy and policy.
