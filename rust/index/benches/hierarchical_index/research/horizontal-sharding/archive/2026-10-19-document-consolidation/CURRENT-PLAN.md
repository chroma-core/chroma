## Construction-cost hypotheses from code inspection

Lyon requests that diagnosis use code inspection and retained measurements to reduce unnecessary experiments. This section records the side conversation's comparison of the frozen optimized reference writer and benchmark with the dynamic writer and owner adapters. Use it to interpret the admitted eligibility off/on pair and choose subsequent work; it does not add an experiment to the current execution window. The mechanisms below are visible in code, but their proposed fixes have no established end-to-end speedup.

The strongest evidence points toward repeated work and synchronization, rather than decoding or queue publication alone. In epoch8, the balance phases ending at28,672 and49,152 vectors consume15.847 and20.148 seconds: together35.2% of balancing time. Both occur before any recorded vector decoding, and their node-cache miss-time increments are only approximately0.010 and0.028 seconds. These spikes cannot be explained by the measured decode work. Whole-process CPU time divided by elapsed time is approximately0.916 cores despite32 configured workers; this is not a balance-specific utilization measurement. Queue capacity1→4 removes almost all queue reads and most commits without materially reducing balancing time. Preserve these negative results and avoid another queue-capacity sweep.

1. **Repeated leaf cleanup and authority synchronization are the leading candidate.** After a successful vector reassignment, balancing can revisit the destination leaf and scan its memberships even when no split or merge follows. The ordinary writer checks current versions locally. The dynamic path retains a node guard, copies membership rows, and checks batches through the home authority and owner executor. Identity locks, chosen from64 stripes per home, remain held across synchronous callbacks; unrelated leaves can therefore contend on the same locks. Epoch8 records27,564 scrubs,67 splits, zero merges,34,582,460 location-batch rows and2,809,626 home messages. Owner Current callbacks accumulate42.002 seconds of caller time,19.548 seconds of queue time and4.245 seconds of service time. These overlapping totals are not additive wall-time buckets, and the Current timer excludes preceding identity-lock and home-lookup waits. First expose the existing scrub row/batch/owner-call counters and measure identity-lock wait/hold time by call site. A fixed concurrent fixture with normally occupied leaves should compare colliding and disjoint identity stripes. A candidate fix is single-owner cleanup against the existing authoritative owner-local current-version map, eliminating redundant home round trips. Prove the ownership-transfer visibility invariant before generalizing it. Skipping cleanup requires explicit invalidation tracking that preserves accurate live membership for splits and merges. The admitted eligibility-prefix optimization targets related authority traffic but does not eliminate full cleanup scans; judge its result accordingly. More batching alone can lengthen lock holds, consistent with the adverse epoch7 result, though independent trees prevent a causal conclusion.

2. **Structural locks cover substantially more computation than in the reference.** The dynamic split holds the global tree lock and topology write scope across source filtering, vector collection, clustering, quantization and installation. Navigation needs the corresponding topology read scope. Reassignment registration also takes the global tree lock. The optimized reference performs split preparation outside its short attachment lock and uses a target-leaf lock for initial reassignment registration. Epoch8 records20.671 seconds of structural lock holding,16.750 seconds waiting and7.052 seconds waiting for topology reads; these can overlap other measurements. Attribute lock holding to preparation versus publication and expose existing clustering/split timers before redesigning synchronization. A candidate fix prepares immutable vectors and candidate clusters outside the global lock, then revalidates membership and publishes atomically under a short lock. Simply removing the lock would violate the dynamic implementation's complete-view guarantees.

3. **Vector access performs substantial work outside the decoder timer.** On a decoded-cache miss, the dynamic store resolves immutable content handles, groups compatible roots, opens readers, verifies a SHA256 digest with an update for each four-byte float, copies vector data and collects block-observation statistics. Observation includes map/mutex work and JSON conversion. The reference retains shared immutable embeddings in memory. Epoch8 records974,679 logical gets with3,640 decoded-cache hits,366,610 reader opens and2,983,031,808 copied vector bytes, but only0.362 seconds decoding. The miss path therefore implies approximately971,039 checksum verifications and745,757,952 per-float hash updates; these are work-count deductions, not measured checksum time. Reassignment can fetch a vector again even though its caller already holds the embedding. Use a fixed content-handle request sequence with controlled provider-cache state to separate resolution, reader access, checksum, copying and observation. Candidate fixes include bulk hashing of the identical little-endian byte representation, typed counters without hot-path JSON, passing an existing immutable embedding into reassignment, and bounded reader reuse or a published construction view. Preserve integrity checks and distinguish immutable content identity from current membership versions.

4. **Navigation loses the reference's packed centroid access.** The optimized reference reads child IDs and centroids from a shared packed parent view. Dynamic navigation fetches parent and child records in waves and can fetch selected children again to identify their kind. Cache hits still clone record/centroid data. Epoch8 records857,620 node point reads,797,074 evictions and7.361 seconds of point-miss time with an eight-record/32KiB clean cache. This contributes work but does not alone explain102 seconds of balancing. Replay fixed navigation queries on a fixed tree and verify selected IDs and distance bits while separating distance computation from record access and copying. Candidate fixes carry child kind through scoring, share immutable navigation payloads and use bounded, versioned packed parent pages. Existing detailed reference navigation timers do not cover the owner's early-return navigation path; wire that path before relying on those counters. Avoid introducing an unbounded duplicate tree.

5. **Benchmark cadence and buffering restrict useful parallel work.** The optimized reference benchmark balances after100K-vector early batches and later1M-vector batches, coalescing worker insertion deltas across an entire batch. The dynamic100K fixture balances every4,096 vectors and flushes leaf groups within each64-row worker window. Its dirty-node scheduler processes one page at a time with worker joins between pages. Most phases have only a handful of splits, so peak worker concurrency is not sustained useful utilization. Epoch8 registers100K insertions through36,992 owner calls, averaging2.70 rows per call; approximately79.7% of calls contain at most three rows despite the64-row window. Use the existing group-size histogram plus eligible-job counts and worker busy time before changing thread settings. Candidate fixes retain bounded per-leaf buffers across windows or regroup a bounded wave before flushing. A separate matched-cadence comparison must account for work and quality changes. Increasing the first balance interval to100K also requires a valid conservative split reservation; the current8,192-row admission limit cannot accommodate that root split. Do not slow the reference to fit the experimental implementation.

The next decision should prioritize owner-local cleanup and identity-lock contention, followed by checksum/observation overhead, before a broad structural-lock redesign. Use the already admitted pair to narrow the first question. Corroborate each subsequent candidate with retained counters or one fixed-work fixture, then validate the best coherent change with a bounded100K construction run that records phase times, CPU work, tree shape, memberships and vector integrity. Internal-branch balancing and multi-machine behavior remain outside what this fixture demonstrates. Do not add overlapping caller, queue, lock and service times or multiply isolated gains into a build-time prediction.
