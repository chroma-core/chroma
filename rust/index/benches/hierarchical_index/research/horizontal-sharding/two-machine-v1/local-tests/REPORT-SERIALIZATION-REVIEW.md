# Benchmark report serialization review

The epoch4 100K attempt completes its add and balance phases, then fails while constructing a report containing 128-bit tree node IDs. Its intermediate JSON value cannot represent those integers exactly, so the report macro panics with `number out of range`. This is a reporting failure after useful measured phases, not a failed membership transfer or an admitted complete benchmark.

The retained `window-epoch4/100k-baseline-distributed/run-receipts.json` records add time of 0.174346379 seconds and balance time of 16.478724946 seconds. At balance completion the initial owner holds all 100,000 vectors in 69 leaves and 70 nodes; it records 68 splits, 115,987 transferred vectors and 7,911,763 vector fetches. The second owner has no postings during this first construction interval, as specified by the initially single-owner design. The subsequent panic occurs while the placement plan enters the cycle report. No complete cycle, durable save, fresh-reader validation or final performance admission follows from this attempt.

## Audited report fields

The placement plan contains wide node IDs in promoted shared roots, ownership-unit roots and planned-move roots. Every occurrence must use an exact decimal string in the report. The underlying runtime structures and their wire serialization need not change. Counts, placement capacity, move sizes, authorities, placement counters and tree-shape histograms remain ordinary 64-bit or bounded machine-size numbers.

The benchmark already converts its run identity to a string. The physical correctness report converts explicit root/source/destination node IDs to strings and reports other placement details as counts. The saved-generation descriptor contains strings and a file reference with 64-bit byte/checksum fields. Saved-reader query results contain vector IDs, which are 64-bit identities rather than 128-bit tree-node identities. Those inspected report fields do not expose another unconverted wide node ID.

The RPC accounting helper also sums two 64-bit counters in 128-bit arithmetic. The admitted 600-second fixture cannot approach that numeric range in practice, but the report helper should still avoid a latent panic: preserve an ordinary numeric value when it fits in 64 bits and use an exact documented decimal string on overflow. The raw endpoint counters remain numeric. This keeps phase-accounting values exact without changing transport behavior.

The implementation author is preparing a report-only helper and regressions covering a maximum-width node ID and maximum endpoint-counter sums. Final source review and the sole compiler owner's retained test/build result remain pending. This reviewer performs no source edits, Cargo or AWS execution.

## Coherent helper review and remaining gate

The report-only helper explicitly maps promoted roots and nested unit/move node IDs to decimal strings. It preserves authorities, placement counters, destination owners, vector counts and final owner totals as numbers. The RPC helper preserves 64-bit numeric aggregates and emits exact decimal strings only above that range, with an encoding note. The regression includes `u128::MAX`, wide nested roots, report roundtrip, work-count assertions and a separate direct model serialization roundtrip; the runtime placement model and wire types remain unchanged.

The retained focused reproduction is `report-u128-red-01.log`. The first full suite after the helper is not clean: `report-u128-final-suite.log` records 151 passed and one failed. The failure enters the scoring-centroid-mismatch diagnostic branch in the 32-worker test, then that diagnostic itself panics while putting wide node IDs into another intermediate JSON value. The diagnostic serialization must be repaired to expose the actual mismatch context. It is incorrect to classify this as a harmless test-only logging failure or admit the runtime from a passing report helper alone. The implementation author and parent are notified; no further remote run is admitted by this review yet.

## Exposed scoring visibility failure

The repaired typed diagnostic exposes a real mismatch in `centroid-context-capture-00.log` and its JSON artifact. At the third repetition of the 32-worker fixture, the published shared parent 18446744073709552108 has revision 1 and retains an older scoring centroid for owner 2 root 18446744073709551912 at placement 1. The actual root has revision 5 and points to that same shared parent. The topology therefore agrees while the navigation scoring copy disagrees. The full published view has sequence 17. This is a correctness gate independent of the report serialization fix.

Source inspection identifies two concrete ways a parent change can suppress the required refresh. The local structural update releases its protected region before testing its captured parent against the latest shared map. A shared split can replace that parent during the gap, causing the test to skip refresh even though the changed owned root still has a shared parent. Separately, the refresh helper reads a shared view and then fetches the owned root; if a concurrent publication changes the root’s parent between those reads, the helper can treat the new parent’s absence from the older view as a completed no-op. A shared parent-change proposal also copies its scoring rows from the saved shared view while separately fetching current owned-root revisions. These observations define controlled interleavings to test; they do not establish the exact execution order of the retained stress failure.

The engine author prepares deterministic regressions and a combined correction for these paths. This reviewer awaits that coherent snapshot and the sole compiler owner’s retained results. All cloud execution remains paused during correctness diagnosis.

## Combined source review

The combined correction closes the inspected interleavings. A shared parent-change proposal now takes each changed root’s scoring row from the same owned image whose revision and parent are validated by the owner reservation. It recomputes affected shared ancestor centroids before publication. A local structural edit refreshes an ownership unit by its current unit identity rather than its captured parent. The refresh helper resolves the parent through the pinned published linkage, so the interval between shared publication and owner completion cannot masquerade as a completed no-op. Its publication turn and revision revalidation still order the final decision.

The deterministic stale-row regression reproduces the old failure in `shared-reparent-stale-row-red-02.log`; it changes an owned centroid while its post-edit refresh is pending, then invokes actual shared balancing. The completion-gap regression reproduces the old early return in `shared-reparent-finish-gap-red-01.log`; it pauses the actual remote completion handler after shared publication and verifies that refresh waits. These tests distinguish the mechanisms from the retained stress failure without claiming its precise execution history.

The combined full-suite receipt `report-and-shared-centroid-final-suite-01.log` records 153 passed and one failed. Both new regressions and the distributed 32-worker invariant pass. The failing test constructs only the local unsharded writer, starts concurrent parent and leaf splits, and reports `split source 36 has no reachable parent`. Its writer and module bytes exactly match the reviewed epoch4 source archive: SHA256 `96ee830fc932a0c9a9582ff8ffb9f3518595eab77d1b5f1a3fbe183f0740bead` and `2b6b5595c50ac40b5853e86e92ed12adf2dc5a4bab872e221af845187e05ec10`. It does not instantiate the distributed cluster or use the new shared handlers. This establishes that the failing code is unchanged by the narrow correction; it does not establish the bug’s introduction date or exact cause.

The local unsharded candidate differs from the retained matched-reference checkout, whose writer SHA256 is `725b9a88bff395b5bb07b2ed801889b30443c9796886a64b6acd7cf3f277abea`. The reference checkout uses its tree lock, while the local candidate uses region reservations and its own scheduler. The failure must therefore remain labeled as a local unsharded candidate regression rather than a demonstrated failure of the retained reference benchmark binary. No source repair or reference rerun is performed by this reviewer.
