# Pruning remote navigation candidates

Per-owner top-K replies can preserve a bounded global beam under a fixed total ordering, but they do not yet preserve this implementation's exact tie behavior. Keep the full canonical candidate sequence for the current comparison. A stable total-order variant is a separate algorithm decision that must also apply to the matched reference; it must not enter as a wire-format optimization.

## When the proof applies

For one query and level, let K be the maximum number of children the coordinator can select. With tau enabled, K is the resolved level's `beam_max`; without tau, it is `beam_min`, already clamped by the policy. The construction configuration uses K=16 with tau=1.5 and a floor of 10. Percentage floors use the global level width and remain capped. Owners need the resolved K, not a floor computed from their own subtree width.

Under one shared total order, any globally selected child has owner-local rank at most K. Otherwise K children from that owner alone precede it, so it cannot enter the global prefix. Therefore the union of each owner's top K contains the exact global prefix and its best distance. The coordinator can then apply its unchanged tau threshold and floor to that prefix. It must retain the existing `max(best_distance, 1e-10)` threshold rule. Owners must not run independent tau/floor selection.

This proof requires owners to filter the excluded source leaf before local selection and to score all eligible children from all requested parents for that query and level. Leaf and internal candidates compete for the same slots. Selected leaves accumulate across levels; they are not a separate local top-K stream, and the final accumulated leaf list is not capped to K by this optimization. A batch of queries requires an independent selection for each query. Splitting one owner request into chunks remains safe with K per chunk, but the payload bound becomes K times the number of chunks rather than K per owner.

There is no useful pruning when the resolved K covers every candidate. `usize::MAX` or another practically unbounded width must fall back to complete replies. Zero is a literal zero-width beam, not an unlimited sentinel. Even with K=0, skipping scoring/validation would change the current failure behavior and work accounting; that is a separate decision.

## Why naive truncation is not exact today

Equal f32 distances have no fixed secondary ordering. The coordinator reconstructs the full frontier-parent/child-ordinal sequence, then sorts eight-byte index/distance tuples with the reference's distance-only unstable comparator. Removing rows changes the sort input and can change equal-score order. Running the same unstable comparator independently on each owner does not establish the global rank used by the proof. Sending every tie at a local cutoff also does not prove the same final order, because the shorter global input can reorder retained tied groups. Tied internal centroids can lead to different descendants, so equal distance does not make this harmless.

A future explicit total order could use distance followed by global frontier position and child ordinal. A local owner can preserve that relative order, and the coordinator can reconstruct it from request order. This changes the reference's current tie semantics and requires a matched-reference decision, exact differential tests and measurement. With distinct candidate scores and valid eligibility, the top-K proof already applies; that is not a safe assumption for all f32 workloads.

The ordinary reference resolves missing children before counting live selections. Its packed centroid buffer uses a NaN marker for an unavailable row, then performs a live lookup and skips an absent node. Raw top K before that eligibility resolution can lose the valid K+1 child when an earlier row disappears. The distributed path instead requires finite published centroid rows, reports stale parent images as an attempt rejection, and uses the published child type. A pruning change must preserve those existing semantics rather than importing a new skip/fallback rule. Nonfinite discarded scores must still fail; excluded children must not consume the local quota.

## The reply contract must change explicitly

Complete replies currently declare each parent's full child count and carry every ordinal from zero through that count minus one. The receiver checks completeness, uniqueness, parent membership, finite scores, one observed revision per parent, request/run/epoch/owner identity and missing parent replies. A truncated reply fails that contract. It cannot reuse `Complete` while silently weakening the checks.

A future pruned reply needs explicit K/filter identity, an acknowledgement and revision for every requested parent, full versus retained counts, retained ordinal range/uniqueness checks and an explicit owner-side guarantee that every omitted row was scored and validated. The coordinator cannot independently verify the omitted top-K claim from the reduced payload alone. Full logical candidate counts must retain overflow checks and work accounting; transmitting fewer rows must not turn an oversized or malformed expansion into apparent success. This remains a protocol design task, not a serialization edit.

## Smallest useful next test and predicted bound

Use a saved fixed tree with a root selecting two internal parents on different owners, three children per parent, K=2 and fixed eight-dimensional queries. Compare the ordered IDs and exact f32 distance bits from full replies and a proposed pruning path, level by level and at final leaf output. This gives six scored rows and at most four transmitted rows at the pruned level. Add a selected internal child below one parent to check later traversal and leaf accumulation. Use the existing fixed-tree differential harness, and separately compare the same fixture with the actual matched-reference writer rather than substituting a performance claim from the sibling writer.

Necessary adverse cases are an excluded nearest leaf, tau disabled/enabled, a floor above the tau-selected count, a percentage floor capped by K, K=0, an unbounded width, reversed replies, stale/missing parents, nonfinite scores and ties at and below the cutoff. A fixed 65-child parent on each owner crosses the small-sort boundary for the tie fixture; exact ordering must match the full-input oracle, not merely the score multiset. These are proposed tests; none runs during this read-only assessment.

For remote owner o with C_o eligible children, the predicted scored-row payload is at most `sum_o min(K, C_o)` per query/level, plus metadata for every requested parent. All C_o distances still need calculation. At K=16, a nominal 100-child parent gives a 100-to-16 row reduction; sixteen such parents on one owner give 1,600-to-16. Deferred balancing can leave wider parents temporarily, so 100 is an example, not a hard tree bound. These arithmetic row reductions are not measured wire-byte, CPU or latency gains. They do not justify applying that factor to epoch21's reported 293.2M remote scored rows or roughly 49GB of traffic without its per-owner/per-level distribution and metadata accounting.
