# Reservation history diagnostic plan

The question is whether retained completed attempts add work to an otherwise identical uncontended reservation. The structural condition is a fixed one-leaf topology with no active grants and no queued competitors. One owner-local manager has no completed history; the other has 64 attempts admitted and released through the actual public manager methods. No vectors, structural edits, RPC, phase changes or benchmark sweeps are involved.

The hypothesis is that conflict discovery scans the retained record map before filtering for active grants. The predicted work for the next identical request is one visited record with no history and 65 visited records after 64 releases. Both cases should perform zero granted-region overlap comparisons. The bounded history makes a clear work-count contrast while keeping preparation and measurement within milliseconds; it is not a scale model of the measured construction workload.

Only test-build counters will count pump calls, candidate requests, visited records and granted-region overlap comparisons. A single request timing in nanoseconds is secondary evidence and has no pass/fail threshold. The test verifies identical topology, no active grants, preserved Released replay outcomes and request success. It then asserts that completed history does not increase conflict-discovery visits. That final assertion is intentionally red on the current implementation and remains the regression for a possible later fix.

The exact command is `CARGO_TARGET_DIR=/private/tmp/chroma-single-shard-target cargo test -p chroma-index --test hierarchical_distributed released_history_does_not_increase_uncontended_conflict_discovery_work --offline -- --exact --nocapture`, with the fully qualified test name substituted if the short filter plus `--exact` matches no tests. The final receipt will record the actual qualified invocation and its output. Compilation has a 60-second diagnostic budget; the test has a ten-second budget and no network or cloud dependency. Stop after this one fixed contrast. Do not optimize in this diagnostic task.

The lifetime check will trace the actual benchmark cycle and owner phase handlers. It must distinguish end-of-save sealing, manager reclamation, and placement-driven manager replacement. The diagnostic establishes bookkeeping work amplification only; it cannot establish its share of end-to-end construction time.
