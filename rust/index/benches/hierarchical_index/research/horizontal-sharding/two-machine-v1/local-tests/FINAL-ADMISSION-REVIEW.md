## Final changes reviewed

Posting transfer divides large requests into chunks with at most 512 KiB of raw one-bit codes. Each chunk captures current source and destination routing revisions, derives destination codes from that centroid, and binds the ordered IDs, revisions and codes in the payload digest. It completes both acknowledgement and release barriers before starting the next chunk. Duplicate IDs are rejected before the first chunk. A later failure does not undo earlier completed chunks; the caller either revalidates current source membership for a known changed dependency or stops on an unresolved outcome. This preserves one current membership while bounding each JSON request. The bound is appropriate for the admitted vector dimensions and remains subject to the transport's hard frame limit.

Balancing preserves eligible work when a newly created leaf is temporarily reserved. A split job schedules the still-eligible source before returning; the queue permits one pending follow-up while that node's current job is active. Reassignment schedules both source and destination after a completed transfer, so an oversized source cannot lose its outstanding split merely because another job moves vectors out of it. Per-node active exclusion remains in the scheduler; independent nodes can run concurrently. The final focused test checks that drained balances leave no oversized owned leaves or internal nodes after both insertion intervals.

Shared balancing rebuilds a proposal when an owner root lookup is stale or retired before it acquires owner protection. It retains a bounded replan budget and does not convert unrelated errors into success. Owner parent changes use fixed request bodies, a publication turn before owner-region acquisition, and actual Published proof before completion. Structural publication propagates centroid changes through every shared ancestor in the same immutable view. Replay returns a retained root and matching publication sequence; changed preparation bodies and sealed-epoch requests are rejected.

Transport explicitly restores blocking mode on accepted sockets before applying read and write deadlines. This resolves the immediate native TCP EOF failure caused by inherited nonblocking mode. A focused regression delays the first request bytes after connection acceptance. Independent control capacity remains bounded and available while data workers wait for remote acknowledgements.

The benchmark records actual settings, cumulative framed application traffic in both directions, completed handoff payload bytes, placement capacity and actual moves. Final depth and branching histograms use routing metadata outside the construction timer. These receipts prevent configuration differences, payload bytes and application framing from being conflated. They do not measure Ethernet/TCP overhead or make local actors into physical machines.
