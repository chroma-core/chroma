# Validate remote child rows once and retain replies without cloning

The navigation coordinator checks complete remote parent replies in one coverage pass and retains borrowed reply handles for duplicate comparison. It then moves each accepted reply’s original child records into the unchanged candidate assembly. Wire fields, complete child coverage, full placement identity, revision checks, beam settings and the reference’s unstable tie ordering stay the same.

A fixed actual-TCP fixture exposes the repeated work before the change. It uses 64 queries, 16 remote parents with 100 children each, mixed leaf/internal candidates, equal scores and node IDs above 64 bits. Its selected output matches the actual local unsharded writer on the identical fixed tree. For the same 103,424 received child rows, counted coverage visits fall from 1,750,016 to 103,424 and the existing logical reply-clone counter falls from 8,421,376 bytes to zero. The initial native debug interval changes from 0.469091 to 0.488146 seconds; this adverse timing remains recorded. A final verification takes 0.468536 seconds. These TCP/debug intervals do not isolate validation CPU or establish a latency gain.

The coordinator keeps returned vectors immutable until every duplicate check finishes. Its duplicate index borrows ordered parent slices and reply bodies. Accepted replies move only after that index drops, so exact conflicting duplicates still fail without retaining a second copy of every child vector. Coverage uses a parent lookup table and an ordinal occupancy array. The sum of declared counts must equal the actual received row count before ordinal storage allocates; an oversized declaration cannot force an allocation beyond the received payload.

The focused checks pass: 23 routing/codec tests and eight actual-TCP expansion tests. They include reversed and exact duplicate replies, missing and partial replies, conflicting duplicates, overlapping chunks, stale/publishing state, wrong run/epoch/attempt/step/slot/owner/placement/shared sequence, mixed revisions, invalid counts, duplicate/out-of-range ordinals and nonfinite scores. All three affected native CLI builds pass. No unrelated full-suite repeat is claimed.

The coverage counter excludes exact-duplicate equality traversal, metadata checks and candidate ordering. Zero reply-clone bytes does not mean zero allocations or zero candidate movement. The change does not prune children or change scoring. Physical construction latency and CPU remain unmeasured for candidate26.

Exact commands, failed fixture setup attempts, native artifacts, source hashes and unchanged staged-index hash are in `EPOCH26-REPLY-VALIDATION.json`. Only `distributed/routing.rs` and `routing_tests.rs` change relative to frozen25b. Candidate26 remains separate from the admitted25b runtime.
