# Independent control-protocol and generation review

This review checks the local protocol and generation components against the selected distributed design. It is an intermediate component review; it does not admit the integrated owner engine or a physical two-machine benchmark.

## Result

The three reproducible protocol progress blockers identified in this review are corrected and pass independent regression checks. Outgoing reservations now have an abort outcome, departed incoming records no longer block a returning subtree, and an explicit root-replacement operation preserves exclusion across an ownership-boundary split. No further component blocker appears in the corrected snapshot. No generation-publication correctness blocker appears within the adapter's documented immutable POSIX namespace assumptions. Integrated engine admission remains required.

## Corrected findings

| Priority | Component | Finding and required correction |
|---|---|---|
| P1 | Handoff capacity accounting | Reserving an outgoing subtree and then aborting its unpublished handoff leaves the reservation active. The ledger has no outgoing-abort transition. A fresh attempt for the same root returns `Conflict`, and its capacity remains reserved for outgoing decisions. Add a retained aborted outcome that releases only the pending outgoing reservation while preserving assigned source capacity; reject or resolve abort versus cleanup races explicitly. |
| P1 | Handoff capacity accounting | A subtree that arrives, activates, leaves and completes source cleanup cannot return in a fresh attempt: the first incoming record remains `Assigned`, and `reserve_incoming` rejects the root against that historical record. Track current root assignment independently from retained attempt outcomes. Keep duplicate acknowledgements idempotent without treating historical assignment as current occupancy. |
| P1 | Region protection at an ownership boundary | A granted reservation on owned root P cannot atomically retire P and introduce replacement owned roots P1/P2 whose local parent is absent. The generic ancestry coverage check rejects the new roots because they do not descend from P. The design requires this boundary split. Provide an explicit validated replacement operation that binds old to new roots and retains protection on all replacements through publication and release. Do not infer unrestricted authority to create unrelated roots. |

## Contracts the integrated engine must establish

The transfer record preserves its state when an edit callback returns an error, but correctness requires the callback to leave membership unchanged on that error. The record cannot roll back arbitrary partial edits. The engine must retain both leaf protections through acknowledged completion and release, and it must derive driver acknowledgement proofs from the same attempt's actual replies. A timeout or unknown response cannot become a successful acknowledgement or an abort after completion begins.

The generic publication component swaps the visible immutable view and records its Published outcome under the same mutex. Its Publish/Abort/Status race test supports that local arbitration contract. Its record reclamation APIs rely on an enclosing phase fence; every incoming handler must check the run and epoch before accessing reclaimed records. Phase closure must continue admitting the remaining steps of accepted attempts until drain and sealing finish.

The generation adapter checks immutable bytes, object integrity, owner-manifest identities, declared format, expected root coverage, total counts and compatible full-vector references. Its conditional latest replacement is serialized across cooperating processes by a non-stolen filesystem lock and an atomic rename. A repeated descriptor resolves a lost successful publication response. These guarantees rely on all participants using the adapter and preserving immutable payloads; crash recovery is outside this fixture.

Routing, node and posting payloads are opaque bytes to this adapter. The adapter's subprocess test reopens and parses its own fixture payloads; it does not prove that the real tree can execute queries, that actual posting membership is unique, that shared-routing contents match directory coverage, or that stored centroids use the real reader format. The engine admission tests must establish those facts using actual saved tree data and a fresh reader after writer processes are unavailable.

## Integrated endpoint and saved-reader corrections

The owner endpoints now resolve successful append and transfer duplicates before consulting revisions or membership changed by the accepted operation. Appends perform fallible checks before admission and mutation. Transfer preparation reserves the complete local leaf bundle and validates captured source and destination revisions. Transfer membership edits check revision exhaustion before changing postings. Navigation uses immutable routing images and does not wait for posting locks while holding the routing gate. Five targeted endpoint regression tests accompany these changes; the parent runs the consolidated target.

The unused general StageNodes, ActivateNodes and RetireNodes RPC commands are removed from the runtime surface. Actual subtree placement and shared-boundary publication use their dedicated protocol endpoints; direct initial installation remains a fixture setup operation.

The saved reader now opens routing and posting-reference metadata without loading posting payloads. Each owner routing object contains a versioned leaf-to-object index. Metadata opening verifies compatible manifests, ownership, topology and matching posting references. The first posting read verifies its checksum, exact indexed leaf identity and code length. Explicit membership and code-validation passes load every posting separately. Strict generation saving and publication retain complete payload checks before exposing a descriptor. New regressions cover a posting file unavailable during metadata open, a wrong leaf inside an otherwise valid indexed payload, and cache budget rejection before allocation.

## Remaining integrated protocol findings

Concurrent mutating Placement requests need one serialized execution path per attempt. In particular, two Activate handlers can prepare the same incoming snapshot before either records activation; a delayed duplicate can then overwrite current resident state or regress a completed record after construction resumes. Export also exposes its record before destination staging and readiness finish. The protocol author is correcting these races with retained per-attempt execution protection, while leaving Status requests independent to avoid cross-owner wait cycles.

Shared-boundary completion must verify the coordinator's actual Published outcome for the same attempt before removing the old node or releasing its region. A caller-provided boolean is insufficient proof. Boundary Ready and Finish also need serialization per attempt so duplicate requests return recorded outcomes rather than repeating preparation. These findings are sent to the construction author and remain remote-admission blockers until their corrections and focused tests pass.

The physical correctness harness has meaningful mechanism gates in the inspected source: a replacement global root and depth of at least two, real destination capacity rejection, a whole-branch move, increased remote posting and expansion counts after post-handoff adds, an isolated cross-owner merge with a uniquely preserved probe vector, and final durable-only exact membership and code validation. Its source labels physical instance/process identity as an external receipt requirement. No false-pass gate is identified in that harness review; this does not replace executing it on two verified machines.

A further coordinator duplicate-response finding remains with the author: StructuralEdit replay must compare the submitted body with the recorded attempt, and its response must pair a root with that root's publication sequence rather than returning a newer root alongside an older sequence.

Shared-view installation now checks monotonicity and equal-sequence conflicts while holding the same pointer write guard used for installation. Navigation pins one published view and derives its root binding and shared sequence from that view. Separately written root and sequence mirrors no longer determine navigation. Two additional endpoint regressions cover deliberately inconsistent mirrors and concurrent older/newer installations.

The 32-worker performance executable reserves 64 data handlers and 128 independent control handlers. Its fixture accepts at most 32 workers and records handler limits, the 16 MiB frame limit and the 30-second socket operation cap. The maximum simultaneous receive-frame allocation is 3 GiB; decoded data, engine state, responses and handler stacks require additional memory and are excluded from that figure. ## Shared balancing and construction review

The shared balancing implementation serializes each mutating request by attempt, validates a fixed request body, acquires its publication turn before owner regions, and gathers owner bundles in increasing owner order. Owner parent updates retain node protection until Finish verifies the coordinator's actual publication and the installed view's attempt and linkage. Status handlers bypass attempt execution locks. Shared split, unary-root collapse and empty nonroot pruning each produce one publication and schedule further eligible work. The shared-centroid refresh path publishes ancestor scoring rows after owned mutation protection is released. These properties are verified by source inspection of the coherent shared-runtime snapshot identified by the author as SHA prefix `6d930781`; its tests are the sole compiler owner's responsibility.

The structural publication wrapper now retains the submitted body and complete result together under an attempt-specific execution lock. A conflicting body is rejected before a cached result is returned. A successful replay therefore returns the retained root and its sequence, rather than combining the latest root with an older sequence. A replay regression after another successful publication is still required in the coverage audit below.

The construction author corrects the identified multilevel centroid finding: owned-root replacement now updates every shared ancestor scoring row, revises and recenters each ancestor, and includes the final root in the same publication. The corrected loop is verified in source. A focused multilevel boundary-split regression should inspect the ancestor rows; a membership-only test cannot detect this difference.
