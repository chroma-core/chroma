# Final balance cost after construction reaches both owners

Navigation and remote candidate handling are the leading measured costs; the transfer protocol also performs substantial coordination for very small moves. The evidence does not support attributing the entire CPU gap to transfer metadata objects. No source changes, builds or benchmarks are part of this assessment.

## What the measurements establish

The final 2M→3M balance takes 26.204 seconds and 934.76 summed process CPU seconds, compared with the retained reference’s 6.846 seconds and 191.66 CPU seconds. Clustering takes 35.222 versus 42.037 CPU seconds, with 715 versus 740 committed splits. Different trees and scheduling prevent a fixed-work speedup claim. The candidate’s 899.54 non-clustering CPU seconds justify investigating its surrounding work.

The candidate performs 718,465 navigation query rows versus the reference’s 714,437 navigation calls. Similar query counts and fewer committed splits do not explain away the surrounding CPU. They make the remote representation, validation and transport costs more promising than another clustering-kernel change. Whole-attempt retries and different candidate work still matter: the candidate records 10,593 attempts for 10,364 navigation calls, 9,759 reassignment rounds and 5,225 rejected groups.

## Ranked source-backed explanations

1. **Remote traversal materializes and validates hundreds of millions of rich child records.** Every child carries its parent, ordinal, target ID/authority/placement, leaf flag, distance and observed parent revision. The codec stores 69 raw bytes per child before base64. Reply validation clones a complete reply into its duplicate-check map, then repeatedly filters its child vector for each parent and constructs ordinal sets. Global selection also reconstructs canonical order and sorts the complete candidate set. The reference instead traverses in-process child arrays and sorts compact `(u32, f32)` candidates. Required checks include complete parent coverage, identities, revisions, duplicate conflicts and global tie order; duplicating the full body and repeatedly scanning it are implementation choices. A parent-grouped decoded representation can retain every row and validate counts/ordinals/revisions in one pass. An immutable shared reply handle or index can preserve exact duplicate comparison without copying the full child vector. Removing per-child parent/revision/implicit ordinal repetition from a future wire format is a separate lossless option; truncation or owner-local top-K is not justified by this finding.

2. **Cross-owner transfer coordinates each tiny destination group independently.** `reassign_inner` groups rows by destination, sends all same-owner groups through one local bulk operation, then calls the staged protocol separately for each remote destination. A successful remote group requires two Prepare calls and nine step calls: Stage, two BeginCompletion, RemoveSource, ActivateDestination, two Complete and two Release. Thus 21,899 successes alone predict 240,889 logical endpoint calls, close to the measured 241,602 including rejected attempts. Each remote call opens a new TCP connection and the server creates a handler thread. Those mechanics plausibly add CPU beyond the endpoint scopes, but existing scopes cannot attribute all unclassified process CPU to them. The reference claims the source and available destinations together, validates all proposed rows, prepares target buffers and compacts the source once. The candidate’s local path already follows that pattern. A cross-owner extension could batch one source’s accepted destination groups by owner under one attempt, one ordered owner-region bundle, one staged payload and one source compaction, retaining per-target centroid/placement/membership validation and explicit retries for rejected targets. This is a protocol design change, not permission to remove acknowledgement barriers or treat source and destination edits as one local transaction.

3. **Terminal transfer handling scans retained replay history.** `transfer_step` checks whether both local roles are terminal by filtering the entire `operations.transfers` map for the current attempt. Released entries remain until `OpenEpoch` clears the map; saving seals the construction epoch. Two releases per successful group can therefore repeatedly inspect completed history. Because the map is keyed by `(AttemptId, role)`, checking its two exact role keys or a bounded key range preserves replay records without a history scan. This is a concrete avoidable algorithmic cost, but it sits inside the measured 32.12 step CPU seconds, so it cannot by itself account for the much larger navigation or total CPU gap.

## Smallest next fixed-work diagnostic

Measure the staged transfer path with navigation removed before deciding how much protocol redesign to undertake. Use a frozen source leaf with 2,048 current postings, eight destination leaves on the peer, 768-dimensional immutable vectors and exactly three eligible IDs per destination. Feed the same precomputed, ordered routes and destination centroids to the current staged driver and to the existing local bulk implementation on an otherwise identical cloned fixture. Restore fixtures outside the measured sections; no splits, scheduler races, navigation, cache loading or changing clustering decisions belong in the timed section. One execution establishes exact work counts; a fixed bounded repetition count may be chosen once if native CPU clocks need more resolution. Set a 30-second absolute stop and preserve any failure.

The current cross-owner path predicts 8×11 = 88 logical endpoint calls, 48 remote calls (six destination endpoint calls per group) and eight source compactions for 24 moved IDs, assuming no rejection or retry. The local reference-style path predicts one source compaction and zero staged protocol calls. Compare exact final IDs/codes and unchanged nonparticipants, per-endpoint CPU, client/server transport CPU, framed bytes and call counts. The test distinguishes the cost of the control mechanism from navigation; it is not an end-to-end or physical-network speedup measurement. Add reciprocal direction, duplicate/lost acknowledgement, changed centroid/placement and failure-after-stage cases only when implementing the batched protocol, using existing adverse-test seams.

For the first-ranked navigation change, the smallest independent oracle is a fixed two-level tree with 16 selected parents, 100 children per parent and 64 fixed queries, including equal scores, wide IDs, mixed leaf/internal children and complete parent replies. Compare the existing validator/selector with the proposed grouped representation on identical saved replies. Require bit-identical scores, identical globally selected order, all malformed/partial/conflicting duplicate replies rejected, zero whole-reply copies and one visit per row for parent validation. Existing fitting 64-query×16-parent TCP and tied-order fixtures supply the geometry. This is a proposal, not a new benchmark execution.
