# Response-local expansion metadata reuse

The candidate sends repeated ordered child metadata once per RPC response and retains every query's complete score bits. The decoded replies and navigation algorithm remain unchanged. A fixed 64-query payload over actual localhost TCP uses 62,266 framed bytes compared with 413,199 bytes for the complete-row codec, including reply envelopes. CPU time is unavailable on this native platform; these byte counts establish no latency or universal traffic gain.

The dictionary key borrows a run of scored rows and compares parent ID, observed revision, ordinal, full target identity/owner/placement and leaf flag in order. It excludes score bits. Hash collisions still require full equality, and metadata changes under the same revision create separate entries. No metadata key or byte buffer is copied per query before deduplication. Newly interned metadata is emitted once; every score and run order is emitted for each query.

The receiver validates dictionary references, exact lengths, legal flags, finite bits and complete raw/expanded budgets before allocating decoded rich rows. The equivalent 69-byte-row budget is independent of encoded size, so a small dictionary cannot expand into an unbounded repeated-row allocation. The response variant is explicitly versioned; mixed old/new response decoders reject instead of silently falling back. The existing typed size rejection, complete-query/parent subdivision and original absolute deadline remain intact.

The final focused routing/codec module passes 27 tests; the bounded-expansion module passes 8 tests. They cover actual mixed-owner navigation against the current reference, exact order/bits, changed metadata, forced collisions, malformed references, decompression amplification, version mismatch, typed subdivision and deadline preservation. Native builds pass for all three CLI programs. Detailed commands, artifacts, source/index hashes, byte counts and limitations are retained in [the validation receipt](EXPANSION-METADATA-REUSE-VALIDATION.json) and the linked native logs. No compile or test attempt fails in this candidate. Expected malformed-input and deadline rejection logs are retained.

The owner still constructs all rich scored rows and the receiver reconstructs them. Dictionary building, equality checks and temporary buffers therefore add work that must be measured in a matched physical run. There is no pruning, precision change, cross-request cache or transport rewrite. The complete source closure also retains the separate fixed 24-ID transfer diagnostic in its test file. Independent review and parent admission control the next physical run.
