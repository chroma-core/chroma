# Completed reservation history no longer drives conflict discovery

The reservation manager now discovers conflicts through an ordered set of currently granted attempts. It retains completed request and outcome records for duplicate handling. Grant inserts the attempt into the active set; release removes it before advancing the queue. Both transitions occur under the existing manager mutex. No replay records are deleted and construction phase lifetimes remain unchanged.

The real-manager diagnostic isolates unnecessary history traversal. A fixed one-leaf topology receives one uncontended request with no active grants or waiting competitors. Before the repair, the probe visits one conflict record with no history and 65 after 64 completed attempts. Both cases perform zero granted-region overlap checks. After the repair, both probes visit zero conflict records, and old attempts still replay as Released. The red log and diagnostic-only receipt remain preserved.

Current construction permits completed history to accumulate within a manager lifetime. The benchmark retains an owner service across add, balance and redistribution cycles and closes and seals only when saving at the end. Release retains records; phase handlers do not reclaim manager history. Specific drained placement events can replace a manager, so history must be interpreted within those actual lifetimes. The repair changes conflict indexing rather than deleting outcomes at balance boundaries.

The active index preserves the manager's existing lifecycle rules. Focused tests check that the index equals exactly the records marked Granted after cancellation, FIFO advancement, duplicate replay, body conflict, release, dependency Replan and root replacement. Existing placement, bundle and grant/cancel race tests pass. All 26 selected protocol tests and 164 applicable distributed tests pass. The full 165-test wrapper is not claimed clean because one previously documented, unchanged local unsharded candidate-writer test remains explicitly excluded. All three native command-line executables compile from the frozen snapshot.

The work-count result does not establish an end-to-end speedup. Single request timings include cold/warm noise and are preserved without a timing assertion or ratio claim. Conflict traversal now follows active grants, while replay lookup remains logarithmic in retained history and retained memory still grows with attempts. The active set adds memory proportional to current grants. Actual balance CPU, mutex waits, posting compaction, navigation and clustering remain separate questions.

The JSON receipt records commands, source and binary hashes, exact measurements, lifecycle evidence and limits. Independent review and only the fixed 100K before/after verification against the exact retained baseline are the next gates; this repair does not authorize a larger run.
