# Matched 100K construction attribution

Measure the entire balance phase of the ordinary reference and corrected distributed implementation on the same retained 100K vectors, order, L2 metric, 768 dimensions, 32 workers, split/merge/branch thresholds and one 100K insertion interval. The distributed tree starts on one owner and redistributes only after balancing. This fixture reproduces the initial-owner slowdown and performs enough splits, reassignment and navigation to distinguish substantial local costs. It does not test deep-tree navigation, cache-capacity crossing or physical distributed construction during the first interval.

The leading explanations are different clustering work, repeated source membership scans and compaction, temporary navigation data, and synchronization waiting. No algorithm, concurrency, initialization or scheduling setting changes as part of this experiment. Source epochs and existing adverse measurements remain retained.

Instrumentation records clustering calls, input rows, iterations and distance work; attempted/prepared/committed/discarded splits; transfer groups, source membership/compaction work and copied bytes; navigation construction/validation/scoring work; reservation active/history/queue state, conflict/ancestry work, mutex wait/hold and queued wait. Both implementations receive corresponding measurements where their operations exist. Unsupported measurements and inclusive scopes must be explicit. Workers accumulate locally and merge at operation boundaries. Avoid per-vector logging and shared counter updates in inner loops.

A benchmark gate stops each process before the timed balance. The observer binds its exact executable, process ID/start time, job marker and reviewed specification, starts userspace CPU recording, and confirms the profiler's enable acknowledgment before releasing the gate. After balancing, the process publishes completion and waits outside the timer while the observer stops recording. This provides complete-phase coverage while retaining bounded setup/teardown samples. Gate waits are at most 60 seconds, profiling at most 120 seconds, raw data at most 256 MiB retained remotely, and each workload remains under its fixed 600-second supervisor limit. Failed attachment, missing acknowledgment, partial coverage, correctness failure or deadline ends that arm and preserves evidence; there is no automatic retry or input-size sweep.

Use existing sandbox machines and retained corpus files. Build both instrumented source closures with the same compiler, release optimization, native CPU flags, frame pointers and debug information as retained measurements. Review the coherent change once and run meaningful local work-count and correctness tests before admission. Open a fresh absolute-guarded cloud window only after preparation is ready; the root remains sole operator. Stop both hosts promptly after collecting evidence and account for the closed window once.

Run one explicitly selected reference arm and one explicitly selected distributed arm. Report wall time, process CPU, per-operation CPU and waiting separately; nested operation durations overlap, and summed worker durations are not a wall-time decomposition. Use full-phase samples and work counts together to identify which differences plausibly explain extra CPU and the critical-path limits on elapsed time. Record instrumentation overhead risk and independent seed/tree differences. Do not assign an exact causal latency contribution where the measurement cannot support it. Reprioritize the plan from this pair; larger tests remain deferred.
