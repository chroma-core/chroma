# Transfer region progress review

The epoch5 3M distributed arm fails during balancing after its second 100K addition. The retained event reports 200,000 current vectors, 125 leaves and 128 nodes on the initial owner, with 32 workers active at peak. The second owner has no current postings because redistribution has not started. The failed balance lasts 8.743922727 seconds and reports `transfer region is not granted` as the final rejection before the reassignment progress budget expires. The process exits with code 1, and its supervisor confirms cleanup. This arm does not provide an admitted 3M result; the completed 100K arms and 3M reference result remain separate evidence.

The exact rejection occurs when the region manager returns a status other than Granted after a transfer requests its complete local source/destination protection bundle. It does not come from an endpoint check that demands each leaf remain an exact normalized root. Normalization removes roots covered by requested ancestors while retaining the ancestor’s protection. The endpoint then validates its actual resident leaf, placement, centroid dependency and membership under the granted protection. The reviewed path therefore does not substantiate an exact-root-versus-covered-descendant diagnosis.

A global topology counter can reject a transfer whose own leaves remain unchanged. The endpoint captures the manager’s current sequence while retaining its request, then submits that request afterward. Every structural publication increments the manager’s sequence. Request normalization compares the saved sequence with the current sequence, and queue pumping repeats that comparison for every waiting request. An unrelated edit can therefore return Replan before submission or while the transfer waits for an overlapping region. This is a concrete progress hazard in the source, but the retained campaign records do not capture the rejection status or topology sequence needed to establish it as the precise cause of this failure.

The implementation author prepares a controlled regression before changing the runtime. The useful interleaving captures a transfer request for two unchanged leaves, publishes a structural edit in a disjoint region, then submits or grants the captured request. The test must distinguish unchanged transfer dependencies from a retired, reparented or differently placed affected leaf. Increasing the reassignment retry budget would conceal this distinction and is outside the proposed repair. This reviewer performs no source edits, Cargo execution or cloud operations.

## Controlled reproduction and reviewed repair

The actual endpoint regression reproduces the rejection in `transfer-region-disjoint-red-02.log` in 0.01 seconds. It holds the left subtree region, waits until a transfer between two leaves in that subtree is queued, performs a real split in the separate right subtree, then releases the left region. The old queue logic returns Replan despite unchanged transfer leaves. The corrected run in `transfer-region-disjoint-green-01.log` reaches Prepared, aborts that staged endpoint cleanly, completes a subsequent real transfer and verifies exact membership. This establishes the mechanism independently of the larger campaign; the campaign’s missing internal trace still limits precise attribution.

The repair changes queue revalidation rather than retry limits. Initial request admission still checks the global sequence. Once admitted, the request records every requested root’s live ancestor path, including roots removed by normalization because another requested ancestor covers them. Queue pumping recomputes current normalized protection and compares ancestor identities, parents and placement counters under the same bookkeeping mutex before deciding conflicts or granting the complete bundle. An unrelated structural revision no longer invalidates intact paths. A relevant reparent, retirement or placement change still returns Replan. The endpoint continues validating node type, centroid dependency and current membership after the grant. Broad structural revisions remain available for structural snapshot validation; they are intentionally excluded from this ancestry dependency because a sibling edit can change an ancestor revision without changing the requested region.

The added adverse matrix checks requested-root and ancestor reparenting, retirement, placement changes, and a normalized-away requested descendant. The positive case preserves queue exclusion until the existing holder releases it. The existing bundle ordering and whole-bundle grant stay unchanged. The initial capture-to-admission sequence race can still request a normal replan; this correction specifically removes unrelated invalidation of already admitted queued work.

The structural fixture crosses an actual owned internal split with two additions of 2,048 vectors, split threshold 128, branching factor 32 and 32 configured workers. The retained `transfer-region-multilevel-green-01.log` reports 23 leaves and one internal node after the first balance, then 47 leaves and three internal nodes after the second. It observes 25 active jobs at peak, 240 completed jobs and 137,087 vector fetches. This verifies the targeted queue behavior while the tree adds another internal level; it is not a throughput prediction for 3M vectors.

The compiler owner’s `transfer-region-final-scoped-suite-01.log` records 156 passed in 3.22 seconds. It explicitly filters the one already retained local unsharded candidate test; it does not claim the entire unfiltered suite passes. The source comparison in `transfer-region-source-delta.json` identifies only the region manager and construction tests as changed from epoch5. Their reviewed SHA256 values are `05b5d530ccccbff2c3c7afde2ad21286195fd9e06d75045d93f130fcfe087855` and `05ec8fd68decb0e8473b2972258e217da8693693d5c6295e1043f0383d967712`. The reviewer finds no source blocker in this repair. A fresh reviewed Linux build, physical correctness check and replacement 3M arm remain separate operator admission gates; the failed arm and completed comparisons remain retained.
