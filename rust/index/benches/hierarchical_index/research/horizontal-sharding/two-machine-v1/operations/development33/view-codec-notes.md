# Bounded compact view installation

A complete shared routing view can exceed the existing transport frame limit at the current benchmark size because its JSON representation repeats full-precision centroid coordinates. The actual Rust request-envelope fixture containing 32 internal branches, 2,131 ownership units and 768-dimensional centroids occupies 22,550,510 bytes in the plain representation. The compact representation occupies 9,396,716 bytes and successfully crosses the unchanged 16,777,216-byte transport limit in a loopback test. The receiver reserializes the request identically. This proves the representation fix for the fixture; it does not by itself identify the failed cloud request.

The change applies only to the view field of the placement request that installs a complete published view. The adapter uses a versioned explicit binary layout carried as a base64 string. It preserves complete 128-bit node identities, 64-bit revision/publication/attempt metadata, child order, centroid-code bytes and all finite float bit patterns, including negative zero and subnormal values. The ordinary view and checkpoint representations remain unchanged. The existing receiver installs the view only after full decoding and its existing validation. This patch does not add new graph connectivity or map-key identity validation.

The decoder limits the base64 field length before decoding and limits decoded bytes to 12 MiB minus 1,024 bytes. Every declared collection length is checked against remaining bytes before allocation. The decoder rejects unsupported versions, invalid flags, truncation, trailing bytes, duplicate map keys and nonfinite coordinates. It verifies child dimensions before allocating the derived navigation buffer, preventing malformed wide-parent/empty-child data from amplifying into a much larger allocation. The outer transport independently enforces the complete frame limit; reserved field headroom does not promise that arbitrarily long authentication tokens or envelopes fit.

All peers must use the new request representation together. Legacy plain JSON view fields are rejected by this adapter. Larger compact views can still exceed the bounded field or frame limits; staging chunks and atomically installing a complete verified view remains a separate larger-scale extension. No frame limit is raised, and no payload is truncated.

The implementation lives in `/private/tmp/spann-research33view`. The source changes are the field adapter declaration in `placement_runtime.rs`, the new `view_codec.rs` and `view_codec_tests.rs`, and the copied diagnostic fixture in `transport_tests.rs`, whose expectation now verifies successful compact transport. The diagnostic sources in `spann-research33` and `spann-research33fix` remain unchanged.

Validation evidence is in `view-codec-large-fixture.log` and `view-codec-placement-tests.log`. The earlier binary-helper test log is `view-codec-tests.log`. Independent review catches and resolves the derived-buffer allocation amplification; the regression fixture encodes less than 1 MiB while a missing dimension precheck could otherwise request approximately 4 GB.
