# Remote request attribution for experiment 34

Detailed diagnostics connect each direct remote request to the job that initiates it. The client requests a timing envelope around the ordinary reply; the server returns monotonic durations with that exact reply. This avoids cross-machine clock subtraction. Ordinary runs retain the existing request and reply format and collect no new per-request attribution.

Set `SPANN_DETAILED_DIAGNOSTICS=1` on both processes. Each retained longest or latest job gains `work.remote_requests`, keyed by the existing fixed request-kind names. Each entry records calls, errors, timed replies, replies with server queue timings, client elapsed and decode nanoseconds, server decoder queue/decode/execution queue/handler nanoseconds, wire bytes sent/received, and maximum client elapsed. The same totals appear in transport snapshot `diagnostics.remote_requests` and each `by_request` entry. Existing `by_origin` totals do not gain these remote timing aggregates; use the retained individual job records for job attribution and transport snapshots for whole-phase totals.

Server decoder queue time starts when the complete frame enters decoding admission and ends when a decoder starts. Server decode time covers JSON parsing and authentication. Execution queue time starts after decoding and ends immediately before handler execution, including the reactor's dispatch delay. Handler time includes any nested work and remote calls. Client decode time is JSON reply decoding. Client elapsed includes connection acquisition, request serialization and transmission, all server stages, response transmission and client decoding. The remaining client time after subtracting measured server stages and client decoding is an unexplained residual, not a network-only measurement: response encoding, framing, socket readiness, client request encoding, connection setup and other overhead remain in it.

Calls from existing scoped expansion workers inherit the initiating job's explicit thread-local context. Server workers do not inherit that job context. Their directly measured handler duration returns with the reply, while their own nested calls remain separately attributable on the server. Consequently, this measures direct remote dependencies of retained jobs and does not reconstruct a complete distributed call tree. Requests running concurrently overlap; sums of request durations do not equal a job's critical path. Server handler duration and nested request durations must not be added as independent time.

The instrumentation uses fixed request-kind names and aggregate numbers, with no request bodies, vector values, authentication tokens or unbounded per-call records. Failed transport requests remain counted but may have no timed reply; consult `timed_replies` and `server_queue_timed_replies` before treating absent stage times as zero. Application-error replies preserve timing metadata and keep the connection reusable. Oversized replies preserve the explicit size rejection in a timed envelope. No request is retried after transmission.

The new wire envelope is requested only by detailed clients and requires a matching implementation at both ends. A server with detailed collection disabled still reports handler time when explicitly asked, but marks queue timings unavailable. Benchmark deployment already verifies matching binary hashes. The metadata adds a small amount of traffic and diagnostic CPU, so use these runs to select a candidate and compare latency with detailed collection disabled.

The added native loopback test checks successful full-width 128-bit replies, application errors and connection reuse with explicit timing envelopes. Existing context tests verify that child-thread remote attribution reaches the initiating job and unrelated server threads do not. Persistent-call tests check exact call counts, complete timing coverage and nonzero queue/decode measurements when detailed collection is enabled. Existing framing, absolute deadlines, no mutation replay, saturation and large-payload tests remain part of validation.

Validation passes in both modes: 316 tests pass, three remain ignored, and the known unrelated concurrent parent/leaf split test is excluded. The native benchmark compiles with `--cfg distributed_owner`. Logs are retained beside these notes. The early detailed-suite failures were exact wire-size assumptions and one server-counter snapshot race; their assertions now include bounded metadata overhead in detailed mode and read completed server counters after shutdown.
