# Balancing diagnostics and attribution

Detailed diagnostics attribute work to the scheduled job that initiates it. The categories are balance, neighbor reassignment, queued reassignment, and unassigned. Every existing operation scope and work counter receives that category, so navigation CPU and rows can be compared with split and transfer work without classifying requests from their eventual destination.

The attribution follows the executing thread and explicitly follows the joined owner-expansion threads created during navigation. It does not cross network request envelopes. Independent request-server threads therefore remain unassigned. The transport's request-kind measurements provide a separate breakdown of server execution, but cannot identify the initiating job. Client navigation CPU excludes remote scoring CPU; client elapsed time includes waiting for those replies. Local expansion can be attributed while otherwise equivalent remote expansion remains unassigned. These categories must not be interpreted as a complete per-job CPU bill across machines.

Each owner retains the 32 longest completed scheduled jobs. Records include job kind, owner, node ID encoded as a string, attempt authority and sequence, Unix start time, elapsed time, executing-thread CPU, and inclusive operation times and counters observed in that job or its joined expansion threads. The attempt fields identify individual executions; a node can appear in several jobs. Nested scopes overlap and must not be summed as wall latency or exclusive CPU. The job's thread CPU excludes child threads, while child operation scopes can contribute to its breakdown. Top records are cumulative: use their timestamp and attempt identity to select the measured phase, rather than subtracting the list between snapshots.

New fine scopes cover neighbor candidate selection, reassignment membership scans and query construction, internal splitting, scheduler dispatch, and scheduler execution. Neighbor distance counts preserve the original short circuit: three distances for every evaluated row and a fourth only when the current centroid is farther than the better proposed centroid. The internal split input counter counts children entering clustering. Reassignment input rows count requested rows once per invocation, while existing rounds and navigation query counts measure retries. Scheduler dispatch includes queue-lock acquisition, scans, and condition waits; its CPU measures overhead, while its elapsed time also includes idle waiting. Scheduler execution includes the request and its reply wait.

Attribution maps, job records, and the new fine scopes are disabled unless SPANN_DETAILED_DIAGNOSTICS=1. Existing light aggregate counters remain available. The profile snapshots expose by_origin and longest_jobs with backward-compatible serde defaults. snapshot_nonzero returns only populated operation totals for short-lived transport aggregation and deliberately omits job attribution, which is already recorded into the shared job context on operation completion.

Unit tests verify nested context restoration, propagation to a joined child, the unassigned category on an independent server-like thread, exact counter reconciliation, string serialization of the maximum u128 node ID, the 32-record bound, and the disabled context path. Integration and benchmark validation are coordinated by the parent agent using the shared build cache.
