# Epoch11 bounded privileged CPU observation

Epoch11 repeats only the fixed 100K profile observation against the exact corrected epoch9 executable and input. Epoch10 remains closed and unchanged. No build, algorithm change, larger fixture, sweep or retry is included. The generic workload supervisor and lifecycle stay unchanged, with 600-second process bounds, 590-second fixed job deadlines and fresh epoch11 identities and outputs.

The only privileged operation is the separate bounded observer. The runner invokes `sudo -n /usr/bin/timeout --signal=TERM --kill-after=2 118 /usr/bin/python3 -I -c` with a fixed bootstrap. That bootstrap verifies the exact collector path and SHA256 of its source bytes before compiling and executing those same verified bytes. It does not execute a later reread of potentially changed source. The collector also checks its hash against the reviewed spec. Python isolated mode ignores user module paths and startup settings. Missing noninteractive sudo or failed hash checks prevent a ready receipt and therefore prevent workload launch. The collector preflight now occurs before the idle peer starts as well.

Root privilege allows the observer to sample the selected workload with existing `perf_event_paranoid=4` and inspect its own marked profiler group for cleanup. It does not alter sysctl, security settings, sudo policy, dependencies or the workload's credentials. The observer requires effective UID zero and still verifies installed perf help/version. Its allowed child commands are bounded perf recording and report generation with fixed arguments. Recording uses `--no-buildid-cache` to avoid updating an unrelated root build-ID cache; unavailable tool options fail closed. Fresh collector directories and small receipts/reports receive readable artifact permissions so the ordinary runner can collect them. Raw perf data stays remote.

Every existing selection guard remains: corrected epoch9 binary hash/path, exact 100K input/settings, reviewed spec hash, owned workload PID/process group/start ticks/boot ID, exact executable and inherited job marker. Recording starts only after observing the first 100K balance event. It is PID-scoped at 99 Hz userspace `cpu-clock:u`, realtime timestamps and frame-pointer stacks. The normal recording stops at nine seconds with one second of forced-termination grace, for a ten-second hard maximum. The file cap is 256 MiB. The collector uses its existing 115-second internal deadline and outer 118-plus-two-second absolute bound, capped by job, actual supervisor and host deadlines. It only signals its own separately created group after checking each live member's collector marker; it never signals the workload or changes its deadline.

The runner retrieves the final small perf report after the collector's completed result arrives. Earlier workload receipt collection can contain partial observer files; `profile-final-files.json` is the final observer receipt set. Raw `perf.data` is excluded. Missing or unreadable final report is a profiling failure and never triggers an automatic repeat.
