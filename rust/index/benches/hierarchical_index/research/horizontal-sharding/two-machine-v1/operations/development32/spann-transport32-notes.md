# Transport diagnostics

The notification-based listener is the source default. The original polling mode remains available through SPANN_ACCEPT_MODE=poll_1ms for controlled comparisons.

Detailed transport snapshots attribute completed connections to fixed request names. Shared centroid refresh, prepare, finish and status calls have separate names, as do owner transfer prepare, step and status calls. Authentication failures and undecodable frames use a separate category; request values and tokens never become keys. Every category reports wire bytes, messages, failures, and observed operation scopes. The category set is bounded by the request enum rather than workload identities. Connection-local counters merge once after completion, so in-flight requests become visible only when they finish; phase snapshots must follow phase joins.

Client elapsed, connection setup, serialization and deserialization CPU belong to the calling client thread. Server serialization, deserialization and handler execution CPU belong to the accepted connection's handler thread. Handler CPU excludes nested worker threads. Handler elapsed includes dependency waits. Thread start wait measures wall time only and therefore has zero supported CPU samples. Thread spawn remains a global listener scope because the request kind is not known before decoding and authentication. Each scope reports its supported CPU sample count; zero CPU with zero supported samples is unavailable rather than measured zero. Detailed_enabled=false means fine scopes and per-request attribution were not collected. Sparse per-request scopes are absent when no observations exist.

The aggregate snapshot retains its existing counters and scopes, including global thread creation costs, while merging completed per-request totals. Sparse temporary snapshots avoid constructing every empty scope for each connection. Detailed collection still adds allocation and aggregation overhead, so timing runs must keep it disabled. Existing job contexts receive client operation measurements separately; request-kind server measurements do not establish the remote initiating job.

Focused native tests pass in ordinary and detailed modes: 12 passed and one opt-in timing experiment ignored in each. Tests cover parallel duplicate requests and wire accounting, fragmented and oversized frames, authentication, separate data/control admission, deadlines including save budgets, oversized replies, bounded request names, and aggregate sums/maxima. Logs are /private/tmp/transport32-light.log and /private/tmp/transport32-detailed.log.

A bounded server worker pool is the narrower next experiment if spawn/start costs warrant it. Separate data/control pools must retain existing capacity, count queued plus executing requests against admission, reject saturation as today, preserve an absolute deadline from acceptance across queue and socket work, and join all admitted handlers during shutdown. A pooled/per-call feature switch permits same-binary comparison. Additional tests must cover control progress under saturated data, queued expiration, fragmented idle peers, shutdown, duplicate identity, framing and authentication. Persistent connections introduce more risks: idle sockets can occupy reserved handler capacity, stream leases must be bounded, stale streams must be discarded without automatically retrying a possibly applied mutation, and each frame needs a fresh independent deadline. No connection pool or server worker pool is implemented in this batch.
