# Scientific review of the isolated pilot

The shared-tree implementation passes the real-data integrity and sparse-append gates. The current million-vector FineWeb study selects its settings on calibration and obtains 97.88% held-out recall with identical results and traversal traces across one-host and two-host placements. These results use 100 test queries and do not establish publication-quality tail latency or saturated capacity. The separate ten-million-vector preparation now passes full ID coverage, bitwise source-value checks, frozen-owner routing membership, and fresh full-corpus exact references; its index measurements are pending.

## Current evidence

The preserved corrected response contains 100 IDs and 100 unique IDs. The initial 20-request synthetic million-vector run fails closed with HTTP 503 because shard responses contain duplicate IDs. That failed attempt remains in the raw history; it is not a current claim that the repaired reader still fails. Corrected query evidence must identify its binary, parameters, and immutable snapshots. Removing duplicate candidates alone is insufficient: the reader must still produce k distinct results and pass exact tiny tests.

The real million-vector independent forest build takes 698.313 seconds overall. Owner 0 takes 698.312 seconds, while owner 1 takes 98.671 seconds. Owner 1's final warning records 30 oversized and 10 undersized leaves after 100 balancing rounds. Both processes return zero, but the incomplete balancing and large timing skew exclude this run from completed-compaction speedup claims. There is no matched one-host build of the same task graph.

The primary mechanics input uses one sampled, frozen root over the first 10,000 real vectors. It assigns 8,593 rows to one ownership slot and 1,407 to the other, retaining the resulting skew. Its model and explicit global-ID maps are hashed and preserved under `subtree/subtree-real10k-v2`. Preparation takes 0.701 seconds including clustering. The earlier preparation attempt's timer excludes model fitting and is retained separately. Local and Linux tests validate map coverage, frozen boundaries, assembly, and compare-and-swap publication; the retained local-versus-HTTP records now show identical frontiers, selected candidates, reached leaves, IDs, and distances. These correctness records do not establish capacity.

The separate FineWeb exporter produces 100,000 real 768-dimensional vectors in 43.074 seconds internally, or 43.30 seconds for the whole process. It fetches 295,997,376 source payload bytes under its 512 MiB and 180-second caps. Peak resident memory is 736,860 KiB. An independent Polars parquet decoder matches every exported value and all 100,000 original UUID strings. Source norms range from 0.999756 to 1.000246. The exporter preserves float16 values exactly in float32 and performs no renormalization. A cache-only fresh retry matches the vector, UUID-sidecar, and SQLite-index hashes. Existing output is rejected unchanged; interrupted-output resume is unsupported. These are preparation results, not index or recall results.

## Reference and identity checks

The MS MARCO million-vector provenance pins the public revision, source files, indexed prefix, and 200 reserved document rows excluded from the corpus. Calibration and test pools contain 100 distinct rows each, with no overlap. They are held-out document embeddings rather than independent user queries. The exact reference files each contain 100 distinct query identities, 100 unique in-range results per query, and ascending distance/global-ID ordering. Their query identities belong to the reserved source interval. The partition source hash matches the prepared corpus hash.

The blocked float64 scorer agrees with the independent scalar oracle on tiny cases for squared Euclidean distance, inner product, and cosine, including equal vectors and global-ID ties. The real reference runs use warm operating-system pages and approximately 4 GB of mapped-corpus resident memory. Their timing is separate from index measurements. Mathematical float64 cosine and the worker's rounded float32 normalization/distance can differ in final bits; bit-identical distance claims are unsupported.

FineWeb has a different value and metric contract. Its source values must remain unchanged after exact float16-to-float32 conversion. One-minus-inner-product is the proposed implementation path, pending agreement with the publisher's numerical conventions. Full-corpus top-1000 answers cannot be filtered into exact prefix references. Query text, regenerated embeddings, runtime pins, and subset references remain separate deliverables.

## Measurement rules

Calibration curves must finish and select frozen settings before held-out tests run. The supplied protocol writes its selection before testing and reports unattainable recall targets explicitly. A repaired reader requires fresh calibration and test runs. The load driver includes failures in all-outcome latency and counts them as zero delivered recall. Its throughput describes closed-loop clients that wait for each response.

A reranking factor multiplies k: factor 10 with k equal to 100 permits 1,000 candidates per shard, or 2,000 across two baseline shards. These are configured budgets rather than measured vectors scored. The reader's search tolerance is fixed at 2.0; the corrected transport rejects overrides. Preserve failed-attempt settings separately from corrected results.

Process CPU values are cumulative seconds, maximum resident memory is KiB, and Linux process input/output block counters are counts rather than byte values. Host physical-device bytes differ from process logical system-call bytes and application block-fetch bytes. Device layers can overlap and must not be summed indiscriminately. Missing application bytes or vectors-scored counters remain unavailable. Cluster peak memory requires simultaneous totals; separate process peaks do not supply that quantity.

Preparation host samples begin after the first download and initial parsing and overlap a compiler run. They cannot establish complete attributable preparation CPU, disk, or network totals. The full preparation wall time, input/output bytes, and hashes remain usable. A calibration warm-up pass is not a device-cold or proven steady-state regime. One hundred distinct timed queries do not establish a defensible p99; repeated requests add samples without adding query diversity.

## Primary integration gates

The primary experiment places the same committed logical tree on different physical workers. Shared upper centroid slots represent persisted lower roots. One global beam spans owners; independently allocated per-subtree beams are a separate policy. Explicit maps preserve original global IDs. Global tree generations and lower snapshot generations are distinct, allowing a one-owner append to retain unaffected older snapshots by their own generations and hashes.

Publication validates actual model, map, and snapshot bytes, complete global-ID coverage, immutable model content, stable map prefixes, and a locked compare-and-swap. Lower-reader open and structural verification remain required; manifest hash validation alone does not parse all lower blocks. The publisher now compares model hash and byte length rather than bundle paths, so relocating identical frozen model bytes does not reject a valid append.

The reviewed integrated evidence contains six tiny and nine real10k query/beam records with identical direct, one-host HTTP, and two-host HTTP frontiers, selected candidates, reached leaves, IDs, and distances. Candidate budgets hold. The sparse append preserves the frozen model and upper slots, changes owner 0 to lower generation 2, retains owner 1 snapshot/map hashes at lower generation 1, and exposes all 10,001 distinct global IDs. All 61 sampled old-reader requests remain pinned to the old tree and return unchanged IDs. The retained worker-operation results expose all 64 exhaustive reranking results even when final k is one. Their extracted IDs and distances match a freshly recomputed scalar oracle exactly in direct, one-host HTTP, and two-host HTTP execution. The saved level trace also demonstrates a global beam selecting two nodes from the same owner, which an independent one-node-per-owner policy would change. The real10k traces cover accumulation of leaves reached at different depths. Two ownership slots suffice for the current mechanics gate but cannot demonstrate eight-host distribution. A meaningful 1/2/4/8 placement sweep needs at least eight fixed slots and the same committed tree. Build scaling must keep the same task graph, report the slowest owner and skew, and require completed balancing before timing claims.

## Utilization limit on the next timing run

The current million-vector construction setting uses one owner job per host, one balancing thread, and two runtime threads on 64-vCPU workers. It times distributed scheduling at that allocation rather than hardware capacity. A headline comparison requires a per-host owner-job/thread saturation sweep with the same policy at one, two, four, and eight hosts. Extra parallel jobs on one host may eliminate apparent two-host speedup and must be reported. Query saturation needs its own load sweep with fixed global search work and explicit errors/recall limits.
