# Optional provider cache targets and lifetime

The optional reader configuration controls how much decoded data the existing provider tries to retain and when it explicitly clears that cache. It does not change saved-index bytes, query routing or candidate selection. Omitting the configuration preserves the existing provider settings and command arguments.

The block cache charges max(1, ceil(estimated Arrow-buffer bytes / MiB)) units per decoded block. The root cache charges one unit per root, regardless of serialized metadata size. Both use the existing plain in-memory Foyer cache. The default targets are 256 block units and 4,096 root entries across 64 cache partitions. Optional targets must be positive, divide exactly across a power-of-two partition count from 1 through 64, and fit the platform usize. The partition count is explicit so a small target cannot silently become a zero-sized partition.

A capacity is an eviction target for each partition, not a hard retained-byte limit. The pinned Foyer implementation evicts existing entries before inserting the new item. An item larger than its partition target can remain cached above that target. A standalone weighted-value test proves that behavior and separately proves that clearing the cache leaves an already acquired clone alive. No new cache algorithm or oversize rejection mechanism is introduced.

The optional clear_after_operation flag clears the complete provider after the operation produces owned results and releases reader block pins, on success and ordinary error. The provider is shared by its readers, so this clears shared cache entries. It does not revoke their root metadata or externally held buffer references, and dropping one reader never triggers a shared-provider clear. Dropping generations and explicit provider lifetime remain separate actions. In the existing persistent CLI, one reader owns the provider lifetime; the diagnostic separately exercises a genuinely shared provider with both saved generations.

The full policy is strict JSON with exactly block_capacity_units, root_capacity_entries, shards and clear_after_operation. Boolean values are rejected for integer fields. The optional constructor makes an owned copy and forwards it to the native reader. Every response, including describe and ordinary errors, echoes the effective optional policy. The adapter rejects a missing or different echo before accepting a result. External backends require separate admission and reject this option. The default None omits both the command argument and response field.

The native source review covers one retained real eight-row generation and its nine-row successor, plus one retained sixteen-row deployment. No new index is built. The provider diagnostic compares unchanged default targets, one block unit and one root entry in one partition, and the same small targets with operation clearing. It retains complete scoring and exact-rerank rows, including reopening access through the old generation after new-generation churn. Candidate comparisons normalize tie order but retain raw order. The controller retains the reviewed three-process, sixty-second-per-process, three-minute aggregate, sampled-RSS abort and output limits. RSS remains diagnostic, not an enforced allocation bound.

The separate coordinator fixture compares three fixed queries, including a repeated M=1 tie, under the default, small and clearing configurations. It requires identical complete logical traces and checks ordinary error policy echoes followed by same-process valid retries. Existing bounded reader timeouts and final cleanup apply. Source and both read-only native binaries must receive review before either replay. Physical cache reload counters come from the separate diagnostic wrapper, not from uninstrumented coordinator timing.

The remaining limits are explicit. Cache targets do not bound active reader metadata, pinned buffers, temporary decoding, candidate containers, allocator overhead or process RSS. Census reads change cache recency. Tiny cache churn establishes reload correctness; it does not select production capacities, establish a performance improvement or demonstrate a large-index working set.
