# Append with an admitted parent and counts rather than all old IDs

The experiment removes repeated global ownership work from actual selected-leaf appends. It assumes the exact retained immutable parent has already passed the separate full bootstrap audit. Counts cannot establish disjoint ownership or current versions; the bootstrap remains an explicit prerequisite, with its input identity and cost retained separately. No production trust, default activation, storage policy, corpus growth or new service is introduced.

The existing full-prefix path remains the baseline. It reads both maps, validates the dense prefix and checks every existing local version for every new row. The counted path holds initial counts and new assignments only. It uses exactly the same global routing function and selected-leaf registration, including the new local ID conflict check. Checked counts establish the next global ID, and every append must extend that exact range. Only the selected owner's old map is read and hashed, once at save. That map receives the ordered new IDs, and the unchanged direct-save implementation verifies complete selected-owner versions, postings, vector bits and both exact selected leaf memberships.

Topology policy remains unchanged. Both paths recompute global widths per row, and the actual route function independently checks them. Registration changes posting contents and leaf length but does not split or balance nodes. The prefix differential test compares route owner/leaf/distance bits, mapping and actual widths after every row, including ties and signed zero. Tests also cover count overflow/budgets, wrong new global ID, authorization mismatch and a conflicting new local ID. These are algorithmic contract tests, not a production failure campaign.

The paired run uses the retained representative 96-row parent and the actual two-row materializer export. Both modes write fresh private outputs and must match the independently retained routes to owner b leaf17, local IDs48/49, including exact distance values. The controller reads each saved map and runs a separate actual semantic audit of each saved fifty-row owner. Unchanged a is represented by its exact descriptor/count in the counted reply; expansion into complete98 ownership occurs only in the separately identified controller oracle. No unchanged map is loaded by the counted coordinator. Parent full inventories and all frozen source hashes are checked before and after.

The principal expected work change is193 baseline old-version probes (96+97) to zero counted global-old probes, and768 baseline map bytes to384 selected-owner bytes. These counters do not include selected-leaf current-version checks, new-ID conflict checks or full saved-owner audit work. All-owner node/centroid metadata opens, per-row topology scans, global routing, changed-owner checkpoint copying and complete changed-owner validation remain explicit. Parent versions are loaded lazily; no claim is made that merely opening a writer loads every old version. Count state is O(owners+new rows), but selected save still holds the full changed-owner map, and output/result vectors and allocator overhead are separate. The paired tiny run demonstrates work elimination, not practical latency or100B throughput.
