# A counted parent removes global per-append ID scans

The experiment removes repeated work over every existing vector during a batch, after a separate full parent audit. For N existing vectors and B new rows, the baseline issues N×B+B×(B−1)/2 global old-version probes and materializes N global IDs plus a dense-prefix set. The counted coordinator holds K owner counts and B new assignments, where K is the number of owners. It performs zero global old-version probes and loads only the selected owners' maps at save. Counts alone cannot prove ownership; exact fixed immutable inputs and the separately charged full audit are prerequisites.

The paired 96→98 experiment measures193 global old-version probes versus zero,96 loaded old IDs versus48, and768 map bytes versus384. Both modes produce the same routes, global/local IDs, fifty-row saved vectors and versions, and exact leaf memberships. Parent encoded storage returns change from65,390 bytes across31 fetches to61,610 bytes across29 fetches. Existing caches explain why eliminating193 probes saves only two encoded fetches on this fixture. These are successful returned encoded bytes, not physical disk traffic, network traffic, decode allocation, RSS or a latency speedup.

At100 billion existing vectors, a hypothetical batch of1000 rows would otherwise perform about100 trillion global old-version probes. The counted algorithm performs none of those global probes after parent admission. This is operation-count arithmetic, not measured throughput. It does not eliminate selected-leaf version validation, actual global routing or the full selected-owner save. If a selected owner holds one million vectors, its u64 map still occupies8MB logical payload while saving; it is no longer necessary to load the aggregate800GB global map into this coordinator. Node/centroid metadata remains eagerly opened across all owners, and topology widths are still recomputed and verified for every new row.

The remaining build costs are substantial. Routing still spans all owner roots with the existing exact policy. Changed-owner checkpoint copying, construction-input generation, map materialization and full saved-owner version/posting/vector audit scale with affected-owner size. The record namespace and legacy complete validation retain their full scans outside this experimental path. The single u32 record namespace does not represent100B documents. Larger batches, persistent parent proof reuse, hierarchical routing, incremental changed-leaf saves and partitioned record IDs remain separate assumptions or future work. No claim is made that this change alone makes the full pipeline proportional to the append size.

The accepted baseline model is unchanged. This delta binds the paired raw evidence and the independent complete review in this directory, plus the separate parent bootstrap under poc-proportional-validation-v3. The independent review verifies all884 source pins and1072 retained input files. No additional runtime is required for this delta.
