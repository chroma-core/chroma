# POC: proportional validation with an immutable input view

The POC should validate an append or topology replacement using changed-owner state instead of repeatedly copying and scanning the whole corpus. The experiment explicitly assumes that its pinned saved inputs remain immutable. It measures an algorithm under that assumption; it does not add production immutability enforcement or claim safety for mutable files. Production integration, save/recovery failures, node failures, resizing and deployment hardening are outside acceptance.

## What still scales with the corpus

The working POC already proves global write-beam selection, one selected destination, exact saved leaf membership, explicit record-offset/global-ID mapping and complete output proposals. Its measured reader-held reference path now has an opt-in one-block peak. The remaining algorithmic costs need separate treatment.

| Cost | Current scaling | Next treatment |
|---|---|---|
| Canonical append input | Copies the entire old vector file in the collection adapter, then copies the complete grown file again in the writer wrapper. Prefix comparisons and full hashes also scan old bytes. | A read-only segmented view references the admitted old prefix plus the new tail. Bootstrap admission is separate; later view reads fetch only requested rows. |
| Owner preparation | Copies every owner checkpoint before global routing; all-owner maps and writer metadata are loaded. | Measure this cost explicitly. Later writer integration can route over immutable parent readers and copy/fork only selected owners, without changing the selected leaf. The first replay does not claim this writer cost is removed. |
| Deployment validation | Full maps/global bitmap, every sealed directory, construction vectors, mapped canonical rows, all pages/trie nodes and repeated health validation. | Validate affected owners and compose exact unchanged ownership under the experiment assumption. Preserve a separate complete oracle. |
| Record identity | Complete namespace/source arrays, all three record maps and exact vector/inverse-lookup checks. Append rewrites global namespace tables and changes shared record roots. | Retain actual record materializer/saved-record evidence, account for full record audit separately, and do not claim owner-proportional total append yet. Page the identity/record proof only if later measurements justify it. |
| Routing and loading | The upper centroid frontier and global beam touch owner metadata; fixed global width/beam can visit many owners. Current star root costs O(owner_count × dimension), and initial writer/map opening can be O(owner_count) or O(global rows). | Expose owner count, active frontier, width and root metadata in the capacity model. No query-strategy comparison is needed for this milestone. |
| Candidate/output working set | Inclusive distance ties can retain every candidate, output Vec and exact seen bitmap remain proportional to admitted row/request counts. Provider buffers/cache are separate. | Keep explicit caps and measured held-reference counters; no unconditional M-sized or RSS bound. |
| Placement and load | Full checkpoint transfer and retained snapshots cost bytes. Current CPU/memory load policy uses recorded inputs/declared next-compaction estimates. | Report per-owner bytes/jobs and modeled transfer/capacity, not production telemetry or automatic fleet behavior. |

The first replay is a validator/input-view POC. It does not claim that all current append writer, record, map or publication costs become proportional in one change.

## One coherent replay on retained data

Use the accepted representative fixture, with 96 initial rows, two owners and 32 dimensions. Its actual append candidate has 98 rows; both additions belong to owner b. The first transition preserves owner a's 48 payload rows and changes b from 48 to 50. The second transition uses the retained 98-row split: a's 48 IDs become two 24-row owners and b's 50 payload rows stay fixed. The b routing slot moves from centroid index 1 to 0; validate equal committed centroid/boundary content separately from unchanged saved payload identity. The experiment creates no new corpus, writer mutation, collection registration or publication pointer.

Run the complete current oracle/bootstrap once and retain its actual cost separately. The immutable-input contract pins exact original artifact identities and values for the entire experiment. A final full inventory verifies that the assumption held during the run; that end check is not a production concurrency guarantee. Reuse prior parent proofs only under this declared contract, with no public production cache or fallback change.

Represent canonical rows with a bounded ordered list of immutable byte spans: the original 96-row prefix and the two-row tail from retained append data. A view fixes total row count, dimension, metric/normalization and exact source identity. It checks span arithmetic and coverage, then implements exact row reads and cross-span range reads without writing a full canonical file. Row and boundary comparisons must preserve FP32 bits, including negative zero. The full retained 98-row file is the independent oracle; it is not copied or scanned inside the incremental measurement. Initial hashes, source inventories and oracle reads are reported separately.

For the append proof, require the exact old b local-ID prefix followed by global IDs 96 and 97 once, preserving local offsets and all old values. No output may insert a prior ID into a new owner or lose a parent ID. Validate actual candidate saved versions/postings, single-copy coverage, map order and exact canonical vector bits for b's 50 rows. Check both actual selected leaf memberships. Reuse a's saved payload proof under the immutable assumption while checking candidate routing metadata against the unchanged boundary content. Preserve exact materialized record offsets 97/98 versus global IDs 96/97 and the retained complete proposal; the full record audit remains a separately measured oracle cost.

For the split proof, read the affected old a map and both replacement maps, require disjoint union equality over all 48 IDs, and validate each actual replacement saved owner completely. Reuse b payload identity, record roots, user/offset mapping and canonical values under the assumption. Prove exact namespace ownership-map references and complete global count. The complete candidate view must match the full oracle's logical ownership, vector bits and all saved output references. A count or hash of a multiset alone is not the ownership proof.

## Measurement contract

Report bootstrap, complete oracle and incremental replay as distinct phases. For each phase classify bytes and unique object identities into canonical input, owner map, saved root/block, sealed provenance/inventory, ownership metadata, record/identity and output/copy. Count actual returned encoded bytes at the native provider fetch boundary for native claims, not inferred root sizes or reader-held pin counts. Report Python returned bytes separately. Cache hits can cause zero backing fetches; use fresh providers per measured audit so the result remains reproducible, and report cache configuration. Neither counter is physical disk/network traffic, decoded peak, RSS or latency evidence.

The existing read CLI cannot request the full single-copy audit and bitwise vector verification. If independently approved, add one narrow read-only benchmark entry that calls those exact existing reader methods for an admitted owner and the segmented input view. Optional fetch instrumentation records the consumed root/block byte-buffer lengths before parsing, without changing storage behavior, cache policy or service defaults. This is a necessary small build for real changed-owner validation measurements; retained producer receipts alone would establish prior audit provenance, not a newly measured native audit. No additional production API or failure mechanism is needed.

Expected successful incremental work is owner b's 50 saved rows plus its affected map/vector reads for append, and the 48 replacement rows plus affected old maps for split. Unchanged-owner payload reads should be zero inside this explicitly assumed-immutable validator path; metadata checks can still visit all owner descriptors. The view writes zero full-corpus canonical bytes. Report remaining writer clone/copy and full record costs rather than adding them to the claimed savings. If native counters cannot be implemented faithfully, mark that category unmeasured instead of deriving it from file size.

## Capacity inputs and assumptions

| Input | Measured evidence | Use in the model |
|---|---|---|
| POC state shape | 96→98 rows, two initial owners, 32 dimensions, actual 20/22 embedding-block roots with a test-only 1 KiB split target. | Establishes multi-owner/multi-block correctness only. The artificial split target and tiny object overhead cannot estimate production bytes per vector. |
| Held reader references | Default peaks 15/16 blocks with estimated 9984/10624 payload bytes; serial release peaks one/max1024 estimated bytes on the retained fixture. | Separates operation-held references from provider buffers/cache, output allocation and RSS. No throughput or process-memory forecast follows. |
| Complete validation | Sixteen-row measured Python returned bytes fall 109322→108938 after same-call sharing; the representative 98-row validator has not yet been measured. | Justifies measuring structural cost, not extrapolating a tiny-byte optimization or native I/O. |
| Load and capacity | Existing deterministic policy tests use recorded CPU_ns/windows and declared memory/storage reservations. | Treat future demand, host count, bandwidth and memory capacity as model inputs, not measured production guarantees. |
| Immutable inputs | Fixed saved inputs for this experiment. | An explicit assumption. It does not certify concurrent mutation, garbage collection or production retention. |

At 100 billion vectors, raw FP32 values require 4ND bytes: 12.8 TB at 32 dimensions, 307.2 TB at 768 dimensions and 614.4 TB at 1536 dimensions, in decimal units. A flat u64 global-ID array alone is 800 GB, and a dense one-bit global bitmap is 12.5 GB. These are representation arithmetic, not measured index storage. Current Python objects, version/posting/centroid structures, historical copies and record tables add costs. The current u32 record-offset namespace does not represent 100 billion rows; explicit partitioned offset/global-ID mapping remains a theoretical design requirement, not a completed widening.

The capacity model should state owner rows R, owner count ceil(N/R), dimension, actual steady-state index amplification, compaction fraction, append rate, per-owner working set, global frontier width and measured bytes per affected-owner audit. Whole-corpus validation has cost proportional to N; changed-owner validation has payload cost proportional to the sum of affected-owner rows plus metadata. Do not call it proportional to only the two added rows. Without representative throughput/bytes-per-vector measurements, provide conditional ceilings/formulas rather than a fitted 100B latency or machine-count claim.

## Budget, stop rule and review

Use only the retained fixture and output new evidence, at most 128 rows and 16 MiB of aggregate copied/evidence bytes. No corpus growth or query-strategy comparison occurs. Propose one 90-second work deadline, ten-second native audit calls, bounded provider/report event cardinality and an 8 MiB raw report limit. Pre/post source and fixture hashes run outside measured regions. The complete experiment performs one bootstrap, two incremental transitions and their separate oracle comparisons. Stop on assumption mismatch, incorrect output, unsupported measured surface or budget exhaustion; do not add failure injection or recovery tests.

First review this design and exact source/binary/controller freeze. Then execute the sole bounded sequence. The acceptance result is a working POC validation/input-view algorithm with measured changed-versus-unchanged cost and explicit remaining copy/record/metadata limits. Production-provider enforcement and deployment/failure hardening are not gates. Subsequent native writer integration can replace its File-only canonical interface and eager all-owner clones if this evidence supports that investment.

The implementation separates bootstrap-parent96, oracle-append98 and oracle-split98 as three charged full-validation identities. Incremental phases return a parent-plus-changed-owner ownership view over the exact retained saved roots. Existing legacy page/trie replacement writes new copies even for unchanged owners, so their complete payload validation remains in the separate oracle, not inside the experimental view proof. Shared record/namespace verification is represented by retained actual audit evidence and remains an explicitly unmeasured linear cost in this replay; no new record audit or record proportionality claim is made. The native observer counts all successful LocalStorage get/get_with_e_tag encoded returns, including root and block reads; within-audit provider requests/cache hits and decode allocations remain unmeasured. Fresh provider per audit prevents cross-audit cache reuse. No default publication validator or writer is changed.
