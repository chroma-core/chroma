# Explicit four-bit navigation control

The existing read command adds `--query-navigation four-bit` beside the accepted `one-bit` and `fp` values. Omission preserves the default one-bit path and omits diagnostic policy metadata. Explicit policies require `--profile-query-work`; FP and four-bit snapshots are capped at8192 vectors. All policies preserve the same per-level traversal policy and downstream query semantics.

Responses echo the policy and exact saved generation/source/dimension/metric/root reference. `fp_navigation_cache` describes the FP arm only; the new `compressed_navigation_cache` describes the four-bit arm only, and is null for the other explicit policies. The compressed report binds Code4 byte size, retained code payload, temporary owned FP payload, accounted preparation payload, per-distance logical unpack payload, code digest and preparation elapsed time. Its nested `fp_source_load` is the complete validated source-load report. Repeated response metadata describes one preparation, not32 preparations.

The template pins original saved manifests/maps/query/GT/leaf reports and permits only beam32/k100/rerank2, policies one-bit/fp/four-bit and six ten-second cells with sixty seconds shared. External exact Linux binary and absolute deadline values remain mandatory. The command is `python3 run-queries.py --spec FILLED_SPEC.json`. The frozen offline two-job build recipe is reused; no upload, controller, resource creation or execution is authorized by this package.

The harness validates each cache/root/payload binding before accepting query results and joins existing bounded stage traces with original GT leaf memberships outside native timing. It records actual selected leaves and distance evaluations. Query-level coverage and recall differences compare the compressed candidate to both controls; they do not assume equal work or broader quality. Source-load encoded returns are provider payload bytes, not physical I/O. Preparation scratch and provider/RSS exclusions remain explicit.
