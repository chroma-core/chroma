# Build-input archive layout repair

The Linux build cannot resolve the protocol definitions because its source package omits a repository directory link. The build script opens protocol paths relative to the types crate, and that crate reaches the shared definitions through `rust/types/idl → ../../idl`. Hashing the protocol files at their repository-root paths does not establish that the crate-relative build paths exist.

The repaired source archive preserves all 934 original regular-file members and bytes and adds exactly that relative link. The extracted link resolves to the package's own `idl` directory. Every archive path is relative, contains no parent traversal, and has a unique name; the sole link target stays within the extracted source root. The other repository link, a documentation instruction alias, is outside this benchmark's build-input closure and is omitted intentionally.

Static validation parses the index benchmark's normal, build and development path dependencies, then follows their normal/build and target-specific path dependencies conservatively, including optional declarations. It finds 16 local crates and confirms all 241 source files under their source directories, their custom build script, literal source includes, eight protocol inputs and local protocol imports, and 18 embedded SQL files are present and hash-correct after extraction. This validation runs no Cargo command, build script, compiler, native diagnostic, cloud operation or controller.

The regular-file artifact list is relative to the extracted source root. The link is a separate typed entry in the archive manifest, including its exact target text and target-text SHA. A verifier must inspect that entry with `readlink`, verify its target and containment, and then verify regular files normally. Treating the link as a regular file or dereferencing it into duplicated files changes the declared package layout. The repair does not modify the parent runner or its verifier.

The failed upload bundle, process result and raw logs remain unchanged and are hash-bound by the repair manifest. The accepted native source archives and implementation remain unchanged. The staged Git index remains unchanged. A separately owned next Linux build must bind this repaired archive and its link validation; static extraction success does not replace that build result.

External Cargo registry/git dependency caches, Rust/compiler/linker configuration, system headers, and the protocol compiler's standard Google definitions remain external build inputs. The package pins Cargo.lock but does not prove cached dependency completeness or Linux toolchain behavior. This closure is scoped to the declared index benchmark and is not a universal workspace-build package. Arbitrary runtime paths and future computed build-script paths are outside the static literal audit.
