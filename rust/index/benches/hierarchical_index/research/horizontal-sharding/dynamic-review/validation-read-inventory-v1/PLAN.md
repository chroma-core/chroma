The diagnostic measures repeated Python reads during exactly one complete deployment validation of the retained sixteen-row tree. It changes no validator and grants no cached trust.

The controller hashes the complete bounded fixture outside the measured region, launches one child with a ten-second subprocess timeout, and hashes the fixture again after termination. The child measures one validate_record call, checks the expected complete report and records returned binary bytes, separately UTF-8-encoded returned text, read calls, opens and seek counts by path and nearest validation function. Reads, readline, readinto and iteration are counted; alternate buffered read surfaces fail closed. mmap, os.open/os.read, import machinery and native/provider traffic are explicitly unmeasured. Seek results are positions, not bytes read. Temporary bitmap writes are existing validator behavior.

The fixture inventory is at most 256 files and 64 MiB. Measured reads are at most 64 MiB, with 256 paths, 512 path/phase pairs and 8192 events. The five-second work check is observed at wrapped operations and checked after validation. The parent enforces ten seconds on its only child with subprocess timeout/kill/wait behavior; no native grandchildren exist. The serialized report is checked before stdout and observed output is checked again by the parent at 1 MiB. The output is fresh and disjoint from the fixture. All failure evidence and full pre/post inventories remain. No RSS, physical I/O, durability reduction or cross-call reuse is claimed.

The hypothesis is that repeated flat-map reads in page and trie comparisons are separately visible. Stop on any permission failure, unsupported wrapped surface, accounting budget breach, changed fixture inventory or changed validation report. Only after source admission, run the controller once; no implementation optimization is admitted by this design.
