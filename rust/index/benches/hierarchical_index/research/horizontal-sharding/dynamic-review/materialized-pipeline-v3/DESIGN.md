# Actual materializer export to a saved hierarchy bundle

The internal authority adapter reads the actual typed materializer export and its execution receipt. It captures the delegate's collection context once, validates exact collection/version/log fields, and binds both the registered descriptor file identity and the parsed parent deployment's semantic hash and ownership generation. It reconstructs float32 source values from strict u32 bits; the registration adapter must reproduce those exact bits. Every later health check revalidates the export and receipt files. The complete task, session journal and sealed hierarchy bundle retain the materialized source binding.

The local exporter is an ignored Rust test that calls the actual record materializer and the admitted source-capture adapter. It takes a bounded two-row raw-input fixture, creates new export and receipt files without overwrite, and records the input/export hashes, its runtime binary identity and compile-time source hashes. Those receipts establish this local fixture's producer provenance, not remote authentication or a production compaction-context integration.

The bounded runtime has three stages. A Python preparation helper loads the existing 16-row parent, records its pointer and checkpoint inventories, and creates a captured collection context and two raw log records. The source vector includes negative zero. The admitted Rust exporter materializes those records using its actual u32 ID allocator. Finally, the Python native test consumes that export without fabricated delegate rows, calls the admitted selected-leaf writer, seals the complete 18-row hierarchy bundle, and independently reads both saved leaf memberships. It checks unchanged parent bytes/inventories and no second pointer. Collection publication outcomes use the explicit fake authority; no real RPC is installed or called.

Strict boundary units reject bool IDs/bits, float coercion, nonfinite decoded float32, duplicate users, wrong order/count/namespace/fence, extra fields, source-byte changes and captured-context changes. The actual exporter input is at most 64 KiB, the receipt at most 64 KiB, and its runtime-binary census at most 256 MiB. The writer timeout remains 30 seconds; the two subsequent leaf reads each have a 5-second timeout. These are per-stage work limits rather than a hard process-group deadline. The existing 100k cap, complete validation and provider limitations remain. No cloud work, query-strategy experiment or larger corpus is involved.
