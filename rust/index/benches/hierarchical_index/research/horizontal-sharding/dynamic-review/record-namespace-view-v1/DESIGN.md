# Current namespace view and registration hooks

The current resolver obtains the namespace and exact current record/canonical/owner references from one captured registered bundle. It keeps the construction collection snapshot distinct from current version, log position and publication time. Stable configuration, schema, dimension, collection/database identity and current row count remain checked. The complete actual record collection binding is a new required field of this opt-in context; the default adapter is unchanged.

The existing registration preparation invokes an optional internal metadata producer after saved vector preparation and before bundle eligibility. It then obtains complete segment outputs and validates the candidate metadata. The namespace adapter replaces only the exact record segment's files with the producer's saved outputs. Submission repeats metadata validation before calling registration. A failed producer or validator poisons the private attempt and prevents replay or registration. None returned by an enabled hook rejects.

This milestone implements the binder and hook contracts only. The producer interface is not yet connected to the retained actual materializer result or a candidate record writer. The three focused Python methods use declared fixture artifacts and fake producers, with the existing deployment validator mocked for isolated binding checks. They do not prove actual record/vector eligibility, service authority, provider content or publication. The V7 actual record-store audit remains separate and preserved.

The requested tests are CurrentView.test_construction_snapshot_is_separate_but_configuration_is_bound, HookPoison.test_failed_record_producer_cannot_repeat and SubmitValidation.test_namespace_changed_after_prepare_blocks_registration_and_poison_replay. No native binary or external service runs in this milestone. The next actual producer freeze must consume the existing result, flush candidate record roots, audit them against the saved canonical/ownership artifacts, retain exact old mappings and expose those roots in the same complete registration proposal.
