# Candidate memory design for review

The next bounded operation can retain the nearest M distinct IDs and every ID tied at their cutoff, while a separate dense-ID bitmap preserves the exact number of distinct live IDs scored. This is a design proposal, not source or runtime admission. Physical posting decoding, provider caches, quantizer scratch, output arrays and RSS remain separate concerns.

A candidate's distance is the minimum over every current-version physical copy scored so far. The Mth smallest such distance never increases as additional rows arrive. An ID discarded for exceeding an earlier cutoff has no competitive forgotten minimum: that old distance also exceeds the current cutoff. A later improved copy can therefore be processed as a fresh admission. IDs tied at the cutoff must remain retained; a capacity limit rejects the whole request rather than breaking ties or truncating candidates.

An ordered collection of distance groups and an ID-to-distance map can implement this invariant without unbounded stale heap entries. A better duplicate removes its previous group entry before adding the new minimum. Remove the worst complete distance group only when the remaining number of IDs is at least M. Finite negative zero and positive zero must use the same numeric tie group. New insertion, pruning and allocation limits need a separately reviewed bounded transient allowance; a final-state count alone does not bound allocation capacity.

Exact distinct-live-ID counts require independent state for discarded IDs. Under the existing dense local-ID count cap, a checked bitset uses at most 12,500 payload bytes for 100,000 rows. Every row must pass authoritative version and range checks before setting its bit. This retains the unique-scanned meaning even when only a small candidate set remains. Physical rows, current physical copies, unique live IDs, retained candidates and transmitted candidates keep distinct counters.

The proof tests must compare against the all-minima reference across adversarial row orders, late duplicate improvements, repeated discarded IDs, unequal per-leaf scores, all ties, signed zeros, M larger than the processed prefix and capacity failures. Randomized tests must cover every prefix, not only final top results. A huge tie group still requires linear retained state or fails the explicit cap; this design cannot promise an unconditional M-sized bound. Default behavior and the existing all-minima path remain available until a separately frozen implementation and native replay are admitted.
