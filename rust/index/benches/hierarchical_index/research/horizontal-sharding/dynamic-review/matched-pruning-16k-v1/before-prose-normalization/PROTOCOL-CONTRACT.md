# One16K comparison under the scale authorization

This package runs one prespecified comparison of an ordinary parallel tree and the same global tree kernel with one or four local authoritative owners. The exact human scale authorization is retained in SCALE-AUTHORIZATION.json. It permits this larger input; it does not substitute for the external sandbox, budget, guarded window and shutdown controls. The worker performs no cloud actions.

The input is the first16,384 rows of the admitted restored2M canonical file, in original order, with768 coordinates and inner-product distance. Preparation copies50,331,648 bytes once, hashes the consumed prefix, rejects exact FP32 query-vector duplicates and declared canonical-global ID overlaps, and recomputes top100 from this prefix using the existing FP64 blocked engine. It never filters a2M ground-truth list. All100 retained queries are copied in their original order and hash-bound; they are reused research queries. Their publisher/query IDs do not prove corpus exclusion, so disjointness remains unknown even after duplicate checks. There is no corpus download to the Mac.

All three construction arms use four add threads, four balance threads, explicit FP write navigation and FP neighbor eligibility, branching4, split256, merge64 and common4096-row balance cuts. The native input reader reads8192-row chunks into the same bounded full-prefix buffer; these reads do not add balance or placement boundaries. The one-owner arm skips migration and must report zero moves. The four-owner arm starts with one owner, places branches only after joined balance and must finish with four populated owners and positive moves at threshold4096. Threshold4096 controls placement, not topology. The default reference kernel and accepted grouped-scrub/immutable-predicate owner policies remain intact, with direct-current reads disabled.

The source changes raise only the explicitly bounded experimental row and stage-ID caps to16,384. Owner/node/cache structures remain process-local; all immutable vectors are still cached and full joined save, map generation and saved census are charged. The Code4 centroid cache retains its256-node and1MiB FP-payload caps; observer maps and stage bounds also remain enforced. An over-cap tree stops rather than expanding the cap. The kernel uses existing uncontrolled split initialization and nondeterministic thread schedules. Those are recorded as uncontrolled, so the independently built trees do not provide seeded or fixed-work causal timing comparisons.

Each arm publishes its original create-new manifest and streamed identity map. Map write and verify overhead is131,072 bytes each per arm, and later controller/diagnostic map reads are separate. The native operation performs the full saved current-membership census, verifies all saved vector bits and reports all-ID exact-distance bits. All three exact-distance outputs must agree; this does not imply identical trees or ANN quality. The original manifests and maps are hashed before and after every later stage and are never rewritten downstream.

The unchanged ground-truth diagnostic runs seven batches of at most16 queries per arm. Each batch preserves the existing1,600-ID union bound and charges its full saved census/map work. All100 queries must have exactly100 expected and covered true neighbors, with exact no-replication leaf and weighted-row oracles. The controller merges only the per-leaf ground-truth ID sets for query-stage joins; these sets do not change the saved index or search.

One fresh Code4 reader per arm receives one warm-up pass and one retained pass at per-level beam_min=beam_max=32 with the accepted tau2.0. The posting scorer, candidate trim200 and FP32 exact rerank100 remain unchanged. The cache policy is explicit for every query arm:256 soft block-capacity units,4096 root entries, one shard and no provider clear after each operation. This changes both cache partitions relative to historical64-shard observations, applies equally to all three new arms, and is not a claim about production defaults or a measured cache fix. Warm timings include tracing and its node-kind lookups; encoded storage returns remain distinct from physical I/O, network or actor fanout. Code4 preload, conversion, retained codes and scratch accounting remain separate.

Structural admission uses actual retained-query traces, not the nominal beam width. A complete trace must reconcile internal and leaf partitions, retained-to-next-expansion counts, centroid evaluations and expanded internals against the exact saved-generation census. At least80 of100 retained queries in every arm must discard an internal candidate and expand fewer internals than the saved total. Failure yields structurally-insufficient, preserves all data and stops this fixed attempt without resizing, threshold changes, seed searches or retries. Equal beam settings do not establish matched recall; results at unequal recall cannot rank latency or byte efficiency as matched-recall performance.

The scientific budget is at most780 seconds:60 setup, three construction/save/census arms at most180 each with540 shared,90 for all ground-truth diagnoses and90 for the three query readers. Build has a separate600-second cap using the pinned Linux Rust1.92 compiler, offline dependencies, two jobs and release opt-level3. The proposed external window is1,800 seconds with a$0.30 ceiling on the retained driver; actual resources, absolute deadline, guard and binary descriptor are supplied by the sole operator. No time or resource is inferred or extended by this package. Each phase takes the minimum of its own remaining time, the scientific deadline and the external absolute deadline.

The disk free floor is20GiB, retained store payload is at most512MiB per arm, metadata at most128MiB including the final result estimate, and cumulative observed child peak RSS is at most8GiB. These are post-operation observations and stop conditions, not allocation bounds. Child timeouts do not replace the external shutdown guard. Whole-child CPU/context switches and cumulative peak RSS are recorded; overlapping actor waits are not CPU fractions. Disjoint native input/setup/phase/save/audit/publication/residual timers reconcile before serialization. Row copies and add/balance/reshard timers are nested within phase elapsed; reservation remains inside add and cannot be reported as a separately measured exclusive phase. Whole-process time also includes output serialization and exit.

The local package evidence consists of one16K capacity-admission test, five Python wiring methods with success/structural-failure/stage-failure cases and a generated64-row,32-dimensional native three-arm entry check with saved census, exact-bit agreement and real traced Code4 queries. These local ARM checks do not execute retained16K data, establish internal pruning at beam32, measure Linux performance or prove distributed execution. Existing constituent correctness suites are not repeated. The post-build artifact-copy path error is retained separately; both Cargo stages pass and the exact newly linked hashed artifact is retained without a rebuild.

The full effective construction configuration records the fixed single-copy rule and empty per-level write overrides in addition to the input configuration. These values are enforced by the existing explicit-FP configuration decoder. Linux child RSS is reported in KiB; the local Mac test wrapper normalizes Darwin byte units before applying the same observed limit. The earlier unit-mismatch test failure remains preserved.
