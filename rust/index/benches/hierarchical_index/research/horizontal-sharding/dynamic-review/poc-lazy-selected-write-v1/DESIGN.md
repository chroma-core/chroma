# Write selected leaves without whole-corpus input copies

The POC uses the existing global write traversal and direct-save implementation, while reading canonical rows from immutable spans and copying only owners that actually receive a registration. The experiment assumes the retained parent files stay immutable. It creates no production storage contract, service, collection registration or failure campaign. Default commands, routing/tie policy, public schema and saved data format stay unchanged.

The new explicit benchmark command opens both actual parent writers for the shared traversal, reads their current maps, and calls the existing append_owned_global for IDs 96 and 97. That helper computes the same global widths/beam, chooses one owner/leaf and registers directly in that writer's private in-memory state. No balancing or rebuild follows selection. Once routing is complete, an owner with the same local count receives no output directory or copy. A changed owner receives a fresh checkpoint copy; the already-mutated writer commits directly into that copy using the previous five root IDs. The source checkpoint is never used as the save destination.

The shared save routine now accepts a canonical-row source. The legacy File implementation performs the same seek/read_exact per row; the segmented implementation checks dimensions and reads the requested row across its immutable spans. The direct commit, flush, full single-current-copy audit, exact vector-bit verification, selected-leaf membership verification and generation/map publication stay in the same shared function. The default wrapper supplies no observer, and its provider/cache settings remain unchanged. The extraction diff is retained for review; selected_write.rs and distributed.rs remain byte-identical.

Only this POC uses the optional local encoded-read observer on parent and saved providers. It reports successful root/block buffer returns, not cache requests/hits, decode allocation, physical I/O, process memory or latency. All owner maps, parent versions and writer metadata are still loaded; WriteOwnership validates the whole dense prefix and append_owned_global checks old local versions per appended row. These remaining O(global rows) reads/working sets are explicit. Changed-owner construction inputs/maps and its complete saved audit remain O(changed owner rows). This milestone removes eager copies, not every whole-corpus cost.

Its actual record offsets 97/98 correspond to global IDs 96/97. The controller checks the source bits, including negative zero, against the two-row canonical tail. The first addition crosses the nearest committed upper boundary and the second has a committed f32 root-distance tie, as retained in the independent reference evidence. Both actual routes must equal the retained independent writer routes, including owner, leaf, local ID and distance.

First execute a copy-only baseline that reproduces the existing two canonical materializations, append-tail file and both owner checkpoint copies. Count actual returned/written Python bytes and files; this is not a second writer or index run. Then execute the new native writer once. It must produce no full canonical file and no owner-a checkpoint. Its actual owner-b copy count must equal the baseline's b count. Read the new saved map, require complete disjoint IDs 0 through 97 and unchanged local prefixes, then run the read-only native semantic audit on the actual new b snapshot. It verifies saved versions/postings, all fifty vector rows, and both exact selected leaf memberships. The complete experimental vector view contains the new b references, unchanged a references, frozen model and segmented canonical input. It does not claim a new record or legacy collection proposal.

The unchanged parent inventory is checked before and after, including both actual source checkpoints. Retain native source/spec/output hashes, copy counters, canonical view reads, per-owner parent encoded reads and saved-provider reads. Retained full record/bootstrap/legacy oracle evidence is linked separately rather than rerun or hidden in incremental counters. Do not compare the copy-only baseline's total time or bytes to the complete new writer as if both measured identical work; compare copy categories directly and expose the remaining read categories.

Use Rust 1.92, locked/offline, two jobs, debug info disabled, a 20 GiB free floor and 1200 seconds per build command. Preserve all source end hashes, logs and the exact executable before runtime admission.

After whole-source and binary review, run one controller invocation with Python 3.13.5 and a fresh runtime-attempt1. The native writer has thirty seconds, the independent saved-owner audit ten seconds, and the controller a ninety-second work alarm. The corpus stays at 96→98, with a 128-row cap. Copy helpers check observed 8 MiB/2048-file selected-owner budgets, the runtime checks observed 16 MiB/4096-file output and 8 MiB report limits. These are scoped observed limits, not instantaneous OS resource bounds. All processes are ordinary subprocess.run children with timeout handling; no listener, cloud action or process-group operation occurs. No corpus growth, query-strategy comparison, production integration or failure injection is part of acceptance.
