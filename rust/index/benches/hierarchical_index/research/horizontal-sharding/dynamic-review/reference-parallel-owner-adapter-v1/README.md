# Run the reference parallel construction through owner-authoritative data

One shared logical tree uses the existing reference insertion and balancing code while local owners hold its mutable postings and current versions. Insertion workers perform their own global destination navigation. Balancing workers use the reference weighted subtree scheduler, including live descendant collection and its handling of missing nodes, parent replacement and orphan adoption. Capacity placement runs only after those workers join. This is an executable local construction POC, not cross-host execution or a matched quality result.

The routing component holds centroids, child and parent links, physical lengths, atomic root and node identities, and the reference balancing set. Its leaf records have empty ID, version and code vectors. The owner actors hold those posting arrays and current-version maps. A directory maps leaf and vector identities to their owners; per-vector locks coordinate transfer of version authority. The coordinator has no mutable posting or current-version mirror. A joined publication builds a temporary complete snapshot from owner data, then uses the ordinary saved format. That full materialization and write remain publication costs.

The adapter calls the reference parallel scheduler directly. It retains the reference per-node map access, balancing set, reentrant structural lock, registration retry, missing-node checks and orphan helpers. Splits and merges temporarily take their posting payload from the owner and install their replacement lists back on the owner. Structural topology and parent changes remain under the reference synchronization. Neighbor snapshots and full-precision predicates execute through the source owner. Immediate registration transfers current-version authority to the destination owner when the version still matches. Per-vector locks prevent a lookup from observing the gap in that transfer. Independent parallel schedules can produce different valid trees; they are not required to match one serial decision tape.

Full vectors use the reference shared immutable embedding cache in this local implementation. Neighbor snapshots copy their IDs, versions and codes. Predicate center bundles are copied once per neighbor or replacement-cluster scope and shared through immutable references; full vectors are shared through immutable references for predicates. Registration still copies the supplied vector for its owner message. Placement moves the owned list buffers and version records in process, without rebuilding clusters. Logical moved payload, snapshot copies, registration vector copies, center copies and shared cache payload are separately reported. These are not serialized network bytes. Durable remote vector loading is not implemented by this adapter.

The phase wrapper starts with one owner holding the root leaf. An add phase admits unique dense new IDs and finite vectors before mutation. It reserves conservative physical-row headroom at every owner, allowing all new rows and another batch-sized balancing allowance at any owner. Physical rows include stale entries. This allowance is separate from the soft leaf-split threshold and does not guarantee that arbitrary balancing fits. The hard per-owner physical-row ceiling is 1,048,576; exceeding it stops the POC rather than providing a recovery protocol. The wrapper admits at most 8,192 vectors, 768 dimensions, eight owners, eight workers and 32 phases. It supports explicit full-precision navigation and full-precision neighbor predicates with one current copy. Updates, deletes, resume and cross-host execution are outside this interface.

The current reference structural lock covers leaf removal, vector preparation, clustering and parent replacement; it is not assumed to be a brief metadata lock. Registration and other structural helpers also use it as in the reference. The report distinguishes its outermost same-thread hold spans, summed acquisition wait, actual subtree worker spans and neighbor-processing spans. Recursive entries do not inflate the distinct-thread peaks. Neighbor-processing elapsed time includes any nested structural work and waits; it overlaps other counters and is not additive CPU time. Owner callback peaks record actual entered callbacks, not configured pool size. Scheduler assignments are bounded metadata samples; their overflow flag must be retained. No field claims simultaneous CPU utilization.

The construction test starts with 512 synthetic vectors, balances in parallel, moves existing leaves among four owners, then adds another 512 vectors and balances with the same changed threshold schedule in both arms. Its final tree has multiple internal levels. Actual reference splits, merges, parent edits, owner predicates and placement moves occur. All owner current records remain unique, the global mutable posting and version counts remain zero, and full saved census and per-vector bit checks pass. Every saved posting code is independently recomputed from its saved leaf center and source vector. Exact full-ID distances match an independently scheduled reference tree. A pinned 512-vector reader retains its results after further construction. These exact-distance checks establish saved-vector coverage, not ANN quality.

A separate concurrent interaction test supplies two missing-parent replacements through the actual reference orphan helper and verifies adoption, parent consistency and a full saved census. The main construction also exercises concurrent parent changes; whether natural missing-target retries occur is recorded rather than assumed. Wrong-owner, missing-owner and unsupported-policy checks fail without a central data fallback. The existing default reference parallel split/merge/deletion regression passes with the owner backend absent. The initial recursive-span accounting result is retained as unsuitable for thread-concurrency claims; the corrected observer de-duplicates recursion. A report-macro compile failure and its repair are retained.

The native diagnostic exposes paired `reference` and `owner` treatments through `reference-owner-diagnostic --spec`. Both use the same explicit full-precision configuration, vector prefix and balance cuts. The owner treatment begins on one owner and moves existing branches only at completed boundaries. Its local 64-row native check verifies both saved censuses, all vector bits and full-ID exact distance equality. The trees are independent and stochastic. No timing ratio or clustering-quality claim follows from this check.

Remaining costs are material. The reference routing metadata, vector-owner directory, per-vector conflict locks and full immutable embedding cache remain local and proportional to corpus size. New IDs initially allocate version authority on owner zero before destination registration, which can concentrate control requests. Owner commands and neighbor snapshots add coordination and copying costs. Placement scans all leaves and checks current records; publication materializes all postings and versions into a temporary ordinary writer and writes a full saved snapshot. The API's small bounds and the shared local cache do not establish 2M readiness, distributed memory, remote I/O cost or an end-to-end speedup.

The implementation boundary is the new owner adapter and minimal opt-in hooks in the reference writer and its persistence lookup. The ordinary backend remains absent by default. The separate native command adds only a diagnostic entry in the existing benchmark binary; it does not change the normal construction command or the parent evaluation runner. Exact paths, hashes, stage results and retained attempts are bound in the source and deploy manifests.
