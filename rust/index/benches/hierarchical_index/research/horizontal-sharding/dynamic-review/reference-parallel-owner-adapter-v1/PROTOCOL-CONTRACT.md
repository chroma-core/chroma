# Bounded native reference-owner diagnostic

The existing benchmark binary accepts `reference-owner-diagnostic --spec <absolute JSON path>`. This command runs one treatment and writes a create-new output directory. It performs no network, lifecycle, upload or controller action. A caller supplies and enforces any absolute deadline and resource window; none is inferred by the command.

The spec uses the protocol string `reference-owner-parallel-v1`, a nonempty `source_id`, a vector descriptor containing `path`, whole-file `bytes` and externally supplied whole-file `sha256`, and `prefix_sha256` for the actual consumed bytes. It also requires `rows`, `dimension`, `metric`, `config`, `treatment`, `threads`, `balance_every`, `owner_slots`, `move_above` and `output`. Unknown fields are rejected. The source file length must equal its descriptor; the exact consumed prefix is hashed before construction. The command does not rehash a larger full corpus or independently establish its immutability.

The treatment is `reference` or `owner`. Both run the same reference parallel routing, balancing scheduler and explicit FP navigation/NPA policy. The config schema is the existing explicit-FP construction schema. The command admits at most 8,192 rows, 768 dimensions, eight threads and eight owner slots. Owner placement starts on one root owner and uses `move_above` only after joined balancing. Balance cuts are logical row boundaries, independent of storage chunking; this implementation retains the full bounded input and reference embedding cache in memory and does not publish a new vector root per storage chunk.

The result echoes the consumed spec and its SHA256, source prefix binding, per-phase add/balance/placement elapsed times, owner accounting, five saved root IDs, save/audit elapsed times, complete saved current-membership census and exact distance bits for all input IDs against the first vector. It verifies every saved vector bit. Owner accounting includes scheduler assignments, depth, occupancy, actual distinct-thread peaks, structural lock hold/wait and copy categories. The node census has a 10,000-node audit cap and a 1,048,576-entry per-leaf cap; those are audit bounds rather than preallocation guarantees.

The owner report is captured after publication so its snapshot-copy counters include publication. Publication uses a joined temporary full ordinary writer; `save_seconds` includes that materialization and saved writes. The embedding cache remains shared and local. The saved root IDs are diagnostic outputs, not a generation manifest for the existing ground-truth command. Independent parallel schedules have no exact tree or ANN-quality equality guarantee. No main `construct-global` or parent-runner integration is claimed.

The local native correctness check uses 64 synthetic 32-dimensional vectors and two treatments. A future retained 8,192-row execution requires an exact Linux binary descriptor and separately authorized deadline/guard/resource bindings. This package creates neither and authorizes no cloud execution.
