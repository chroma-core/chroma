# Batch immutable owner predicates without delaying live mutations

The accepted paired run exposes consequential coordination cost: owner balance takes 16.136954997 seconds, while the independently scheduled reference takes 0.417727490 seconds. The owner performs 97,210 pure predicate callbacks, and each current-version lookup also makes a synchronous actor call. Its outer structural lock holds for 1.390784870 seconds in aggregate. These overlapping elapsed observations identify a coordination hypothesis; different stochastic work prevents a causal ratio or exclusive attribution of the remaining time.

This opt-in change batches at most 64 immutable vector/center distance predicates into one source-owner callback. Each decision uses the same existing full-precision arithmetic. The caller consumes decisions in the original row order, checking the current version and evaluated-ID set at the original point and immediately performing eligible reassignment. Earlier reassignments therefore remain visible to subsequent rows. No version is prefetched, cached or delayed. Owner placement cannot change during these joined construction phases; the vectors and center bundle are immutable references. The batch may compute decisions for rows later rejected as stale or already evaluated; the computed-row counter records that extra work separately.

The default policy stays disabled and avoids constructing a batch. A private-wrapper method enables the policy only at a joined phase boundary. The native CLI remains unchanged and does not enable it. The scheduler, tree locks, registration, ownership transfer and scrub logic remain unchanged. This milestone does not eliminate per-row current-version actor calls, owner-zero initial admission or full placement/publication scans.

A fixed 130-position input contains a missing vector at the 64-row boundary and a two-row tail. For both self and neighbor predicates, the legacy path executes 129 callbacks and the batched path executes three callbacks with identical ordered optional decisions. Across both modes, callbacks decrease from 258 to six, removing exactly 252 callbacks. Empty batches perform no callback. The test also checks live current-version mutation independently of precomputed pure decisions. These are work-count assertions, not a timing benchmark.

The existing 1,024-vector multi-region construction enables batching and verifies complete saved current membership, every saved vector and posting code, full-ID exact distances against an independently parallel reference, placement and pinned old readers. Missing-parent and wrong-owner tests remain included. The wrong-owner panic printed in the passing negative test is caught deliberately. Four tests pass; the benchmark target passes compile checking. The first run's three passes and obsolete individual-callback assertion failure remain in `attempt1-old-counter-assertion`; the repair changes the assertion to require batched work rather than weakening saved-state checks.
