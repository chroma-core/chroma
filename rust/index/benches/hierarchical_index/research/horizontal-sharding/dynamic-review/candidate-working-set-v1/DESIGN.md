# Isolated candidate collector acceptance

The collector is compiled only for CPU tests. No CLI request, streaming operation or default query path selects it. The source archive contains the complete source closure, and the native V5 streaming replay remains a separate binary and receipt.

The component keeps an ID-to-distance map and ordered distance groups, with signed zeros in one group. Each successful push finishes duplicate improvement, group insertion and whole-group pruning before returning. A failure latches the private operation, and later snapshots, pushes or distinct-count requests reject it. Diagnostic metrics remain available after failure but are not candidate results. The seen bitmap preserves exact distinct counts for IDs discarded from the candidate state.

Limits distinguish final retained entries, one optional staging entry, the final cutoff group's tie count, output entries and bitmap bytes. New candidate entries are checked against retained-plus-staging count before insertion, and output count is checked before allocating its vector. HashMap capacity, bitmap capacity and output capacity are measured separately. These are count and payload limits, not a bound on BTree node allocations, hash control bytes, allocator overhead or RSS. Standard BTreeMap/BTreeSet allocations remain infallible allocator calls; process OOM is not converted to a structured collector error. Explicit configured limit failures latch the operation and expose no partial result.

Four focused CPU tests pass in 0.11 seconds. Every prefix of 24 deterministic sequences is checked for each of M=1, 2, 7 and 32: 15,360 prefix results and exact distinct counts agree with the complete min-distance oracle. Additional checks cover a discarded ID returning with a better distance, all cutoff ties, positive and negative zero, losing NaN duplicates, exact staging capacity, one-over staging or tie capacity, output overflow, bitmap admission and invalid serialized limits. A selective 32-ID/M=2 case retains two entries, has HashMap capacity three and 24 key/value payload bytes, uses a four-byte bitmap and returns two output entries. These counters are component properties, not a whole-query or physical-host capacity claim.

The independent review repeats all four tests and 15,360 prefix checks successfully. Native integration requires a new source freeze and admission. It must preserve current-version filtering, the existing streaming physical-row and total-unique limits, all external-ID cutoff ties and whole-request failure behavior. Output conversion overlap and provider/quantizer memory remain separate. No search semantics change or native activation is admitted by this component receipt.
