# Four-bit residual posting quality experiment

This experiment tests whether an existing higher-fidelity posting scorer retains useful candidates at fixed navigation. It changes one common posting policy across three immutable saved trees. It does not widen the search beam or candidate budget to pass a target.

## Policy and saved generation

Both ordinary reference and dynamic trees use persisted full-precision centroids for navigation. The fixed per-level beams are 36 for reference, 38 for one local owner and 36 for four local owners, with tau 2.0. These navigation choices are informed by calibration. The existing cutoff still partitions by ascending approximate distance, truncates exactly to 400 candidates and sorts those candidates. The existing full-precision reranker returns 100 results. Current posting rows are filtered by the existing reader, and scoring emits distances in that same physical-row order, with the same minimum-by-ID reduction and tie behavior. All prior defaults remain unchanged when the overlay flag is absent.

The new scorer uses the existing four-bit quantizer relative to each persisted leaf centroid. It passes the full-precision query residual, centroid norm and dot product, and query norm to the existing four-bit distance correction. Inner-product distance remains one minus the reconstructed dot product. The one-bit control uses a quantized query, so this is a comparison of supported scoring paths, not an isolated stored-bit-width experiment. The current implementation also retains the original per-leaf query quantization setup; no latency improvement is claimed.

## Immutable overlay and bounds

Saved tree formats, objects, manifests and ID maps remain unchanged. A separate immutable directory holds one four-bit code file per leaf and a manifest binding the original saved manifest digest, root, metric and dimension. Each leaf binding covers its persisted centroid bits and the sorted multiset of current ID, version and original one-bit code. Sorting the binding does not change score emission order. One four-bit code is stored per distinct ID within a leaf; repeated physical copies still emit repeated distances in the original loop. Each code file records local IDs and bytes with a whole-file digest. A reader verifies the same live membership binding before accepting an existing overlay.

Preparation processes one leaf at a time and copies one raw vector at a time. The bounds are 16,384 input vectors, at most 256 loaded nodes/leaves, 4,096 persisted physical rows per leaf, 32,768 persisted physical rows across the snapshot, 16 MiB of retained code payload and 512 KiB of overlay metadata. Code files are created without overwriting, flushed and synced before a synced manifest is written. The exclusive preparation call joins every read before block pins are cleared or the observation is reset. A malformed code length/header, wrong generation, digest, ID set, current posting binding or centroid fails before an overlay becomes active.

At 768 dimensions, each four-bit code is 396 bytes, compared with 112 bytes for the existing one-bit code. The file additionally stores four ID bytes per distinct leaf-local code. Both the original Code1 store and loaded original posting arrays remain present. The code payload is not total resident memory. Preparation includes one leaf’s binding copy, one serialized leaf buffer in addition to retained codes, one raw vector, centroid data, bounded metadata/maps, quantizer residual/absolute/grid/packing arrays and critical-point storage. The existing quantizer has dimension-bounded critical points; allocator capacity and provider decoded roots/cache are separately unmeasured by payload arithmetic. Per-distance unpacking uses 6,144 logical bytes of u32 and f32 scratch at 768 dimensions. Observed child RSS remains a coarse process high-water, not an allocation proof.

Native reports separate preparation elapsed, actual embedding gets and logical return bytes, explicit and loader centroid gets, retained code payload, leaf-copy payload and raw vector-block observations. Aggregate traffic is reported only when the existing completeness checks close against the counted preparation point gets; otherwise it is unavailable. The orchestration reports exact serialized sidecar bytes and repeated integrity hash-read bytes/time. These are logical and encoded-return quantities, not physical I/O, wire bytes or network latency. FP navigation preload and all-posting/current-version materialization are charged before queries. Preparation can warm provider caches, so query timing is not compared as an isolated speedup.

## Calibration and sealed evaluation

The protocol reuses the exact 288 document-query IDs, canonical exclusion/duplicate provenance, query files and new prefix ground truth from the reserved-cohort protocol. It performs no extraction, corpus download or ground-truth recomputation. Old 100-query membership reports are not joined. New Code4 calibration runs on the same 32 queries for all three arms; old passing one-bit cells are not reused as new-policy passes. The offered leaves, live current ID sets, raw physical score emissions and navigation work must match the hash-bound one-bit calibration at each fixed beam. Retained candidates and returned IDs may change because that is the tested mechanism.

Each arm must reach at least 95% mean calibration recall and show actual internal pruning on at least 26 of 32 queries. A miss is a terminal scientific negative with no evaluation, sweep, retry or target reduction. After all arms pass, the program writes and fsyncs a selection artifact and its descriptor, then syncs the containing directory. This artifact binds the complete common scorer/configuration, new binary build, original snapshots and every overlay manifest/code digest. It is checked before the first evaluation read and before and after each evaluation reader. Only then may the fixed 256 reserved queries and labels be accessed.

The unchanged inference uses paired queries, SplitMix64 seed 2026101701, 10,000 shared resamples, and linear quantiles at 0.005 and 0.995. Five 99% intervals cover three absolute recalls and two dynamic-minus-reference differences, with approximate simultaneous 95% conditional coverage. A conditional pass requires each absolute lower bound at least 95%, both paired intervals inside minus/plus one percentage point, and at least 205 of 256 queries with actual internal pruning in every arm. Other outcomes remain negative or inconclusive. This is fixed-tree empirical resampling over deterministic, potentially correlated document queries, not population certification or between-build equivalence.

## Runtime and evidence

The proposed fresh external window is at most 1,200 seconds and $0.20, with an offline two-job release build capped at 600 seconds. Scientific work is capped at 180 seconds: calibration is at most 45 seconds with 15 seconds per reader; evaluation is at most 90 seconds with 30 seconds per reader; inference is at most 10 seconds; admission inventory is at most 20 seconds. The shared elapsed cap includes remaining orchestration and integrity work. Admission requires 180 seconds before the fixed external deadline for preservation; final preservation is at most 30 seconds. Disk floor is 20 GiB, observed child RSS cap is 8 GiB and retained metadata cap is 512 MiB using the accepted exact formatted-serialization accounting. Added score traces are charged and may cause a preserved cap failure; the cap is not automatically raised.

The existing Linux build recipe binds the exact source closure, safe IDL symlink, pinned Rust 1.92 compiler, release optimization and actual binary descriptor. Effective environment/configuration, resource guards, transport and shutdown admission remain external. No worker cloud action occurs. Exit 2 is a collected calibration negative, exit 1 is an operational/integrity failure, and exit 0 is completed evaluation regardless of whether its scientific inference passes.

Only bounded vector-free results, reader replies, process receipts, calibration/evaluation ground-truth IDs and distances when accessed, original snapshot inventories, overlay manifests, sealed selection/configuration and build provenance are eligible for retrieval. Query files, requests, canonical vectors, saved object stores and leaf `.code4` payloads remain remote. Existing saved trees predate the live-prefix and split-filter construction changes. Four owners are local actors on one machine; this experiment measures saved-tree quality and local reader work, not physical distribution.
