# Make write preparation follow the visited frontier

The next recommended architectural milestone removes eager metadata opening for every owner and repeated complete-tree width scans from append routing. The counted-parent experiment already removes global old-ID probes and global map materialization, but each batch still opens every owner's full writer skeleton and full-precision centroids. Every appended row then computes all level widths twice: once before routing and once when routing verifies them. This work is certain from the source; its practical time at realistic scale is not yet measured. It prevents a credible bounded-working-set build path when global node metadata exceeds one machine's memory.

The preserved registration operation changes a leaf's IDs, versions, codes and length, then marks that leaf dirty. It does not change node IDs, child relationships, centroids or the number of nodes at each level. An admitted fixed immutable parent therefore supplies a valid routing geometry and aggregate width summary throughout an add-only batch with no balancing. The current helper nevertheless computes depth recursively and traverses every node for each width request. Parent-level policy/config agreement and complete global widths can be established once, separately charged with the full bootstrap, rather than by repeated scans per row.

The coherent POC interface would separate immutable route access from mutable selected-owner writers. A route view binds exact parent roots, policy, committed boundary centroids and global level widths. It resolves only the root/frontier node records needed by the existing global beam and keeps a bounded owned-node cache. The same route arithmetic, owner/node tie ordering and mixed-depth leaf accumulation must be shared with the eager oracle. A selected owner opens its actual writer once, receives the exact chosen leaf directly and saves through the existing selected-leaf path; an unselected owner opens no mutable writer. No navigation or rebuild follows the selection. Global ownership remains counts plus ordered new assignments, and saved-owner full audits remain independent.

A fixed-input bootstrap may export an indexed routing view once from the actual admitted nodes/FP32 centroid bits, with its full cost and bytes explicit. That is an experimental immutable-input representation, not a production storage guarantee. The hot path must perform actual indexed/on-demand reads rather than load the whole exported geometry and call it lazy. Root metadata and centroids still scale with owner count, and exact flat-root scoring remains. The proof must not imply hierarchical root routing or cheap high-dimensional pruning that is not implemented. Source roots, changed-owner saves, canonical overlay and record/legacy costs remain separate.

The smallest meaningful experiment reuses the retained96→98 geometry and exact global destinations/ties. It compares eager counted-parent routing with the route-view path and requires identical every-level candidate/frontier decisions and final saved memberships. Counters distinguish separately charged bootstrap bytes, actual routing node/centroid reads and cache occupancy, width traversals, actual owner writer opens and selected-owner save bytes. It should show zero mutable owner-a open, one owner-b open, and no per-row all-node width traversal. If the tiny beam visits all nodes, report that honestly: the fixture can establish removal of eager writer opens and repeated width scans, while no frontier pruning benefit is established. No corpus growth is needed for that mechanism proof; realistic retained larger checkpoints would be required before a practical startup/latency claim.

Posting working-set work ranks second because a bounded candidate collector and streaming path already exist. The new partition helper retains the full unique map and Vec capacity, so it does not solve O(U) candidate residency. A future fused scoring/top-candidate collector can remove the all-hit Vec/full minima map while preserving exact seen counts and cutoff ties, but it must reconcile the existing streaming version-read overhead and the100k prototype cap. It also cannot avoid essential per-current-copy distance calculations. Without new memory attribution or representative score arrays, another collector benchmark risks displacing the more fundamental global metadata architecture.

Query sharing and selection already compose at their existing interface. The adapter restores identical reader payloads before the selected-leaf policy runs, and the policy echo is a separate response field. A combined unchanged local run would not measure real network or real CPU-stage fractions, so it adds little evidence. Keep the measured byte and kernel gains separate, with the all-ties slowdown and unchanged scoring/storage costs explicit. No further implementation or runtime is activated by this recommendation.

## Prefer the smaller shared-object save milestone first

A shared experiment-owned object store can remove repeated selected-owner checkpoint copies with less routing refactoring. The actual writer commit already forks all five exact parent root IDs, and the root fork preserves unchanged sparse-index block references under a new root UUID. Dirty block commits and root flushes write new UUID-named object keys. The benchmark currently copies the entire selected-owner checkpoint so those old keys are available at the save destination, even though most are unchanged. The measured selected-owner copy is 89,807 bytes across 41 files for the representative append.

The remaining obstacle is output packaging, not the blockfile algorithm. The shared save routine renames existing execution-input/provenance files to retained names, then publishes a generation manifest and overwrites the mutable manifest.json convenience head. A POC-only shared layout can instead create generation-scoped execution inputs/proof, leave every old path unchanged, and write only the new immutable manifest-N.json. Generation maps already have distinct names. Readers can open pinned generation manifests in the same store; no second authority or service is required. The original fixture stays untouched, and all parent store objects can be verified byte-for-byte after the append. UUID conventions and this experiment do not establish a production immutability guarantee.

The proposed coherent experiment bootstraps one owned selected-owner store once, separately charging its full copy. Subsequent append preparation performs zero full checkpoint copying, reports every actually new root/block byte and sidecar byte, and checks exact global routes, selected leaf memberships, saved vectors/versions and old pinned-generation results against the current clone-based oracle. The first bootstrap is not free and must not be hidden as an end-to-end I/O saving. A repeat batch from the same store is the clearest amortization proof if the parent admits existing retained follow-on rows; no new corpus or failure/recovery campaign is needed. Whole-owner construction inputs/maps and full saved audits remain unchanged and separately charged.

This path is recommended ahead of lazy routing because it removes a known R-byte copy with existing persistence semantics and one narrow layout option. Lazy frontier routing remains the next global-memory barrier, but needs a new actual indexed metadata access path before a credible lazy claim. Neither byte-copy elimination nor the current CPU kernel establishes full proportional append cost. This appendix is feasibility analysis only; no implementation or run is authorized by it.

The save boundary must distinguish object storage from attempt artifacts. All five parent blockfiles are read and forked against the same owned store identity; a manifest copied elsewhere cannot resolve missing parent block keys by itself. Old id-map-N files, old generation manifests and all root/block keys remain at their exact paths. Generation-only save must skip every source-side execution-file rename, leave manifest.json untouched rather than replace/delete it through rename, create only fresh generation-scoped input/proof files and the new id-map-N/manifest-N, and retain no implicit latest-head authority. The ordinary pinned-generation reader uses those map/root references with the same store. Legacy complete sidecar/provenance validators are a separate contract and must not be claimed satisfied merely because the native reader reopens. A later source gate must inspect these exact writes before a shared-store runtime.
