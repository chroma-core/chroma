# Load routing nodes on demand before opening selected writers

The next substantial write-path barrier is opening every lower writer before selecting a destination. The current POC already avoids repeated global version scans, whole canonical copies and selected checkpoint copies. It still reads every owner’s complete node metadata and full-precision node centroids into mutable writer objects. That work grows with all nodes even if two new rows reach one owner.

The actual open path reads scalar singleton metadata, opens the vector/leaf/internal roots, fetches the complete persisted centroid range, then fetches every leaf and internal node. It copies centroids into both an intermediate map and node objects. The append controller performs that open for every owner. These are source-confirmed allocations and reads; their realistic latency and retained memory have not been measured on the retained real-data checkpoint because those checkpoint objects are unavailable locally.

Each new row also recomputes every owner’s level widths twice. The counted append function traverses the complete topology, then the global route repeats the traversal to validate supplied widths. Each traversal first recursively computes depth and then traverses nodes again. Routing itself scores all ownership-boundary aliases, sorts the current frontier and expands retained parents. Optimizing only the duplicate width check would leave the larger eager-open architecture intact.

A coherent next POC interface separates immutable routing from selected-owner mutation. One admitted parent supplies exact root identities, policy, per-level widths and boundary aliases. A read-only router fetches full-precision centroids and children only for reached nodes, keeps bounded operation-owned routing state and applies the identical global beam and total-order ties. It then opens full mutable writers only for selected owners and registers the exact preselected leaves without rerouting. The existing complete saved-owner oracle remains separate. Width summaries must come from an independently checked bootstrap, with its full scan charged separately; they cannot be inferred from counts or unverified caller fields.

The fixed-parent add-only contract makes this separation plausible. Registration changes leaf postings and length, versions and new embeddings; it does not change centroids, parent-child edges, node IDs or node counts, and it does not balance. Therefore a row’s route does not depend on earlier rows in the same no-balancing batch. This invariant needs an actual differential test before implementation is accepted. Splits, merges, reassignments and balancing require a fresh routing snapshot and remain outside this one append operation.

The smallest useful experiment uses the retained 96→98 pair, compares every route and final saved vector/leaf proof to the existing eager writer, and counts actual opened owners, fetched routing nodes, encoded returns and peak owned routing payload. It must include both the crossing destination and root tie. The mechanism claim is removal of eager all-node loads, not a real-data latency gain. Full selected-owner maps, construction input and semantic audit remain charged. A flat boundary still scores every owner root; this milestone does not resolve root fanout at 100 billion vectors. No implementation or runtime is authorized by this assessment alone.

Reference paths are the append controller (`poc_lazy_write.rs`), writer opening (`persistence.rs`), level counting (`diagnostics.rs`), global routing and registration (`distributed.rs`) and leaf insertion (`writer.rs`). Exact source hashes accompany this assessment.
