# Live version checks stop before each mutation

The owner adapter batches consecutive NPA version checks without retaining observations across reassignment. NPA means the existing neighbor-posting reassignment step: it checks whether a vector should move after a split. The measured 16K run shows many small current-version actor requests after scrub and immutable-predicate batching. The new policy targets those requests in FP self and neighbor NPA only. Split-input filtering, merge relocation, placement and reassignment's own current/versioned registration checks remain unchanged.

The coordinator acquires at most 64 unique per-ID conflict locks in sorted order, resolves authoritative owners, and asks each owner for its current values. It consumes rows in their original order with the existing missing-to-zero byte comparison, evaluated-ID set and immutable predicate results. It stops at the first reassignment action. The helper returns only after its guards and unused suffix observations drop. The coordinator then performs the existing global navigation and versioned mutation and starts a new authoritative read window for remaining rows. No observed version crosses that mutation boundary.

The ID locks are the existing locks that protect owner transfer from source removal through destination installation and directory update. Actor callbacks only read their own maps; they never wait on another actor, ID lock or coordinator callback. The new path is called after the split releases its structural lock and with no source node guard. Sorting and deduplicating lock IDs prevents opposite-order batch deadlock. The broader read window changes allowed concurrent interleavings, so tests require visibility and progress rather than an identical independently parallel tree.

The policy is off by default. The public joined-phase setter requires immutable predicate batching, actor reads and no live trace hook. Disabling its predicate prerequisite or enabling direct shared-memory reads is rejected while it is active. The original scalar NPA loops remain the fallback. This is still a local actor POC with a process-local lock directory and full immutable vector cache. Batching can cross an owner request boundary, but no physical remote locking, transport or distributed transaction implementation is claimed.

Four focused tests pass. A fixed decision tape includes stale, duplicate, deleted-byte and missing records. Its first action changes a later ID that is already in the prefetched suffix; resampling skips that old version exactly as the scalar oracle does. Ordered actions, evaluated IDs and owner code bytes match. Current-version actor calls fall from 131 to 5 on this fixed workload. Other tests check empty and over-cap requests, wrong-owner rejection, visibility across a paused authority transfer and opposite-order concurrent requests with bounded completion checks. Expected caught negative panics remain in stderr.

The generated 256-row integration check uses four owner actors and the reference parallel scheduler. It exercises splits, merges, placement, a full saved current-membership census, all saved vector bits and an unchanged pinned old reader. Its actual batch counts and length histograms are retained in MECHANISM-RESULT.json. More rows may be requested than consumed because an action discards its suffix; the extra version and predicate computation must be charged. This test is not a scalar-versus-parallel performance comparison or an ANN quality claim.

The counters record requested and consumed rows, action yields, owner request calls, owner-requested rows and two fixed 65-bin length histograms. The difference between requested and consumed rows measures discarded suffix work. A logical payload estimate could use 4 ID bytes requested and 2 presence/version bytes returned per owner-requested row, excluding positions and envelopes; this is not an encoded or physical network measurement. No all-ID cache or central mutable version mirror is added. The source archive preserves 941 files and the IDL symlink, and the staged index remains exact. The native entry passes a compile check only; it does not yet expose this policy as a runtime flag.
