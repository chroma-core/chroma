# Native prepared-split policy wiring

The existing construction diagnostic accepts prepared_leaf_split as an optional Boolean with default false. It validates the policy before creating output. Enabled preparation requires bounded vectors, the wide writer with full authoritative records, one owner, nonpaged vector metadata and local reassignment disabled. Setup enables the policy after the full-record path exists. Both before_save and after_save reports contain captured, installed_before_flush, discarded_before_detach and already_locked_fallback counts.

The reports also expose the existing split clustering and output quantization elapsed counters. These are cumulative spans, include discarded preparation, overlap concurrent workers and are nested in balance. Ordinary preparation contributes to structural hold; prepared work occurs outside it. The durations are not exclusive wall time or CPU fractions. No additional phase-line payload or per-row observation is introduced.

Multi-owner, destination-local reassignment, paged metadata, absent full records and reference treatment reject before creating output, with the prepared-policy admission error. The parent mutation is reachable during balancing because a different structural task can replace a source's parent before it publishes.
