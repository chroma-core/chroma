# Compare the parallel reference kernel with owner-authoritative construction

Both arms consume the same retained 8,192-row, 768-dimensional inner-product prefix with explicit full-precision navigation and neighbor predicates. Both use four workers and balance after rows 4,096 and 8,192. Branching factor four, split threshold 256 and merge threshold 64 deliberately create multiple internal regions within the fixed row budget. These settings diagnose construction coordination; they do not represent a quality-tuned index. The owner arm starts on one owner and moves existing leaves after each completed balance, using four owner slots and a 1,024-row placement threshold.

The controller requires at least two nonempty final scheduler assignments, actual overlapping subtree contexts, completed balance, ownership movement and at least two populated owners. It records depth, occupancy, split/merge work, actor work, structural critical-section wait and hold, full publication copy costs and all phase times. A missed shape condition fails the run without retry. Context overlap includes waits and does not prove simultaneous CPU work. The existing structural lock can have only one holder.

Each arm has a 30-second direct-child timeout, and both arms share a 60-second monotonic compute envelope bounded by the externally supplied absolute deadline. Input prefix hashing and the separately timed offline build are outside this compute envelope. The external operator supplies resource guards and an exact newly produced Linux binary descriptor. No script starts a machine or creates an authorization window. Retained immutable restore evidence binds the full source; this controller hashes the consumed 25,165,824-byte prefix instead of rereading the 6,144,000,000-byte corpus. Saved store payload is reported separately from the observed 50 MiB metadata limit. Child timeouts are not process-group or RSS enforcement.

Run the unchanged offline compiler recipe against the extracted 940-file source archive, then fill only the exact binary descriptor, fixed authorized deadline and fresh output path in the template. Invoke `python3 run-pair.py --spec FILLED_SPEC.json`. Use the existing target/cache and pinned Rust 1.92 toolchain; the compiler recipe enforces two build jobs, offline dependencies, optimization level three and the 20 GiB free-space floor. No global target-cpu setting is introduced.

Both saved censuses must contain every expected current ID exactly once with no unreachable nodes. The native entry verifies every saved vector bit, and the controller compares the full-ID exact distance bits across arms. Independent stochastic schedules may produce different topology and memberships. Phase timings are descriptive, not a causal speedup or ANN-quality comparison. Global shared embedding memory, actor messaging, owner-zero initial version admission, location maps, placement scans and full publication remain in scope as explicit costs. This is local actors and shared storage, not cross-host distributed execution.

The two local glue tests use the retained actual native report to exercise positive and negative shape gates and verify the fixed runtime template. They do not execute the real corpus. The accepted underlying source and native correctness checks are reused without repetition.
