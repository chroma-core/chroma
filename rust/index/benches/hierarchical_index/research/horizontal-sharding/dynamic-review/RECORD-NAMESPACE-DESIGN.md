# Connect record IDs to global vector IDs explicitly

The record store and vector tree use different IDs. A record offset identifies a user record within its saved record segment and is currently a u32. A global vector ID identifies one vector across the complete hierarchical index and is represented by the existing u64 owner maps. The next integration must preserve both values and join them through an explicit mapping; it must not subtract one or equate record count with user absence.

## Existing authorities and components

The saved record segment already stores user-to-offset, offset-to-user and offset-to-data mappings. Its exact file references belong to the collection registration snapshot. The hierarchical tree already stores lower-local-row-to-global-ID maps, with flat-map, paged and trie validation against the canonical global vector rows. A new bounded namespace descriptor connects these two existing representations. Its descriptor is stored in the same complete hierarchy bundle and collection registration as the saved record and vector roots. It has no independent pointer or publication function.

The bounded descriptor binds the collection and record segment identity, exact record file references, complete global ownership/canonical references, row count, parent namespace hash and a hashed table. Each table row contains a global u64 ID, actual u32 record offset and exact user ID. It stores no vector payload. The current 100k cap and full validation remain. The existing ownership-page codec cannot directly store arbitrary record offsets because it validates dense global coverage; reinterpreting its payload would violate that contract. The first implementation should therefore use a small flat sidecar with the existing artifact/hash/durability machinery, not introduce another tree or silently relax the ownership codec.

## Initial identity and validation

A parent namespace must already belong to the registered complete bundle, or be created at initial collection/index construction from an exact shared source identity assignment. An existing legacy vector snapshot plus matching vector values does not establish user identity: equal vectors can belong to different users. Such a legacy snapshot stays unsupported unless an independent complete source identity audit supplies the missing correspondence. A caller-provided label or a fabricated trusted receipt is insufficient.

The auditor opens the actual record reader from the exact bound segment references. It checks complete table coverage, unique global IDs, unique record offsets and unique users. For every row it verifies both user lookups and the actual record embedding bits against the canonical row identified by that global ID. It also checks complete global ownership against the existing flat-map oracle. Repeated admissions reread actual files; the current provider supplies no cross-call immutable-retention authority. The resulting internal validated object is created only by this audit and cannot be reconstructed from an external serialized trust flag.

## Append and publication

An opt-in adapter owns the exact retained record reader and calls the real materializer against it with a checked private allocator. It verifies a complete raw Add-only window and rejects existing or duplicate users, updates, deletes, folded rows and unsupported payloads. It retains the assigned record offsets. The coordinator assigns new global IDs through the explicit existing dense-global append policy, independently of record offsets, and records both IDs with user, vector bits, log window and exact parent namespace identity. The prototype still rejects unsupported holes or exhaustion; it does not claim that widening the external field removes the u32 record-store limit.

The selected-leaf writer consumes the new global IDs and preserves the actual chosen leaves through direct private writer commit. The ordinary record writer consumes the same materialized records and produces the candidate record segment. A candidate namespace extends the exact old global/user/record assignment prefix and adds only the admitted new rows. A full audit against the candidate record reader, canonical vectors and global owner maps must finish before the complete bundle becomes eligible. The candidate descriptor and every changed record/vector root enter the same existing collection version/log-position registration. A separate namespace CAS is forbidden.

## Smallest meaningful proof

Construct one tiny parent from a shared explicit identity assignment, with record insertion order permuted relative to global ID order. This defeats an accidental subtract-one implementation. Publish its namespace descriptor only as part of the captured complete parent bundle. Append two new users through the actual parent reader/materializer, ordinary record writer and selected-leaf writer. Independently verify all old and new mappings, current record bits, persisted selected leaves, exact source offsets and one complete candidate bundle. Keep the prior record/index roots and namespace pinned, with no second pointer.

Reject a missing namespace, wrong parent or record roots, duplicate/missing mapping rows, changed old user assignments even when vectors tie, conflicting record offsets, existing users and stale publication fences. A failed record/vector flush or partial sidecar write retains private output and blocks bundle eligibility. A fresh-parent retry is distinct from reusing a poisoned writer or consumed allocator. The first proof remains local and uses the existing test metadata authority; production compaction context/server wiring, the full worker dependency blocker and a representation suitable for 100B vectors remain separate work.
