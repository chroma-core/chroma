# Internal branch pruning counters

The query-stage trace now reports whether the existing beam cutoff removes internal branches or only leaves. The scoring, sorting, cutoff, leaf collection and downstream search remain unchanged. The existing stage-trace opt-in enables this diagnostic for both compressed and full-precision centroid traversal; there is no new native flag or remote package.

Each retained level reports actual internal parents expanded, offered internal and leaf candidates, and retained and discarded candidates of each kind. For either kind, offered = retained + discarded. On a complete ordinary tree traversal, the sums of offered candidates equal centroid evaluations, and the sums of expanded parents equal expanded_internal_nodes. The root counts as an expanded parent but is not an offered child. Retained internals form the next expansion level; retained leaves accumulate without a final leaf cap. Counts describe actual candidate entries, not globally unique nodes or physical machine requests.

The trace retains at most128 level records. Any further record sets complete=false; an absent node during classification also invalidates completeness. A consumer must reject incomplete traces for structural admission. Query decisions continue unchanged after overflow. This cap bounds retained trace records only; it does not bound tree residency, frontier memory, cache, RSS or total query work. The opt-in adds node-kind lookups and copying inside navigation timing; traced timing is not comparable to earlier untraced latency measurements.

The deterministic fixture has a root with two internal children. A beam of one discards one internal child, and the next level discards one of two leaf children. A separate leaf-only frontier rejects a leaf without reporting internal pruning. A wide beam rejects neither kind. The same shared traversal returns identical node IDs and distance bits with observation off and on for both default one-bit and FP scoring. The complete FP search also preserves exact returned IDs, distance bits and work totals. Another test verifies128 retained records and explicit incompleteness on record129. Both focused tests pass; the existing native entry compiles with cargo check. These ARM local tests prove counter mechanics, not beam32 pruning at8192 or16K rows, ANN quality, throughput or any remote behavior.

The native response exposes the optional trace through query_work.counts.navigation_level_trace when the existing stage tracing is active. The default value is None, serialized as null inside a requested work profile. No input, row, node, cache or stage-ID cap changes. The separately reviewed16K proposal remains pending human scale authorization. Its accepted policy addendum binds tau2.0 with per-level minimum and maximum32; the test beam one is deliberately different and makes no scale claim.
