# Compare centroid scoring on the same saved trees

This diagnostic asks whether one-bit centroid distances exclude useful leaves that full-precision distances retain. It changes only the centroid distance calculation during navigation. The same per-level beam policy, child traversal, sorting, tie handling, posting scorer, 200-candidate retention and 100-result exact reranking remain in place. A beam of 32 is not a final leaf cap; the report records actual selected leaves, expanded internal nodes, centroid distance evaluations, traversal levels and peak child frontier. The previous two retained runs each have exactly 32 selected leaves in all 64 beam-32 responses, and their oracle joins already use actual counts.

The FP arm loads persisted centroid rows from the opened snapshot’s vector root. It verifies root-reachable topology, parent links, complete node visibility, dimensions and finite values before queries. A private identity token binds the cache to that exact opened reader, so another reader or generation rejects it. There is no fallback to another root or reconstructed centroid. The cache holds at most 256 nodes and 1 MiB of FP payload, with dimension at most 768. These bounds fit the retained 104-node reference and 95-node owner trees. The payload estimate excludes map/container allocation, provider cache, decode buffers and process memory. Immutable admitted saved inputs remain an experimental assumption; this is not a storage integrity protocol.

Centroid preload is outside query timing and has its own elapsed span, point-get count, bit digest and vector-block observer report. Encoded storage returns are successful provider payload bytes, not physical I/O. Reader opening is separate. Preloading can warm the provider cache, so equal beam policies do not mean equal total work or identical cache state. The repeated response cache metadata describes one preload and must be charged once per reader. The reader’s existing memory estimate excludes this external cache; add the separately reported owned FP payload without calling their sum an allocation or RSS bound.

Two local Rust tests cover both metrics’ exact FP distance bits, known one-bit ranking reversals, shared traversal, generation identity, missing/wrong-dimension/nonfinite centroids and the dimension cap. Six native reader processes compare default, explicit one-bit and FP results on two saved 64-row fixtures with full coverage: IDs, FP32 bits and saved file hashes match. Three wiring methods cover the real native outputs plus GT joins, prescribed settings, four-cell success and first-child failure. Failed compile attempts are retained. These local ARM checks establish correctness and wiring, not the real-data quality hypothesis.

The proposed runtime uses the existing saved 8,192-row reference and combined-owner snapshots, original manifests/maps, frozen sixteen queries and exact prefix GT. It has four ten-second reader cells and forty seconds shared, with one warm-up and one retained pass. External GT joins use the existing stage-coverage implementation outside native query timing. Record query-level differences in selected-leaf GT, retained-candidate GT and returned GT; do not infer a quantization cause from prior losses alone. Trace timing is perturbed and not comparable to the earlier untraced latency sample. The cohort is reused and corpus/query disjointness is unproven. Saved global roots do not measure actor fanout or network traffic. No tree rebuild, larger corpus, beam sweep or cloud action is part of this local package.
