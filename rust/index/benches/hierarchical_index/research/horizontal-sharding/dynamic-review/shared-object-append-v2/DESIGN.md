# Reuse saved objects without copying the selected checkpoint again

The POC reuses unchanged saved index objects in one experiment-owned store. It uses the existing five-root UUID fork and direct selected-leaf commit, while giving each new generation its own execution files and immutable manifest. The original fixture remains immutable. This does not establish a production provider/GC/retention contract, latest-head authority, collection publication or recovery behavior.

The default checkpoint-clone save remains the baseline. Its five execution-file retention renames and manifest.json convenience-head update are unchanged. The new shared layout creates generation-N/construction-input.f32, generation-N/construction-input.u64le and generation-N/compactor-execution.json. It publishes the existing new id-map-N at the root and creates manifest-N.json directly with create_new/fsync. It never calls the existing head publisher, never renames the five old execution paths and never replaces manifest.json. Both layouts share exactly the existing commit/flush/reopen/full single-copy/vector-bit/selected-leaf proof code.

The explicit POC spec may provide a shared_stores owner/path map. Provided stores must exist at exact canonical absolute paths, be disjoint from immutable owner checkpoints and the attempt output, and match actual parent manifest hashes. Owner-b writer open reads all five parent blockfiles from that same owned store; commit forks those IDs there, and full saved reopen uses that same store. An unselected owner receives no clone or save. A selected owner without a provided shared store fails rather than silently copying. Counts, actual global routing/ties and exact selected leaf registration are unchanged. Shared inputs remain under the fixed immutable parent assumption; a manifest hash alone is not a full store proof.

Three Rust layout tests check every old execution/head path byte, the legacy retention layout and no-clobber generation manifests. Two Python accounting tests distinguish retained new UUID objects from sidecars and enforce old-key byte identity. Whole source review precedes those five tests and the bounded benchmark build. Use pinned Rust1.92/offline/locked/twojobs/debug0,20GiB free floor and1200s per command. Reconcile all source end hashes and retain the exact binary before native admission.

It copies owner b once into an owned shared store and charges all returned/copied bytes/files separately. The baseline appends into its normal selected-owner clone; the shared branch appends into the already bootstrapped store with zero per-append checkpoint copying. Both routes must equal the independently retained reference (cross-boundary winner and root tie), and both actual saved-owner audits verify all fifty global IDs, exact saved vector bits/current versions/zero duplicate copies and both selected leaf memberships. The complete vector view retains unchanged a and the shared generation2 b references; record/legacy publication is not rerun.
