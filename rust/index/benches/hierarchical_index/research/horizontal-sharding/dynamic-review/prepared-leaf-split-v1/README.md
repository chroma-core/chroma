# Prepared leaf split prototype

The optional split path keeps its source leaf visible while it fetches immutable vectors, clusters them, and computes posting codes outside the global structural mutex. It then re-enters the existing publication scope, validates the snapshot, and uses the shared detach/install/parent-update/NPA path. The policy is off by default and is exposed only through the joined wide-writer API; no diagnostic runtime or cloud package is changed.

Admission requires bounded vectors, full authoritative node records, one immutable owner slot, nonpaged vector metadata, no external mutation hook, and destination-local reassignment disabled. The reverse reassignment and paged-metadata setters reject incompatible combinations. Existing ordinary and multi-owner paths remain selected when the new option is absent. A recursively entered split that already holds the structural mutex uses the existing path and increments a fallback counter; dropping a nested guard cannot release an outer mutex.

The source snapshot contains physical row IDs, stored versions and codes in their original order, centroid bits, parent, record revision, posting owner and placement epoch. It also contains the current-validity selection and full immutable handles for selected rows. Final validation captures these again under the structural scope. A mismatch returns before detach and emits an explicit newer dirty-work event, including a version change that leaves physical source rows unchanged. The scheduler can then balance the source. There is no unbounded local preparation retry loop. Failed pre-detach admission changes no source payload; a post-detach unwind preserves the existing poisoned-writer and immutable-old-generation behavior.

## Modeled simultaneous allocation

Both complete split charges are acquired before cloning any physical source row. The first charge drops if the second admission fails. Both remain held through preparation, final comparison, publication or discard, and the existing subsequent NPA/recursive tail. The reservation uses the configured maximum row count, not just the observed leaf length. Topology dirty/pin/queue credits are separately admitted under the existing publication scope before detach.

Let n be the admitted maximum rows, d the vector dimension, C the existing one-bit code size, and P the clustering tuple size. One wide charge is R = n*(4*d + 256 + 2*C + 8 + P) + 64*d + 65536. This prototype reserves 2*R. The local 64-bit fixture reports handle=64B, legacy clustering tuple P=24B and leaf header=136B; C(32)=24B. A snapshot has n*(8B identity + 1B stored version + C code + 1B selection + 80B identity/owner/handle tuple) plus bounded headers/centroid. The final comparison can retain a second snapshot at the same time as the first snapshot, prepared wide tuples (32B per selected row), shared FP payload and output codes. Its selected per-row payload is therefore at most 4*d + 212 + 3*C, before vector capacity/headroom and clustering scratch. The two charges provide 8*d + 576 + 4*C per row plus center/header headroom; the existing modeled clustering scratch and wide ordinal allocation are retained within those charges. During detach the validation clone has dropped, while the original source payload can overlap the initial snapshot and prepared groups. No all-row identity guards or node leases survive into I/O or clustering.

This is modeled owned scratch admission, not an allocator/RSS bound. Provider caches/root indexes/encoded buffers, cache-retained vectors, thread stacks, allocation slack and other writer state remain separate. The algorithm's accepted scratch model is retained rather than newly proving a maximum for every clustering-library allocation. At100000rows/768D, C=112 and one current wide charge is358,514,688B. Two charges for32workers and5nested levels total114,724,700,160B (about106.84GiB), above the unchanged64GiB policy. Such a fully occupied hypothetical envelope rejects; no budget is increased or remote run admitted. Retaining charges through the NPA tail is deliberately conservative.

## Local evidence

Five focused tests pass. The authored tree has one internal root and two populated 32-row leaves, with a two-entry node cache. One fixed prepared clustering result supplies expected ordered IDs, versions and posting codes; shared publication produces those exact groups and codes, current saved FP bits and the unchanged64-row old generation. A paused preparation leaves its source navigable while another leaf receives a structural metadata update and flush; the original prepared split then succeeds. A real registration into the other leaf changes a source vector's current version without changing source physical rows; final validation rejects, emits work, and eventual balance reaches no pending work. A centroid-change case rejects in the same way. The second-reservation failure test returns the first charge and preserves the source without detach. The admission/failure test rejects incompatible local reassignment and multi-owner modes, exercises an initial64-row root split, and injects a post-detach panic to prove writer poisoning and old-generation readability.

The existing default-off connected full-record split/current/old-generation regression passes once. The native source CHECK passes in5.04seconds. The focused tests finish in0.09seconds after compilation. All first command/compile failures are retained: an unavailable benchmark target, then a module-path typo and a test node-guard lifetime error. No semantic test assertion fails. The new code has no Linux, optimized,100K, throughput, contention-speedup, or physical distribution result.

The installed_before_flush counter increments after installing the prepared output and before destructor flushing; it is deliberately not named successful publication. Captured/discarded counters measure attempts, including discarded stochastic clustering work. Current version/handle observations are repeated during validation, so the prototype can add callback and clone costs even while shortening lock scope. The fixed-decision witness establishes publication fidelity, not equal stochastic construction trees. The initial root test establishes attachment correctness but cannot create independent subtree work before its first split. Actual provider-I/O failure during structural flush, physical transfer to another owner, changed handle/placement epoch, row reorder and provider allocation peaks are not newly injected in this fixture; their comparisons or inherited failure paths are source-supported only.

The reference source subtree, runtime packages and staged index remain unchanged. New measurement selection still waits for the matched reference decision.
