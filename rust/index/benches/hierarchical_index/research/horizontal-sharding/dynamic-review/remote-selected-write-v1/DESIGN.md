# Append at the globally selected saved leaf across two agents

A single coordinator chooses one destination leaf across all published owners, and the chosen owner saves that exact leaf registration. The complete collection proposal contains the resulting record, vector and namespace roots together. No lower-tree rebuild or ordinary add operation runs between selection and persistence.

The existing agent supports complete builds and generation reads but has no private selected-leaf writer. The narrow addition is an opt-in Rust JSONL writer session launched by that agent against a fresh clone of one exact source replica. The source inventory, manifest and five block roots, old map, collection deployment/model/ownership fence, job/session/attempt and materialized two-row input are pinned before the writer opens. The session never exposes balancing. Every command identifies a declared new global ID; the worker reads its exact vector bits from the pinned candidate canonical input instead of accepting arbitrary routing vectors.

The coordinator requests actual root scores through committed upper aliases, then actual expansions for globally retained internal nodes. It sums every owner’s local level widths once. The existing Rust write-policy function receives the complete sorted global distances and widths and returns the beam count; counts agree across owners. The existing frontier coordinator accumulates leaves across mixed depths and uses stable owner/node ordering after the Rust f32 total order, including signed zero. It validates every returned row before pruning. A per-request ownership ledger assigns every new global ID once to one owner and assigns the next local ID in that owner’s full map.

Registration binds the selected owner, reached leaf, local ID, global ID, vector bits and route receipt to the same session and source epoch. The worker rejects an unscored leaf, an undeclared row, a changed command, a reused local/global ID or a stale authorization. It calls the existing selected-leaf registration directly. Finalization forks from the exact parent five roots, flushes all components, reopens the saved snapshot, verifies zero duplicate current postings, every canonical vector bit and the exact new live leaf memberships, and only then exposes a saved replica. The current local compactor’s direct-fork save routine supplies this behavior; extraction must preserve its defaults and failure semantics.

Each frame has a strict schema, monotonically increasing sequence, request identity and exact authorization. Requests are limited to 64 KiB, replies to 256 KiB and sessions to 256 commands for this fixture. The last exact request/reply may be retained for byte-identical replay without another mutation; conflicting or older replays fail the private session. The client never blindly retries a lost acknowledgement. Any registration, flush, framing or ambiguous task failure discards eligibility and requires a fresh source clone. Private files remain as evidence. The agent reserves session and replica names before launching the child, owns its deadline and normal close/wait, and never kills unrelated processes.

The first end-to-end fixture consumes the exact eighteen-row current bundle from the accepted two-agent topology proof. Its actual record reader and materializer assign offsets 19/20 to globals 18/19; their exported vector bits become the writer allowlist. The fixture selects across the ownership boundary, includes a deterministic tie case, and compares the distributed route with the same Rust global route on exact source mirrors without publishing the oracle. Both new IDs must appear exactly once in the saved selected leaves and complete global map. A stale capture and an intentionally aborted private registration produce no eligible bundle or authority advance. A fresh attempt then submits one complete record/vector/namespace proposal through the existing test collection authority.

The fixture keeps two loopback agents, two new rows and existing full audits and prototype caps. New source and native binaries require independent admission before execution. The record exporter must accept the actual captured current collection version rather than a fixed version-five fixture assertion; all current bundle, schema, row, log and namespace checks remain. This is a local transport and saved-index proof with injected identities and a fake authority. Full-worker compilation, physical fleet execution, production authentication and registration, the u32 record namespace and scale limits remain separate.
