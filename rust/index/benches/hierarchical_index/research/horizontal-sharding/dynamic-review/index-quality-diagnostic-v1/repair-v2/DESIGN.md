# Diagnose saved ground-truth memberships before comparing quality

This diagnostic inspects where supplied ground-truth neighbors live in an actual saved index. It computes exact leaf-count and current-row-cost oracles after proving complete, unique membership for that ground-truth set. It neither changes search nor measures latency. Ground truth means an upstream exact reference; this diagnostic binds its bytes and identities but does not recompute a real corpus reference or prove its corpus pairing.

The new command opens generation-pinned saved snapshots, validates their local-to-global maps and walks root-reachable saved postings. It resolves authoritative scalar versions in batches of 64 with 16 futures, rejects missing/out-of-range versions, excludes deleted/stale copies and rejects duplicate current ground-truth memberships. It never loads raw corpus embeddings, scores vectors or invokes navigation. Every expected ground-truth ID must appear exactly once after combining owners. Unreachable stored leaves cannot supply missing coverage. Missing or invalid coverage produces an error, not zero-valued excellent quality.

The row costs distinguish physical saved entries from live current copies. A leaf report includes its root path, ground-truth IDs, physical/live row counts and code-byte counts. Only ground-truth-bearing leaves retain reports; other leaves contribute aggregate counts. Current non-ground-truth copies count toward the work of scoring a selected leaf, even if they repeat. The output proves disjoint ownership of the requested ground-truth IDs only. It does not certify full-corpus map injectivity, complete non-ground-truth coverage or zero non-ground-truth replication. Existing full-ownership admission remains a prerequisite for a whole-index no-replication claim.

For complete disjoint ground-truth sets, descending ground-truth population gives the exact minimum number of leaves needed to cover ceil(0.90 K), ceil(0.95 K) and K neighbors. A separate 0/1 dynamic program over coverage counts computes the minimum sum of live rows for each target. It does not use count-optimal leaf order as a substitute for a weighted optimum. These are ground-truth-informed oracles; they are not executable routing strategies, physical block I/O minima, owner-latency minima or evidence of superior clustering. Overlapping current ground-truth replicas are rejected rather than fed into a disjoint solver.

The implementation bounds persistent membership state by at most 1,600 unique ground-truth IDs from at most 16 queries, each with at most 100 expected IDs. There are at most 128 owners and 1,600 ground-truth-bearing leaf reports in the successful combined output. Paths have at most 128 nodes. Maps stream through a 64 KiB buffer and retain only ground-truth local positions; no corpus-sized ID map or bitmap is built. One posting borrow and at most 64 owned scalar results are active during the saved scan. Topology traversal retains bounded node metadata (at most one million nodes), not corpus embeddings. Existing reader opening, root/block decoding, allocator overhead and provider caches remain outside an asserted preallocation/RSS bound; the cap is checked before retaining diagnostic state, not before the existing Arrow decoder allocates.

Cohort size is generic. The specification declares global_rows and max_map_rows; their relation and the sum of owner map counts are checked. There is no 10M corpus constant in the implementation. A future matched comparison can begin near 2M identical vectors, queries and reference IDs. Actual construction duration must be measured; this milestone assumes neither ten minutes nor any cloud launch. The separately recorded 10M root inventory is retained-evidence context, not a diagnostic run.

The local correctness fixture reuses the retained 98-row, 32-dimensional, two-owner saved index. Test-only code reads its hash-pinned canonical vectors to compute independent FP64 L2 references for three 20-neighbor queries and one complete 98-neighbor query. The diagnostic consumes hash-bound query/reference files and actual saved roots/maps. A separate serial saved-reader set oracle checks every membership and physical/live leaf cost; exhaustive subsets check exact row and leaf minima for the small query sets. The all-98 query checks full combined coverage and the exact complete-cover cost. Raw canonical reads belong to test reference creation, not the diagnostic's embedding-read count.

Semantic negative tests use private two-vector saved stores drawn from those same retained vector bytes. They check missing/duplicate/deleted/stale/out-of-range postings, missing and above-u8 scalar versions, a valid stale physical copy, capacity rejection and reader-map uniqueness. Retained saved-reader tests additionally remove a reachable edge only in a private in-memory reader to prove unreachable data cannot satisfy GT coverage. Map alias/hash mismatches and malformed integer schema reject before a backing store opens. No source store is written. Full retained-fixture inventories are compared before/after the admitted test run.

The immutable 917-file preparation-observer epoch remains archived unchanged. This epoch adds three files and changes two wiring files only. A formatter initially followed path modules into ten unrelated files; only those incidental formatter edits are restored from the verified 917-file archive, with a retained formatting-only patch and repair record. All other baseline files are hash-identical. The accepted hardware scorer, preparation observer, production paths, parent state and journals remain untouched.

The preparation 32-call experiment remains shelved. This package authorizes no real-data census, controller, cloud operation, download, query-strategy comparison or performance run. The whole source/test package requires independent review before local tests and benchmark check. Local results will distinguish actual tests from compile-only checks and retain all failures.

The numeric cost report includes every reachable leaf, capped at 4,096 leaves per owner and 16,384 across owners. Only ground-truth IDs are retained as memberships; paths are retained only for ground-truth-bearing leaves. The independent saved-fixture test lives with the CLI module so other ordinary reader test targets remain compatible.
