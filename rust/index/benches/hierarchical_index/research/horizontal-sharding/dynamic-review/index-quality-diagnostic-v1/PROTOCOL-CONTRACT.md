# Read-only saved-index diagnostic

The opt-in command is `diagnose-ground-truth --spec /absolute/spec.json`. Existing commands and defaults are unchanged. It returns one JSON report only after every requested ground-truth ID has complete unique current coverage. Errors return no eligible partial quality report. The command performs no search, registration, publication or raw corpus embedding lookup.

The version-1 specification contains source_id, dimension, metric, global_rows, max_map_rows, selected_queries, owners, ground_truth and query_vectors. Ground truth and query vectors are absolute artifact descriptors with exact bytes and lowercase SHA-256. Each selected query declares query_id and expected cardinality. Each owner declares owner_id, generation and an exact snapshot artifact. The snapshot must match source/dimension/metric/owner/generation, its actual saved root and dimension must agree, and it must carry an explicit generation-local ID map. Every consumed snapshot, map, query and reference byte is hash checked; there is no separate hash reread that can bind different consumed content.

The command streams all declared maps, verifies their lengths/hashes/counts/ranges, and retains only ground-truth local positions. The combined declared row count must equal global_rows and not exceed max_map_rows. Every requested global GT ID must map exactly once. This does not prove uniqueness for non-GT global IDs; the report states that scope. Missing/duplicate selected query or GT records, wrong expected cardinality, duplicate GT IDs, nonfinite values, dimension mismatch and unsorted reference distances/tie IDs reject before opening owner stores.

The report policy is saved-gt-quality-v1. It binds spec_sha256, source_id, dimension, metric, the consumed query/reference artifacts and each owner snapshot/map/five-root identity. Owner census reports include physical/live/stale/deleted rows and version reads, plus GT-bearing leaf paths, memberships and physical/live code/row costs. Query reports include expected/covered cardinality, GT owner/leaf counts, and exact minimum_leaves/minimum_live_rows for 90%, 95% and 100% coverage targets. raw_embedding_reads is zero by the diagnostic API path; query/reference parsing and test-only canonical reference creation are distinct costs.

Admission caps are 1 MiB specification and snapshot files, 128 owners, 16 queries, 100 GT IDs/query, 1,600 GT union entries, 16 MiB per query/reference JSONL artifact, 256 KiB per JSONL line, 64 KiB stream buffers, one million topology nodes, 262,144 physical rows/leaf and depth 128. Version reads use 64-position batches/16 futures. UTF-8 JSON numeric types are parsed into integer fields without bool/float coercion. Owner IDs and selected query IDs are at most 256 bytes. Existing storage decode allocation and provider cache residency are not pre-decode memory bounds. Input immutability is an explicit POC assumption, not a storage-provider guarantee.

The retained real-data prerequisites are listed in RETAINED-10M-PREREQUISITES.json: all 128 snapshots/maps exist as metadata, but the metadata archive contains zero root/block payloads. Its 640 exact root UUIDs need actual saved backing data before any later census. A future approximately-2M matched cohort uses its own declared size/source/reference identities and measured build duration. No real-data execution or preparation setup is part of this source/local-correctness package.
