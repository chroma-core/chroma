# Rebuild topology through two existing worker agents

A collection registration makes the complete saved index visible after two worker agents prepare and verify its inputs and outputs. Record identity remains unchanged. This is a loopback transport correctness fixture, not a new ingestion service, physical-host experiment or production authentication claim.

The initial placement copies each exact saved source checkpoint to its assigned agent through the existing bounded archive import. The controller checks the complete destination inventory, snapshot, map and actual reader before preparing one collection proposal. The proposal preserves the exact logical tree, namespace artifact, record files, log position, count and size; only physical replica references, collection version and deployment fence change. This path is distinct from the logical-label placement helper and never uses a local deployment publication pointer.

The topology execution object pins the current deployment hash and fence, each source worker/instance/run/replica tuple and complete inventory, and each destination assignment. It checks actual source metadata against that capture. It transfers every required source checkpoint to the destination agent before an affected rebuild, verifying bounded wire bytes and expanded regular-file contents through the existing archive functions. A source already present on the destination remains pinned by its exact captured inventory. The existing remote builder receives vectors extracted from the same fully validated canonical global-ID source and builds the affected lower trees. It returns complete mirrors so existing saved-tree validation stays active. Copies retained for this tiny proof are explicit; this does not introduce multiple authoritative owners for any stored vector.

The complete proposal contains the rebuilt vector roots, ownership maps and namespace root. The namespace retains the exact user/global/record-offset table, identity source, canonical vector artifact and record files. A fresh actual record audit and destination generation readiness check precede eligibility. Submission repeats destination and source checks, checks the collection session after transfer/build/audit, and issues one registration request. An ambiguous response stays unknown until an exact candidate observation; it never authorizes a blind retry.

Private replica reservations and transfer/build intents are durable before remote requests. Any failure retains partial private artifacts and prevents proposal eligibility. Cleanup closes only generations, readers and fixture agents owned by this attempt; it does not delete source checkpoints or operate on unrelated processes. Existing parent generations remain intact through failed preparation. No denied process-control operation is retried.

The smallest fixture uses the retained eighteen-row record/vector bundle and two loopback agents with injected fixture identities and private random tokens. It first publishes the verified-transfer placement through the same test collection authority. It splits one owner to leave three source owners, merges across the two agents, then reassigns an ID across agents while retaining one authoritative owner per global ID. It checks exact record identities and files at every stage, full source/destination inventories, actual remote saved-vector reads, stale publication rejection, one failed transfer with no eligible proposal/RPC, and owned reader/generation cleanup. Agent limits remain 128 rows, sixteen dimensions, one concurrent build per agent, 32 MiB wire archives, 64 MiB expanded archives, sixteen MiB per member and 512 members. Each RPC/build/read has its existing timeout. The fixture does not claim an instantaneous RSS or aggregate wall-clock bound.

Remote rebuilds receive canonical vector bytes through the existing bounded build request. Imported source checkpoints establish exact source provenance and readiness; the builder does not incrementally read or edit those imported blocks. The opt-in remote path requires previously committed per-centroid boundaries, while the default local path retains its existing conversion behavior. Readiness is single-use so a second call cannot overwrite owned generation handles. Unknown server-issued handles remain unreconciled and block acceptance; the first deterministic fault concerns corrupt bytes before import, not a timeout or forced process cleanup.
