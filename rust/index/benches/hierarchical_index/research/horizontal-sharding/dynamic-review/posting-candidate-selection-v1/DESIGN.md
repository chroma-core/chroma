# Select the cutoff before sorting retained candidates

The selected-leaf scorer currently sorts every unique approximate candidate before keeping the requested budget and every boundary tie. The new opt-in partitions around the same numeric cutoff, retains every distance at or below that value, then sorts only those retained rows. It preserves the actual quantized distance kernel, current-version filtering, strict-less minimum update for duplicate IDs, signed-zero tie group and all later global-ID mapping/order/exact refinement. Normal search keeps its existing exact-m truncation behavior. The default selected-leaf mode remains full-sort inclusive; a separate explicit partition policy and required adapter echo prevent silent fallback.

A shared collection helper contains the mechanically extracted scoring/minimum-map body. Ordinary score_leaves still applies its own m/truncate/sort sequence. The selected-leaf wrapper invokes the same collection helper, rejects nonfinite physical scores and then chooses the pure full-sort reference or partition helper. Selection validates positiveM and finite inputs before reordering. Numeric partial_cmp and <= group both signed zeros; equal-distance local-ID order is intentionally unspecified until the existing CLI maps all ties and applies total-distance/global-ID ordering. Every same-ID minimum keeps the original bits because equal values never replace the first copy. No posting/version/metric/routing policy changes or streaming-policy mixture is admitted.

Four pure Rust tests cover emptyU, invalidM, M1/M>=U, all ties, signed zeros, negative finite/extreme values, duplicate minima and every budget over deterministic permutations. A saved16-row reader test compares baseline/partition candidateID+distance bits across budgets and checks normal search still returns exactlym. The existing stale/deleted/duplicate posting integrity test is selected as a separate regression. Two Python adapter tests reject invalid policy/unsupported streaming mix before spawn and missing old-worker echo. These are meaningful correctness tests, not production failure work.

The actual shared selection helper is also imported by a standalone std-only Rust harness. Compile it using the pinned1.92 rustc with edition2021 and -O -Cdebuginfo=0, not an unoptimized development binary or a full release dependency rebuild. The harness generates deterministic finite arrays with seed0x7e57 at six quantiles of the retained1689-call U distribution and budget1000. It uses spread,32-group tie-heavy and all-ties shapes. Seven repeated pairs alternate AB/BA order. Input generation, vector cloning and output normalization/assertions are outside the timed kernel; clone time is recorded separately, and black_box observes both inputs/outputs. Every pair checks exact ID/distance-bit multisets. Profiles report actual sorted/retained rows, selection/sort time and complete kernel time. The arrays are synthetic because full pretrim real scores are unavailable. Per-size ratios are not a weighted query speedup or an attribution of the260ms posting-stage lower bound.

The native development binary serves a separate correctness proof. On the retained98-row,32D,two-owner fixture, three coordinators use the retained c8 reference binary, new full-sort profile and new partition profile. Four full query trace triplets include the committed alias crossing, root tie/repeat and M>=allownerrows. Actual selected candidates, all distances, globalID order, reached leaves, budgets and every route level must match. Retain all native requests/responses and stage diagnostics. No latency conclusion comes from these tiny unoptimized operations. The full minimum map, all-U Vec capacity, quantized scoring/versions and record/legacy costs remain. Worst-case cutoff ties can retainU, so no unconditionalM memory or time bound is claimed.
