# Explicit paired native construction

The command builds a global index through either the reference writer or actual local owner actors. Both arms require full-precision navigation and full-precision neighbor-posting predicates. They use the same logical balance cuts independently of storage chunking. Actors share one global saved store; this supports construction-quality assessment and does not implement cross-host execution.

Run `hierarchical_spann_shard construct-global --spec PATH`. The specification uses strict JSON with `format_version: 1` and rejects unknown fields. The output directory must not exist. The command writes `output_dir/store` and a create-new `output_dir/manifest.json`, then prints that same logical manifest to standard output. Input vectors are unmodified finite FP32 little-endian rows; supported metrics are `l2` and `ip`. Cosine normalization is outside this command.

The required top-level fields are `format_version`, `treatment` (`reference` or `authoritative`), `source_id`, `vectors` (`path`, `bytes`, `sha256`), `rows`, `dimension`, `metric`, `config`, `storage_chunk`, `balance_every`, `owner_slots`, `owner_vector_threshold`, `max_nodes`, `max_owner_physical_rows`, `max_leaf_rows`, and `output_dir`. Dense local IDs and global IDs are both exactly `0..rows`; no implicit permutation is applied. The manifest hashes the exact u64 little-endian identity-map bytes without allocating the full map.

The required configuration fields are `branching_factor`, `split_threshold`, `merge_threshold`, `write_beam_tau`, `write_beam_min`, `write_beam_max`, `write_rng_epsilon`, `write_rng_factor`, `reassign_neighbor_count`, `write_navigation` (must equal `fp`), and `fp_npa` (must equal `true`). Effective configuration also fixes one replica, empty per-level override arrays, and emits all those fields. The reference configuration-type defaults are branching 100, split 2048, merge 512, beam tau 1.5, beam minimum 10, beam maximum 16, RNG epsilon 0, RNG factor 1, and 32 reassignment neighbors. The command does not use the separate profile command's implicit quantized predicate default.

The first row creates the ordinary one-owner reference root. The authoritative treatment persists that root and admits its live state to owner zero; additional actors start empty. `storage_chunk` is between 1 and 8192. Registration stops at each common `balance_every` boundary, balances once, and also balances the final partial interval. The 100,000-row balance schedule therefore remains identical when storage chunks change. Capacity placement runs at chunk boundaries and transfers existing leaf branches; an indivisible branch or a full actor pool can limit placement. Placement timing is explicit and does not alter the required logical balance cuts.

The manifest contains the consumed specification SHA, input identity, complete effective configuration, dense identity-map SHA, five saved UUIDs, root descriptor, branch-to-owner directory, strict complete saved posting/current-membership census, per-cut timings and pending reference leaves, authoritative event counters (including balance-round-limit hits), and separate construction/save/audit durations. Reference balance cuts report `round_limit_hit` whenever pending work remains after the reference's 100-round stop. A successful full census requires every dense ID exactly once at its current version. It does not claim that balance converges when the reference stops at its round limit.

The two arms use independent ordinary stochastic split decisions, not a test tape or an identical tree claim. A matched assessment must record both input/spec hashes and compare quality using common corpus/query/ground-truth and work settings. No 2M-row resource or duration claim follows from the local entry-point test. Errors leave a private incomplete output; no resume/recovery interface is provided.

The saved store also receives a create-new reader-compatible `store/manifest.json` with generation 1 and an explicit construction wrapper `{version:2, protocol:"explicit-fp-global-v1", config:...}`. Existing `read --checkpoint-dir output_dir/store` opens it directly. Its ID offset is zero, stride is one, and no external ID mapping is required. Legacy construction-version-1 reader validation is unchanged; version 2 dispatches through the new strict configuration parser. There is no latest-generation publication or resume operation.
