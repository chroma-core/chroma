# Separate algorithmic work from local owner-message cost

The next diagnostic asks why owner-authoritative construction takes substantially longer than the ordinary reference on one host. It compares the reference, the same adapter with one owner and no capacity movement, and the same adapter with four owners and joined-boundary placement. Four construction threads remain enabled in every arm. The accepted predicate-batching package remains unexecuted, and predicates stay individually dispatched in this diagnostic. This separates adding an owner execution boundary from adding multiple owner actors; it measures no network latency.

All three arms use the identical retained first 8,192 vectors, 768-dimensional inner-product metric, explicit full-precision navigation and neighbor predicates, balance cuts at 4,096/8,192 rows, branching four, split threshold 256 and merge threshold 64. The one-owner arm skips the placement call entirely and must report zero moves and one current-data owner. Both adapter arms must reach multiple independent scheduler regions and finish balance. The four-owner arm additionally requires actual moves and multiple populated owners. All arms retain full saved current-membership census, vector-bit and exact full-ID distance checks. Saved-code correctness remains covered by the existing local construction test. Independent stochastic schedules may yield different shapes and work; no causal ratio follows merely from matching configuration.

The first measurement layer reports comparable semantic work. Both the reference and adapter expose the same existing writer-statistic deltas around each add and balance call: navigation calls, registrations, splits, merges, balance calls/rounds, self and neighbor evaluations, visited/active neighbors, reassignments and missing-node retries. A narrowly added common current-version lookup counter covers actual lookup entries in both arms, rather than treating the adapter's current-entry count as a reference count. Before/after snapshots occur only at joined boundaries. The reference shape must be recorded with depth, occupancy and live/physical rows, not inferred from adapter shape. These counters identify work differences; they do not force identical trees or alter scheduling.

The second layer measures aggregate local message timing. The existing actor call records enqueue time, service-start time, service-end time and caller-return time. Bounded counters retain count, total and maximum queue delay, callback service elapsed and caller round-trip elapsed, plus the peak queued request count. No per-request timeline or unbounded key map is retained. Existing current lookup, predicate, registration and snapshot counters identify operation frequency. Queue delay includes local scheduling and contention; callback service includes descheduling and any nested waits. Caller round trips include queue, callback and return-channel scheduling. These sums overlap across construction workers and cannot be divided into wall-time fractions or added to existing structural/NPA spans. The actor callback still drops its observation before replying. Errors and actor lifecycle behavior remain unchanged.

The third layer records process resources without a new profiler. The sequential controller takes process-child resource snapshots before and after each direct native child and reports user/system CPU seconds and voluntary/involuntary context-switch deltas alongside monotonic wall time. These are whole-arm CPU and scheduling evidence, including setup/save/audit; they are not balance-only CPU or a direct measurement of blocked seconds. Existing phase wall times and structural lock wait/hold remain separate. The controller launches no other children inside each measured interval. The Linux build remains outside the diagnostic compute budget.

A proportionate local fixed-work check compares enabled and disabled aggregate message timing on the same bounded no-op callback sequence. It verifies identical callback count and results and reports observer overhead descriptively. It is not a latency benchmark for real construction. Meaningful local native wiring tests exercise all three arm schemas, one-owner no-placement behavior, common statistic reporting and exact saved results on the retained synthetic fixture. Existing structural correctness suites need no repetition unless shared behavior changes.

The proposed runtime budget is 30 seconds per arm and 90 seconds total, bounded by a separately authorized absolute deadline. This is a proposed three-arm budget, not an extension of the existing two-arm 60-second authorization. Metadata remains observed and capped at 50 MiB; saved stores are separately charged. No retry, size increase, transfer, cloud action or launch is authorized by this design. The parent and sole pilot retain resource, lifecycle and runtime decisions.

If semantic counts are comparable while one owner already shows substantial caller/queue time and low callback service work, local round trips are the next concrete target. If extra splits/evaluations/reassignments dominate, inspect their semantic cause before interpreting elapsed differences. If process CPU is high and callback service accounts for substantial elapsed, examine computation and repeated scans. If the four-owner arm differs mainly in movement/full scans, placement is distinct from balance. Each conclusion must retain workload and timing-overlap qualifications; the diagnostic need not produce a single additive cost partition.

The minimal owned integration would touch the owner adapter's actor timing, the shared writer statistics/current-version entry point, the isolated native diagnostic and its paired controller. It would preserve the reference scheduler, eligibility predicates, immediate versioned registration, storage behavior, staged index and accepted immutable epochs. No grouping, cache or construction optimization belongs in this measurement change.
