# Configuration defaults and benchmark command defaults

The admitted construction path supports the reference configuration type’s defaults, including full-precision neighbor-posting analysis. The benchmark command selects quantized neighbor-posting analysis unless its full-precision option is supplied. These are distinct defaults. The current owner-authoritative API rejects quantized neighbor-posting analysis, so the completed local package does not establish readiness for the benchmark command’s default matched treatment.

Quantized support requires preserving each original posting code and its ID-to-code position through leaf replacement. Owner-local self predicates must use those original codes and the exact reference query correction arithmetic. Neighbor predicates must use the existing quantized eligibility rules, followed by immediate owner-versioned registration. This remains an explicit integration boundary, not a configuration toggle.

The current evidence establishes structural semantics and saved-state parity for the full-precision predicate mode. It does not establish a two-million-row build, quantized-predicate parity, Linux execution, cross-host execution, or quality equivalence.
