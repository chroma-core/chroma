# A bounded owner-authoritative construction path

The construction path grows and merges one global tree while its owner actors hold the actual mutable postings and current versions. Placement moves existing leaves between actors without changing the logical tree. The coordinator navigates, clusters affected split input, allocates stable node IDs, and sequences structural edits; it does not keep a second full posting, code, current-version, or corpus-embedding authority.

This package advances the local POC toward a matched treatment. It is not a two-million-vector build, quality, latency, memory-capacity, remote-storage, or distributed-durability result. The matched runner and its build-output provenance remain outside this source ownership.

## Complete source cut

The existing files changed from the accepted 930-pin evolving-authority epoch are `authoritative_owner.rs`, `authoritative_split.rs`, and `authoritative_split_tests.rs` in `rust/index/benches/hierarchical_index/writer`, plus `live_owner_tests.rs` and `writer.rs` in that directory. Three new files define direct construction, general structure edits, and their tests: `authoritative_dynamic.rs`, `authoritative_structure.rs`, and `authoritative_dynamic_tests.rs`. The existing test file changes only helper visibility. The reference writer changes only two test-only hooks: recording outer balance round order and recording internal split decisions through the existing splitter wrapper. Without tests, its split implementation and construction behavior remain unchanged.

The accepted small-tree prepared interface remains available and retains its rollback-copy contract. The new direct interface does not call whole-owner preparation or clone the coordinator routing/location/placement tables before every addition. An incomplete direct operation poisons its instance and forbids saving it; no rollback, retry, or production recovery protocol is implemented. Unsupported configuration is rejected before mutation. Storage, capacity, invariant, or actor failures during a supported operation can leave incomplete working state, which is unusable for publication.

## Supported semantics

The new path accepts the actual reference full-precision defaults: branching factor 100, split threshold 2,048, merge threshold 512, one replica, full-precision navigation and neighbor-posting analysis, and the default uniform write beam. It supports multiple tree levels, internal overflow splitting, leaf and internal parent replacement, root growth, removal of empty parent chains, root contraction, and both reference merge registration choices. Every live leaf can reside on any available owner, and an owner can hold several leaves.

A leaf split preserves current versions and vector references while assigning two new node IDs. The source owner supplies only the affected leaf's live rows and vectors. The coordinator uses the same splitter and child-centroid rules as the reference. When an internal node overflows, the coordinator clusters its child centroids, replaces that internal node, and sends actual parent updates to affected leaf owners. It preserves child ordering, centroid arithmetic, centroid-code bytes, root and next-node counters, and the reference balance depth limit.

A merge removes its source from navigation before finding the global target, as the reference does. Navigation skips the missing child rather than using a stale alias. The source actor detaches the physical posting but retains authoritative current records while rows are handed off. If a row is no farther from the selected target than its old source, the destination owner registers the same version. Otherwise, global navigation chooses a destination and the owners perform a version-incrementing handoff. Registration and recursive balance are immediate, so subsequent predicates and scans see the updated authority. The reference's 100-round outer-balance stop remains in force; a round-limit event reports any pending leaves, rather than claiming convergence.

Quantized write navigation or neighbor analysis, replication, nonuniform per-level write overrides, user deletion/update, concurrent construction, and concurrent orphan adoption are outside the new construction interface. The existing fixed-topology replacement API is not the matched construction interface. No central mutation fallback handles unsupported operations.

## Inputs, balance cuts, and placement

Saved vectors enter once per bounded storage batch. A vector batch creates one immutable vector-data fork, and its rows carry that root/key reference into owner-local state. The caller can register several storage chunks without balancing and then request one balance cut. This allows a driver to preserve a larger reference construction batch without materializing that entire batch in the new interface or forcing an extra balance after every storage chunk. The convenience API also supports balancing after each row or at a storage batch's end; a matched driver must choose identical balance cuts for both treatments.

Automatic placement uses actual owner live counts and a caller-selected threshold. It moves existing leaves and their owned posting/current/reference payload through source-to-destination actor messages. It reads live IDs from the selected posting and updates only those coordinator directory entries; it does not sweep the full ID directory or the source current map for every transfer. Selecting a transfer still scans the overloaded owner's branch rows, and owner loads are queried through their actor boundary. These costs remain explicit.

The available actor pool is bounded and pre-created, with only the first owner initially holding data. This is not elastic fleet provisioning. An indivisible leaf or exhausted destination headroom can prevent the soft placement threshold from being met; the path records that condition and does not split solely to satisfy placement or change the reference tree. Hard physical-row limits remain separate from the placement threshold.

## Persistence and ownership

Owners write their actual postings, current versions, and leaf records into private forked writers. The coordinator writes structural metadata and centroids and removes retired node keys. A save returns complete root references after owner acknowledgements and all flushes. The saved format remains one global snapshot; per-owner durable checkpoint partitioning, placement persistence across process restarts, remote vector loading, and machine-level authoritative state are not implemented. Reopening currently starts with saved data at owner zero; placement can then move actual leaves.

The storage provider and cache are shared local components. Actors own mutation state and run on separate local execution threads, but this does not establish physical data distribution, network cost, process isolation, or remote durability. No new publication head, service, runner, or controller is introduced.

## Meaningful local evidence

The main sequence contains 225 constructed 32-dimensional vectors derived from the retained fixture and explicitly constructed near/far groups. It starts from an ordinary one-vector saved root, builds through 192 rows using smaller structural thresholds to exercise deep growth, and transfers actual leaves as owners cross a live-vector threshold. It then applies the unmodified default structural configuration to the same live tree, merges its undersized branches, contracts the root as the reference permits, and continues adding to 225 rows under those defaults.

Reference and treatment receive identical batches and balance cuts. Tests record the reference's random split decisions and outer balance order and replay those choices in the treatment. They compare the hooked semantic boundaries and complete in-memory topology, IDs, centroids, codes, root and next-node counters. They do not claim independent random builds are identical or that every unhooked self-predicate event is separately traced. Ordinary non-recorded splitting is also exercised, so the runtime path does not require a test tape.

Saved checkpoints compare all posting IDs in physical order, versions, codes, raw vector bits, scalar versions, persisted centroid bits, and complete root-reachable live membership against the reference. A pinned 192-row reader and every old object hash remain unchanged after default merges and subsequent additions. The final physical-row counter sum matches the saved census, and owner preparation-copy counters remain zero on the direct path. Offline event replay classifies actual cross-owner eligibility, version-incrementing handoffs, and later version visibility in the final epoch. An earlier retained V3 trajectory also exercises a cross-owner same-version merge transfer; `CROSS-EPOCH-SEMANTIC-BINDING.json` verifies that its merge and accept/reroute implementations are byte-identical to the final epoch. This is explicitly cross-epoch coverage, not a claim that every transfer class occurs in the final trajectory.

The initial storage batch is split into two writes before one reference balance cut, proving that storage chunking does not silently change construction scheduling. An additional test opens the actual default configuration and default two-million-row admission limits, rejects malformed IDs, nonfinite vectors, zero thresholds and capacity exhaustion before input mutation, and executes a trace-off ordinary split without recorded reference decisions. This is API and correctness evidence, not evidence that a two-million-row build fits a machine or finishes in a particular time.

The accepted prepared-path tests also pass after the common owner and structural refactor. Their private-discard and old-reader guarantees remain separate from the direct path's poison-on-incomplete-operation contract.

## Costs and next prerequisites

This slice removes two material per-add costs: copying every owner's state and the coordinator's whole directory/routing state, and creating an immutable vector root for every individual addition. Owner physical-row admission now uses a maintained count rather than summing every leaf on each registration. Placement updates only the moved branch's directory entries. These are mechanism changes, not measured throughput or physical-write savings.

Global routing metadata and the ID-location directory remain resident centrally. Owner bootstrap and saves still enumerate complete owner state. Outer balancing scans leaf metadata through actor requests, and transfer selection scans an overloaded owner's branches. Split clustering can materialize all vectors in the affected leaf, while the provider may cache more. Trace-off mode bounds retained event storage but still constructs some temporary event values. Raw counters describe logical payload and requests, not provider cache retention, encoded storage traffic, network traffic, RSS, or CPU fractions.

A useful matched run still needs a runner adapter for these APIs, identical corpus/query/ground-truth and metric, identical batch and balance cuts, explicit random-build provenance, per-owner and provider budgets, and measured build duration. The saved snapshot and query integration also need to be connected to the chosen evaluation path. The capacity estimates in `CAPACITY.md` identify concrete limits and exclusions; they are assumptions and arithmetic, not an admission for a real-data run. No cloud operation or matched experiment is authorized by this package.
