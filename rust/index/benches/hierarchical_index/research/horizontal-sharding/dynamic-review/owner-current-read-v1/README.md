# Read the owner's authoritative version map without a local message

The three-arm run identifies current-version messaging as consequential coordination work. The ordinary reference already performs 1,385,752 balance lookups; the one-owner adapter performs 1,516,613 and the four-owner adapter performs 1,019,439. Most adapter lookups enter through scrubbing rather than the kernel's point-lookup wrapper. The one-owner current-message bucket records about 0.401 seconds of callback service but 22.600 seconds of summed caller elapsed, while whole-child system CPU is 12.723 seconds and voluntary context switches approach three million. Different stochastic work and overlapping elapsed prevent exact attribution of the total gap. These observations justify removing per-read local dispatch, not claiming a network or whole-build speedup.

This opt-in path reads the same owner-authoritative map through a process-local synchronized handle. Each owner actor and its read handle share one allocation containing that owner's version map behind a read/write lock. Every existing version mutation still executes on the owner actor. The backend retains only handles and the existing owner directory; it creates no version mirror, cache or prefetched snapshot. The map stores the same records as before, with only a lock and shared handle added per owner.

A read first takes the existing per-ID conflict lock, resolves the current owner and reads that owner's original map under a short read guard. Version bump and cross-owner registration already hold the same per-ID lock while sending the owner mutations. Therefore a reader cannot observe the temporary source-removal/destination-install gap or an old directory entry during that move. Placement remains at joined phase boundaries. Actor callbacks acquire only their version-map guard; they never acquire the per-ID lock or synchronously wait for another actor. Read guards end before the conflict lock drops and never span an actor call. All mutable posting ownership, scheduling, eligibility and immediate reassignment rules stay unchanged.

The default policy keeps the message path. The wrapper permits changing policy only at a joined boundary. The report echoes `direct_current_policy` and counts `direct_current_reads`, separately from total lookup requests. A lookup without an owner returns the same missing result without a callback. Tombstones and wrong-owner behavior are unchanged. The current native CLI does not enable this path; this is a completed local source/correctness milestone, not a runtime package or permission to launch.

The fixed-decision test compares both policies on the same authoritative setup. Each performs 256 identical reads, then version bump, cross-owner registration, source removal and destination reads, tombstone checks and wrong-owner rejection. Ordered saved posting IDs, versions and code bytes agree. The message policy executes 256 callbacks for those reads; the direct policy executes zero. The test confirms the read handle and actor state point to the same allocation. This is exact callback-work elimination, not a measured timing gain.

The concurrency test pauses an actual registration after source removal and before destination install. It verifies the directory still names the source and neither map contains the version. A reader enters the real lookup while the mutation holds the conflict lock and cannot return during that gap. Resuming registration installs the version and directory; the reader then returns the new version. Both policies run this test. The pause hook exists only for tests and is inactive otherwise. This demonstrates immediate visibility and transfer synchronization without a recovery protocol.

The multi-region construction enables direct reads and keeps predicate batching disabled. It passes full saved current-membership census, per-vector bits, independently recomputed posting codes, exact full-ID distance parity against an independently scheduled reference, placement and pinned old-reader checks. Its observed tree has depth four, 48 nodes, 48 splits and 25 merges; 42,869 resolved version reads use the direct handle. Seven focused tests and a benchmark-target compile check pass. Expected caught wrong-owner panics remain in passing negative-test stderr. No earlier accepted source archive or staged index changes.

This is a local shared-memory POC improvement. A cross-process or cross-host owner cannot expose this pointer; it would need owner-local batched validation or a separately synchronized transport contract. No remote authoritative-read, network, ANN-quality, large-scale capacity or Linux timing claim follows from these tests. Per-ID locks, per-owner map locks, predicate messages, version mutations, registration, full-vector residency, placement scans and full saved publication remain costs. No new cloud run, larger fixture or repeated performance benchmark occurs here.
