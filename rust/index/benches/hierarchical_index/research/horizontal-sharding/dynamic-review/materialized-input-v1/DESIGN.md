# Materialized compaction input

The optional adapter checks the actual raw log window against the actual record materializer output before creating a writer task. It accepts a complete, visible, contiguous window of distinct new Add operations with finite float32 embeddings, no metadata and no documents. It rejects folded updates, deletes, upserts, backfills and duplicate users even if the final materialized operation is AddNew.

Each output row uses the materializer's actual u32 record offset as its global ID. The adapter joins by user ID, compares every vector bit including negative zero, and keeps the corresponding source log offset. It preserves the collection identity, version and log fence, plus the exact parent deployment hash and ownership generation. It does not infer IDs from collection row count. The expected dense new-ID range is an internal binding from the previously validated ownership parent; this function does not prove that parent or turn a caller label into authority.

The current 100k prototype accepts only an actual offset namespace compatible with its dense global IDs. Existing one-based or sparse production namespaces must fail rather than be silently remapped. The function calls no writer and does not publish. Materialization can already have advanced a private ID allocator before rejection; the rejected attempt must be discarded and reconstructed from its authoritative parent, not rolled back or reused.

The focused test target calls the existing materialize_logs function with real Chunk, LogRecord, OperationRecord, MaterializeLogsResult and private AtomicU32 allocator types. Three proposed methods cover out-of-order user names and exact IDs, unsupported raw rows and folding, and signed-zero/namespace/visibility/overflow failures. These tests remain unexecuted until source admission. The target adds only a direct existing segment dev dependency; the worker's feature-enabled build remains separately blocked. No actual CompactionContext, lower writer, service transport or registration activation is claimed by this component.
