# Test the cost of same-process current-version dispatch

This two-arm diagnostic asks whether eliminating per-read local actor messages materially changes construction cost. Both arms use one owner, four construction threads, no placement call, individually dispatched predicates and the same retained first 8,192 vectors. The first arm uses current-version messages; the second reads the same authoritative owner map through its synchronized process-local handle. The underlying map representation and all construction algorithms are identical in both arms. This is a same-process ablation, not a proposed distributed 100B read architecture.

The native JSON field `direct_current_reads` is a boolean that defaults to false. True requires the owner treatment. The consumed specification and owner report echo the policy. Both arms explicitly set `predicate_batching:false`, `construction_observation:true`, `skip_placement:true` and `owner_slots:1`. They retain the common semantic work snapshots, fixed-operation message queue/service/caller counters, process user/system CPU and context-switch evidence. The direct arm must show positive synchronized reads and zero current-message callbacks; the message arm must show the reverse. Missing IDs still return the same missing result without a callback. The existing per-ID transfer lock remains held across every resolved read.

Both arms use 768-dimensional inner-product distance, explicit full-precision navigation and neighbor predicates, branching four, split threshold 256, merge threshold 64, and balance cuts at 4,096/8,192 rows. Each independently requires multiple assigned scheduler regions, overlapping subtree contexts, completed balance, one populated owner and zero placement moves. Complete saved current-membership census, every saved vector bit and full-ID exact distance parity remain required. Posting-code correctness remains covered by the accepted local construction test rather than a new native code oracle. These thresholds exercise construction and do not represent ANN-quality tuning.

Each arm has at most 30 seconds, and both share 60 seconds under a separately authorized absolute deadline. No retry or size increase follows a failed gate. Input prefix hashing and the offline build are outside that compute envelope. Saved stores remain separately accounted from the observed 50 MiB metadata cap. The external operator owns resource guards, lifecycle, exact Linux binary binding and shutdown. The script does not create or extend a window. Child timeout is not a process-group or RSS guarantee.

Independent parallel schedules can produce different evaluation, scrub, split and reassignment work. Report those counts alongside phase times; do not treat an elapsed ratio as a fixed-work causal gain. Whole-child CPU includes setup/save/audit, not only balance. Queue, service, round-trip and lock sums overlap across threads. Dispatch-to-service timing includes reply-channel/job preparation, not just queue wait. This single host measures no network latency. The physical-distribution follow-on remains a plan in `PHYSICAL-OWNER-FOLLOW-ON.md`.
