# Send a shared query once per adapter batch

The opt-in batch format removes repeated query vectors from HTTP request bodies while preserving the existing search operations. Default HttpBackend calls retain the exact legacy JSON encoding and wire shape. An explicit share_query boolean enables shared-vector-v1; the adapter separately enables shared_query_batches and returns a required format echo. Old adapters that ignore new fields cannot silently satisfy that echo. No cross-query cache, numeric conversion, normalization, candidate change or query-service redesign is introduced.

The client copies its complete operation phase and validates all query values before starting HTTP tasks. Query arrays must have identical JSON numeric values/types, including negative zero; booleans and nonfinite values reject. Each owner batch then carries one shared_query array and omits inline arrays. The receiver rejects unknown schema/version, inline/shared ambiguity, absent or malformed shared query, unknown/duplicate subtree, wrong snapshot, unsupported operation and any actual pinned dimension mismatch before starting any child call. It creates separate owned query lists for the per-reader operations. Tree identity and deadline checks remain, as do all original subtree, snapshot, generation, operation, node, local-ID, budget and ordering fields. The Rust boundary still receives one query per reader; HTTP byte reduction does not imply reduced Python serialization CPU or Rust distance work.

Five Python contract methods exercise the actual encoder, adapter decoder and client response check. They cover exact legacy bytes, roundtrip operation/negative-zero preservation, mixed numeric values/types and cross-owner phase rejection before network, every ambiguous/malformed server case before any child call, disabled adapter behavior, per-batch ownership/no cache, and missing/wrong echo rejection. The complete change is reviewed before these tests; native execution remains separately gated.
