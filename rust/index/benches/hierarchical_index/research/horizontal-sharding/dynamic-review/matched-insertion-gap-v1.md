# The insertion gap mixes durability work with smaller posting batches

The reference's displayed49milliseconds and the dynamic writer's4.273seconds do not time the same work. The reference timer starts after all100Kvectors are decoded into resident shared arrays; its durable vector publication occurs later at commit. The dynamic add timer includes reading and hashing the input again,13durable staging commits, bounded worker windows, and immediate owner/version/handle registration. This is still a material construction difference, but the two numbers are not a matched insertion speed ratio.

## Timed boundaries and measured work

The reference loads the checkpoint's100Kvectors before starting index_start. Its retained loader reads307200000bytes, decodes finite FP32 values, builds Arc arrays and checks the consumed input hash. The displayed load is488milliseconds. Before that, RetainedF32::open performs another complete validation/hash scan without a separately reported stage timer. The index timer encloses buffered insertion and balancing, then subtracts the enclosing balance duration. It reports38milliseconds of worker collection,11milliseconds of regroup/flush and49milliseconds total insertion. Commit/fork/flush/reopen, root-reachable membership validation and saved-bit verification are outside those insertion numbers. The external native receipt is16.696seconds and includes these additional tasks. Source: frozen reference `hierarchical_spann_profile_quantized.rs:1247–1324,1454–1495,1559`; retained loader `datasets/retained_f32.rs:12–34`.

The dynamic harness first validates the entire input prefix in64-row chunks, reports0.594129seconds as input_seconds, rewinds, then starts each logical insertion timer before its streaming read loop. At100Kcadence that timer covers13reads of up to8192rows, FP validation/decoding, a second consumed-prefix hash, conversion to wide IDs, and13calls to add_phase. Its add_seconds is4.273200seconds; copy_seconds_nested_add is0.495537seconds and includes this second read/decode/hash/conversion. These are nested timings, not two additional wall buckets. Source: active `sharding/reference_owner_diagnostic.rs:79–85,145–149`. The retained epoch13long spec and result bind the actual8192staging grain,64-row stable windows,32workers and one owner.

Inside add_phase, each staging chunk completes a blockfile fork/write/commit/flush and builds immutable full handles before routing or registering its rows. The13stage calls report2.296844seconds of cumulative staging elapsed for307200000logical FP bytes. Their source order is synchronous stage, then joined worker collection/flush, then clear pending staging handles. The staging span includes blockfile work, row copies and per-vector handle digests; it is not pure physical-write time. Document decoded-cache hits cannot remove this first durable publication. Source: active `writer/wide_identity.rs:123–137`, `writer/owner_vector_store.rs:84–99`.

Dynamic stable insertion reports1568windows and1568owner registration calls for100000rows:1536full64-row groups and32groups of53rows. Peak active windows is32. Worker collection accumulates0.459865seconds and worker flush36.949167seconds. Those sums overlap across threads and include contention;36.949seconds is not elapsed insertion and cannot be subtracted from4.273seconds or added to staging. There is no retained disjoint insertion-core timer. The before_save all_registration_node_leases and home-message counts also include subsequent balancing, so they are not insertion-only dispatch attribution. The stable-specific counters are insertion-specific. The after-add phase confirms100Kadds/registers/navigations and zero splits, merges or reassignments. Its full-record store has only3point misses and no evictions. Cold centroid decoding therefore does not explain the initial add gap by itself.

Both insertions route against the initial single root leaf before any balance. The reference's packed-child centroid payload is absent during this phase, and its navigation initialization reports0.1microseconds. Packed internal-child scoring is not the reason this particular initial insertion differs. Both still perform FP routing and posting-code generation; the meaningful differences are input residency, durability, grouping, synchronization and authority publication.

## Reference behavior and necessary differences

The optimized reference splits the whole100Kslice into approximately3125rows per worker. Each worker assigns versions, shares embedding Arcs, routes against the stable tree and collects posting codes by destination leaf without appending to that leaf. The workers join; their deltas are regrouped by destination; each destination then takes one posting write lock and appends its complete group. For this initial tree there is one destination. Its version/embedding tables are local concurrent maps. Source: frozen reference `writer/writer.rs:477–638`.

The connected path already routes and quantizes in parallel, but flushes each at-most64-row window directly to its owner. Each flush takes a destination node write lease, validates centroid bits, acquires deduplicated identity stripes, reserves home-authority entries, calls the owner to atomically install posting/current-version/content-handle state, activates authority, and marks node/version work. Thus32workers repeatedly contend on the same root's node lease while submitting1568small batches. The grouping boundary, rather than per-row routing correctness, differs from the reference. Source: active `writer/writer.rs:315–341`, `writer/reference_owner_adapter.rs:614–647`, `writer/wide_identity.rs:128–135`.

Immutable handles, stable64-bit IDs and atomic posting/current-version publication are required by the chosen connected owner design. Bounded staging is required to avoid retaining a complete input corpus as resident vectors. The current contract requires durable vector handles before membership becomes authoritative; copying the reference's commit-later assumption would change that contract. Identity/owner authority and error rollback also remain necessary for later transfers. Their exact message count, one-node-lease-per64rows, and the64-row flush boundary are implementation choices, not inherent requirements of sharding. Public add_phase already excludes balance, placement and publication while its stable tree is being collected; immediate external visibility inside each64-row window is not a public phase guarantee. Any new buffering must preserve complete visibility when the public phase returns and before balancing, rather than weaken existing mutation semantics silently.

Provider/cache settings and allocator differ as well. The reference uses resident vectors and jemalloc with a reported1GiB block cache. The dynamic arm uses durable16KiB vector blocks,256MiB byte-charged provider cache and384MiB decoded document cache. These affect the pipelines but are not a measured explanation for a particular insertion-core duration. Aggregate operation, cache and balancing counters cannot resolve them into additive wall time.

## One promising reference-like experiment

The most focused candidate is a default-off joined-stage regroup: retain the existing8192-row durable staging and64-row per-worker computation admission, but return each worker's bounded deltas to a stage coordinator instead of flushing the same leaf after every64rows. Join the workers, regroup only this admitted stage by destination in deterministic input/worker order, and flush the root or other destination under one node-lease interval. This follows the reference's collect-join-regroup-append shape without buffering the entire100Kcheckpoint or changing durable vector handles, balancing cadence, routing choices, cache policy or posting codes.

A complete treatment must actually reduce destination node leases/owner appends, rather than merely move64-row callback loops behind a new function. The existing register_new_batch and home reservations cap requests at64. A safe larger stage flush needs an explicitly admitted owner append transaction, atomic capacity/current/version/handle installation, and bounded home reservations/identity guards held in stable stripe order through the reply. Home reservations may remain bounded subrequests even if posting append and node publication coalesce. Failure before append cancels reservations; failure after append poisons the writer or completes the existing publication contract. Destination centroid/placement is rechecked before flush. Initial admission should remain append-only, joined, single-owner, nonpaged, one-copy; unsupported modes retain their accepted path. No dense ID mirror or replacement transport is proposed.

The extra stage delta buffer needs checked bytes for8192IDs, versions, codes, grouping metadata and simultaneous worker/aggregate copies. Current per-worker1MiB windows and128MiBstaging remain separate budgets; neither automatically admits a new coordinator buffer. A fixed129-row oracle should compare exact ordered destination IDs, versions, codes and full immutable handles through partial windows, one destination and several destinations. It must cover duplicate/capacity rejection, reservation rollback, postappend publication failure, and saved current/old generations. A negative-control many-destination tape should retain cases where regrouping offers little benefit. This is a proposal only; no implementation or new run is authorized by this note.

For any later experiment, the primary common outcome remains full source-to-insertion-complete cost with all vectors usable for the next balance, plus complete-build cost. Preserve separately timed input validation, input load/decode/hash, durable staging, and joined collect/regroup/publication spans. A future dynamic insertion-core interval can start with a verified staging chunk already available and stop after membership publication; its stronger durability postcondition must still be labeled beside the resident reference. Do not derive that interval by subtracting overlapping callback sums. The current receipts support source-level staging and flush-contention hypotheses, not an exclusive decomposition or projected gain. The prepared-split comparison remains the current priority.
