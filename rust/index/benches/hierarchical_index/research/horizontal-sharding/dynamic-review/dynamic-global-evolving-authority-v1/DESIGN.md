# Owner-authoritative leaf splitting in a bounded local tree

The tree changes its branches through the actors that own their postings and current versions. A coordinator chooses global destinations and updates tree structure. The coordinator does not keep a reference writer, corpus embeddings, posting lists, codes, or a current-version table. This is a local, serialized correctness slice; it does not implement a distributed service or establish a quality or performance result.

## The pieces

- Owner actors hold mutable leaf postings, current versions, and durable vector references. A vector reference names a saved vector-data root and a row key. Actors read the referenced vector when a predicate or registration needs it.
- The coordinator holds node IDs, parent links, centroids, ordered child lists, branch placement, and an ID-to-current-location directory. A version query follows that directory to the actual owner; the directory does not answer versions itself.
- A prepared operation keeps a complete previous owner-state backup inside each owner. Working postings and versions remain private until the complete supported operation passes admission. The backup is bounded and copied locally; this implementation does not claim that preparing an operation is proportional to its changed rows.
- Saved blockfile roots name immutable reader versions in this experiment. One save includes actual owner-written postings, current versions and leaf records, plus coordinator-written internal records, centroids, root ID, next node ID, and removed-node tombstones. There is no new publication pointer.

## Supported operations and admission

The opt-in operation supports full-precision global navigation, full-precision neighbor-posting analysis, one replica per vector, at most 128 live vectors, and at most four local owner actors. Merge thresholds must be zero. The starting tree is one root leaf or one internal root whose children are leaves. Root-leaf splitting creates a new root. Splitting a child replaces it with two new stable IDs, appends them in reference order, updates their parent links, and recomputes the root centroid and code with the reference arithmetic. Recursive leaf balancing follows the reference depth limit of four.

Merge operations, internal-node splits, multi-level parent edits, root collapse, replication, and quantized navigation or neighbor analysis are outside this slice. Configuration, owner-directory and initial parent-headroom checks reject before a vector write or owner preparation. Data-dependent structural growth is evaluated only in private prepared owner state. A branch overflow or remaining outer balance round discards that private preparation and restores the committed routing, location directory, owner state, and saved-vector reference; no committed authority changes or eligible save results from that preparation. Private vector forks can remain unreferenced. This is an exclusive local admission mechanism, not a recovery protocol or a claim that private preparation performs no writes or mutations.

The existing fixed-topology APIs remain separate. Their normal save path returns the same unchanged internal root when no structural tombstones exist. The new operation has no CLI activation and is not connected to the parent's evaluation runner.

## The operation

1. **Check the operation boundary.** The coordinator checks the supported configuration, dense new-ID range, actual branch owners, input dimensions and finite values, and parent headroom. It saves the new vector to a private immutable root and starts owner preparation.
2. **Register at the actual owner.** The coordinator runs the reference global navigation and sends the selected leaf and durable vector reference to its actor. The actor appends the code and version to its own posting and current state.
3. **Split from owner-supplied live rows.** The source owner scrubs stale rows in the reference swap-remove order and supplies only the affected leaf's current rows and vectors. The coordinator uses the reference split routine, assigns the next node IDs, and asks the source owner to install both replacement leaves. Existing membership versions and vector references remain unchanged during this structural replacement.
4. **Apply immediate neighbor analysis.** Self-group and neighbor predicates execute against actual owner current versions and durable vectors. Each neighbor's posting order and centroid are captured at that scan's start, while each row's version is checked when it is evaluated. An earlier registration therefore affects later checks. The shared evaluated-ID set, predicate arithmetic, global destination ordering, version increment, and recursive balance order follow the reference. The coordinator sends versioned handoff commands directly between source and destination actors; it does not mutate a central version map and mirror it afterward.
5. **Install only a complete prepared operation.** Owners retain their old state until the supported operation finishes. The coordinator installs complete owner states under its exclusive operation boundary and refreshes the structural and location metadata. These local messages do not provide a distributed atomic commit or failure-recovery guarantee.
6. **Save the complete reader version.** Each owner writes its actual current postings and scalar versions into private forked blockfile writers. The structural helper removes retired leaf metadata, postings, and centroid keys, writes current internal metadata and centroids, and persists root and next-node counters. Old roots continue to name their previous bytes and memberships.

## Evidence and independent oracle

The meaningful positive test uses 101 vectors with 32 dimensions. It starts from a one-vector ordinary saved root and runs the remaining 100 additions through actual owner authority. The first five coordinates are deliberately separated; 91 far-branch vectors derive from the pinned retained fixture, and five final additions exercise the cross-owner split witness. These are constructed local correctness inputs, not a new real-data quality cohort. The exact input bits are retained in the result.

After the first root split, the test transfers an actual branch from owner zero to owner one and verifies that the source owner no longer answers the moved row. Every addition uses the same add-then-balance schedule in the reference. Test-only tape replay supplies the exact random split decisions, so this test checks construction equivalence conditional on those decisions; it does not claim that independent random runs produce the same tree.

The test compares the hooked semantic boundaries for all 100 additions: add destinations, actual owner registration code bytes and vector bits, replacement IDs, global neighbor discovery, pre-scrub versions, neighbor row ordering, per-row current versions and eligibility, global reassignment destinations, and versioned registration. Self-group predicate events are intentionally omitted by this normalization because the reference hook does not emit them. Extra preparation, self-group predicate and owner-polling events are retained separately. This is not a claim that every internal reference event has a trace counterpart. Every add also compares all node IDs, parent links, ordered children, centroid bits, centroid-code bytes, root ID, and next-node ID with the reference.

At 96 and 101 rows, the test compares saved postings in full: leaf IDs, physical row order, current and stale versions, code bytes, all vector bits, scalar versions, and persisted centroid bits. The saved-reader census checks complete root-reachable current membership across all IDs, rather than only full-precision rerank results. A retained 96-row reader produces the same report after the final changes, and every object present at the 96-row checkpoint retains its exact hash. The initial one-row saved reader and all its objects also remain unchanged.

The positive sequence requires an actual cross-owner eligible neighbor and an earlier versioned registration visible to a later pre-scrub query. It ends by checking that missing parent headroom rejects before any further owner preparation or registration. The negative admission test checks missing and wrong owners, enabled merges, and a multi-level structure; the latter two reject without owner preparation or new registration. It also crosses the checked event cap only after actual private registration and a root split. That case proves that abort restores every owner current/posting table, routing, root/next counters, location and branch directory, tombstones, vector reference, and parent binding. It then saves the restored four-row state and checks full saved census, posting/code/vector parity, absent rejected ID, and unchanged old object hashes. The test retains the private split events and advanced preparation/registration counters, so discarded private work is not described as no mutation.

## Bounds and cost labels

The existing authority limits retain at most 128 current rows, 256 physical rows per owner, four owners, 16 cached vector-root readers per owner, a 4,096-dimensional input cap, and a checked 1,024-node routing cap. The operation checks a 10,000-event report limit. Some checks follow reads or a complete prepared operation; these are not provider-decode, allocation, process-memory, or preallocation guarantees. Blocking actor sends and joins have no independent aggregate deadline; the local subprocess stages have finite 1,200-second limits and ten-second reply waits.

The source actor can return a bounded full-vector split group to the structural coordinator. Subsequent neighbor predicates do not copy a full owner state to the coordinator. The counters record actual returned vector payload, actor commands, posting payload copied into preparation backups, current records copied, and actual predicate evaluations. They exclude container allocation, provider cache retention, encoded storage traffic, network traffic, RSS, and CPU time. Repeated durable-root opens and provider caching remain explicit costs.

The implementation retains global routing metadata and the full ID-location directory. Every prepared operation copies all owner posting/current metadata and backs up the coordinator routing, location and placement metadata; the current counters exclude the coordinator backup bytes. Every save writes all current owner postings. These costs remain O(corpus) within this bounded implementation. Source-vector reads, global navigation, complete oracle saves, old-object hashing and saved censuses are charged correctness work, not a speed claim.

## Source epochs and failures

The initial epoch fails to compile because the new test treats range iterators as vectors and tries to serialize the unmodified root-ID type directly. No test executes and the check is skipped. Repair V2 compiles: the negative test passes, but the positive test fails because its reference schedule omits the separate balance call. Repair V3 corrects that schedule and reaches the final save comparison, where the test incorrectly forks the final reference save from the initial root after a 96-row commit has cleared dirty state. That test failure is retained. Repair V4 corrects the reference parent and passes the full positive test and benchmark check. Repair V5 adds explicit initial parent-headroom admission and its representative rejection assertion; the positive test and check pass. Repair V6 adds exact missing/wrong-owner assertions to the negative admission test; that test and check pass. Repair V7 extends that same negative test with post-preparation root-split discard and restored-state save assertions. The unchanged positive test and production files remain bound to V5.

## Remaining integration

This slice is an opt-in local owner-authoritative structural implementation. It does not replace the default central writer, activate the previous live-owner callback in production, implement internal splitting or merges, dispatch durable state across processes or machines, or establish matched two-million-vector quality. Owner processes, remote vector access, concurrent mutation, distributed commit, recovery and publication integration are not implemented here. The preparation experiment remains shelved, and no cloud or evaluation controller runs as part of this package.
