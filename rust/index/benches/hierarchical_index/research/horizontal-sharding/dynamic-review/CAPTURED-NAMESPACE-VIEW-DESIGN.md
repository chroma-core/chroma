# Bind namespace identity to one captured registration

A complete registered bundle binds the current record store, vector snapshots and identity table together. The identity table's construction history describes its preceding inputs; it does not authorize a new write against the current collection. The next adapter keeps those two roles separate.

The current view comes from the existing compactor's captured collection and complete segment set. The selected vector segment contains the registered hierarchy-bundle reference. The adapter checks that exact artifact, the bundle's collection-version/log relationship and its complete current deployment using the existing validation path. The bundle must contain one namespace-root reference and the exact record segment ID/files. Missing namespace metadata rejects by default; legacy bootstrap requires a separately completed identity audit against independently bound shared source bytes.

The current bundle must independently bind the namespace reference, record roots, canonical vector descriptor and owner map descriptors. The namespace auditor checks these identities against the parsed namespace root before reading its payload or opening record readers. The root's construction-parent fields remain provenance. The saved construction receipt must match them when supplied as proof; no unrelated caller-supplied pair upgrades either field into authority. The current write fence comes only from the captured enclosing deployment and collection context.

The existing constructed fixture supplies an explicit shared identity source before either store is built. The next positive fixture uses the same rule to create a parent bundle with actual record and vector roots. Record insertion is permuted, while global IDs follow the shared source. Two distinct users have equal vectors. A namespace table that swaps them rejects. Its registered bundle and all artifacts remain private local fixture data under the fake collection authority; no production authority is claimed.

The actual materializer uses the exact retained record reader and private checked allocator from that current view. It validates the complete raw window before assigning append global IDs separately from actual record offsets. The export carries both IDs and retains exact user/vector bits, source offsets, current registered descriptor reference, current deployment fence and parent namespace artifact. The default equal-ID adapter remains unchanged and rejects this protocol.

The candidate record writer flushes the actual materialized result into private roots. The selected-leaf writer saves the coordinator-selected global IDs without rerouting. A preparation hook then creates the candidate namespace root against the actual candidate canonical vectors and owner maps. It preserves every old identity row and records the exact prior namespace artifact. A fresh record provider fully audits the candidate against these saved artifacts before the hook returns eligible metadata.

The existing task seals one bundle containing the candidate namespace reference, actual record segment outputs, vector deployment, ownership roots and source export. The existing collection registration proposal includes the complete segment set and the single bundle reference. No namespace pointer or local deployment pointer advances independently. A partial record flush, sidecar error or audit mismatch poisons the private attempt, retains its artifacts and blocks bundle eligibility. Retry starts from the captured immutable parent with a fresh private allocator.

The first runtime remains a tiny local fixture. It must retain the actual export, both saved-leaf membership responses, full parent/candidate namespace audits, exact record inventories and the complete fake-authority proposal. The existing full worker build blocker, production context/server integration, remote transport and u32 namespace ceiling remain explicit. This design does not grant cross-call trust or remove the full audit and 100,000-row cap.
