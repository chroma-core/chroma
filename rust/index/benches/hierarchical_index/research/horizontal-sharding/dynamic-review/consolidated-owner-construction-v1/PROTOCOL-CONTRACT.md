# Publish a combined owner construction for saved-index diagnosis

The existing native construction command can publish a complete original checkpoint after its saved-state audit. Its reference arm and combined owner arm use the same explicit floating-point navigation and neighbor predicates, construction settings, thread count and logical balance cuts. Their random split schedules remain independent.

The command remains `reference-owner-diagnostic --spec PATH` with protocol `reference-owner-parallel-v1`. The new optional `publish_checkpoint` boolean defaults to false, preserving the existing command's output and storage behavior when omitted. For the combined owner policy, set `treatment="owner"`, `predicate_batching=true`, `batched_scrub_validation=true` and `direct_current_reads=false`. The result echoes `construction_policy="owner-batched-v1"`. Other explicit ablations remain available and echo `explicit-ablation`; no existing policy default changes. The ordinary reference arm keeps all owner-only flags false.

When publication is enabled, the command creates `store/id-map-1.u64le` once, streams dense global IDs as little-endian u64 values, hashes the written bytes and reopens the persisted map through the existing hash-verifying lookup. It creates `store/manifest.json` once from the audited five roots, root ID, configuration, source/spec/prefix binding and verified map descriptor. An existing manifest or map causes a create-new failure. No admitted manifest is rewritten downstream. The result's `checkpoint_publication` binds the original manifest hash/length, map descriptor and separate map write/verification byte counts and elapsed times. Publication elapsed includes both map operations and the manifest operation; it is separate from saved-state audit and five-root save.

The unchanged `diagnose-ground-truth --spec PATH` command consumes that manifest directly. Its specification pins the manifest, exact ground truth and held-out query files by full length/hash, selects expected cardinalities, and supplies global range and map bounds. Complete unique GT membership and strict saved current-version/deletion checks remain mandatory. The manifest names one global saved snapshot; diagnostic owner count does not measure live actor fanout.

The bridge writes and verifies eight bytes per vector per arm: 512 bytes each for the local 64-row proof and 65,536 bytes each for a future 8,192-row arm. These are logical payload counts, not physical I/O. The current source/input admission still verifies the consumed prefix while full-source SHA admission is external, exactly as in the existing native command. No real-data command, deadline, Linux binary or cloud authorization is supplied by this local package.
