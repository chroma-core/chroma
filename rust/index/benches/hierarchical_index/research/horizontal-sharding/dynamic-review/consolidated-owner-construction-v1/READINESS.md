# Consolidate accepted construction work before another performance experiment

The next coherent milestone combines grouped scrub validation and immutable predicate batching in the reference parallel owner adapter, then publishes an original saved checkpoint that the existing ground-truth diagnostic can read. Direct current pointers remain disabled. This connects accepted work removal to a usable tiny construction and evaluation path instead of adding another isolated profiler. No implementation or new run occurs in this readiness assessment.

The accepted scrub pair demonstrates the message mechanism within one arm: 958,772 requested physical rows use 17,952 owner callbacks, avoiding 940,820 individual dispatches counterfactually for those same rows. Balance has 182,835 current callbacks, of which 164,883 remain live individual checks outside grouped scrub. About 105,000 pure predicate callbacks remain. Whole-child system CPU and switches decrease, but split/merge work differs and concurrent elapsed sums overlap. The result supports consolidation without claiming a causal wall-time ratio, network saving or ANN-quality gain.

The two policies already fit the same joined-phase wrapper and native specification. Grouped scrub changes only how a current scrub obtains authoritative versions under source-node and ID transfer locks. Immutable predicate batches change only pure vector/center calculations. Each NPA row still checks its current version and evaluated-ID set at the original point and immediately performs reassignment. Predicate callbacks acquire no ID or node locks and wait on no other actor, so they add no lock cycle with scrub's coordinator-held ID locks. Immutable add-only vectors and captured center bundles remain the scope assumption. A combined test is still necessary because the resulting actor scheduling differs from either policy alone.

The main publication gap is concrete. The reference-owner diagnostic saves five roots and a result, while the ground-truth command requires an original generation-local snapshot manifest and explicit local-to-global map. The existing global constructor creates that format but uses the separate serial authoritative implementation. Reusing its compatible publication shape in the parallel adapter must stream an identity map, hash and verify its actual bytes, and create the snapshot manifest from the actual saved roots before returning. It must never patch an admitted manifest downstream. At 8,192 rows the map writes and verifies 65,536 bytes per arm; report both costs. The saved construction configuration must preserve explicit FP navigation/NPA and the exact source-prefix binding.

The bounded implementation cut is one supported combined policy with `batched_scrub_validation=true`, `predicate_batching=true` and `direct_current_reads=false`, plus an optional native checkpoint publication bridge. The ordinary reference arm uses the same construction configuration, threads and logical balance cuts. Existing diagnostic ablation flags and defaults remain available. The local correctness package should run the existing multi-region construction with both policies enabled and verify current membership, saved codes, vector bits and pinned old readers. It should then construct both actual native arms, emit their original maps/manifests, and invoke the existing ground-truth command on each with an independent small set oracle. No constituent twelve-test suite or performance experiment needs repetition merely for unchanged mechanisms.

The smallest future matched quality diagnostic keeps the retained 8,192-vector prefix and the existing frozen sixteen held-out query vectors. It must recompute top-100 ground truth for this exact prefix using the existing blocked float64 exact engine. Filtering the two-million-vector ground truth would omit prefix neighbors and is invalid. That engine currently sizes its corpus from the whole input file, so the minimal no-engine-change setup writes one separately charged 25,165,824-byte evaluation prefix file and binds its hash; it does not copy the full corpus. The original construction continues to consume the pinned prefix directly. No query embedding, corpus download or new dataset is needed.

The first matched report should compare saved GT-bearing leaves and minimum leaf/weighted-row coverage under the diagnostic's complete-GT and single-current-copy checks. It is a construction locality diagnostic, not measured ANN recall or search latency. The existing harness reads one global saved root per arm; its owner count is therefore one saved snapshot, not the number of live construction actors. Logical actor fanout would additionally require a hash-bound reachable-leaf-to-owner directory from the joined construction; it must not be inferred from aggregate owner counts. That metadata can remain a clearly separate prerequisite if the initial report covers leaf locality only.

The saved-reader diagnostic enforces a 4,096-leaf bound, so the actual saved shape must pass before diagnosis. The wrapper still caps 8,192 vectors, 768 dimensions, eight owners/workers and 32 phases. It retains a full shared embedding cache, global node/location/conflict metadata, owner-zero initial version admission, whole-leaf snapshot/flags, joined full publication and full saved audits. This is usable only as a bounded local construction POC; consolidation does not establish two-million-row readiness, physical distributed execution, an industry comparison or a 100B capacity result.

A future single paired experiment can retain the existing 30-second construction-arm limits and separately bound prefix/GT preparation and saved diagnostics under one fresh externally authorized deadline. The parent owns its final budget and runner/resources. No cloud launch, automatic larger prefix, new transport or additional profiler cycle follows from this proposal.
