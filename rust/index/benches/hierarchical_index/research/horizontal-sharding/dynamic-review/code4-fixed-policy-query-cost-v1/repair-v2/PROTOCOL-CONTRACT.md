# Costs at frozen observed quality

This protocol describes query costs for three saved global trees at their fixed observed recall. It does not claim 95% recall, exact matched recall, population equivalence, or distributed execution. The original evaluation remains consumed and target-not-met. The recovered means are 94.30859375%, 94.7421875%, and 94.44140625%; both paired 99% conditional intervals fit within ±1 percentage point. This new protocol supersedes only the older cost proposal's requirement to pass the full quality gate for this narrower descriptive comparison. It leaves that failed quality gate and its inference unchanged.

The three arm names describe how each tree is constructed: ordinary parallel reference construction, construction with one local owner, and construction with four local owners. Every query reads one saved global tree on one machine. It does not dispatch queries among owners or measure network communication. The saved construction epochs precede the newer live-prefix and split-input changes.

## Frozen work

The experiment reuses the exact existing native binary, original manifests and maps, immutable Code4 overlays, and 256 consumed evaluation queries. The full runtime template binds their hashes. Full-precision navigation uses per-level beams 36, 38, and 36. Each request scores the same selected postings, retains 400 candidates, performs 400 exact reranks, and returns 100 IDs. Stage tracing is disabled for this cost measurement. Every warm-up and retained reply must match the prior evaluation's IDs, FP32 distance bits, and scalar work counters. No GT labels are reloaded and no new quality inference is performed.

Each arm has one persistent native reader process. Arms run in fixed reference, dynamic1, dynamic4 order. Each process receives all 256 queries once for warm-up and then three retained passes in the identical frozen order. The protocol averages the three measurements within each query before summarizing the 256 query means. These repeats do not create 768 independent queries. No additional passes, tuning, seed search, or retry are permitted.

## Measurements and boundaries

Native elapsed time covers the existing query implementation with work and vector-access observers enabled. The client separately measures serialization, local-pipe round trip, response decoding, and the complete request call. These timers have nested scopes and must not be summed. Response validation and derived evidence writing occur after the client request timer but inside the process lifetime; a native child can wait for its client during that work. The existing bounded local-pipe client is reused without a new transport or service.

Whole-child user and system CPU, context switches, and elapsed time cover process startup, warm-up, all retained passes, and exit. CPU divided by that exact whole-child elapsed denominator reports average consumed CPU cores; it is not per-query CPU. Child maximum RSS is the operating system's cumulative child high-water observation and cannot isolate each arm's peak when earlier children have larger peaks. No sampled RSS curve or physical device I/O is collected.

Startup reports retain reader-open time, full-precision centroid preload, and Code4 overlay load/current-posting materialization. Overlay code payload, preparation observations, and the prior overlay-creation cost remain charged separately. Loading an existing overlay is not free and does not remove the original Code1 store. The first warm-up client request includes startup waiting and is reported separately. Subtracting nested timers from whole-process time does not identify pure startup CPU.

Every process creates a fresh provider cache with 256 block-capacity units, 4,096 root entries, one shard, and no clear after an operation. Overlay and centroid loading warm provider caches before ordinary query work. The operating system's page cache is uncontrolled and is also affected by input hashing and earlier arms. Fixed arm order therefore confounds elapsed differences with operating-system cache and ordering effects. This is a short descriptive measurement, not a causal latency study.

Vector-access evidence reports logical gets, reader pins, provider hits and misses, encoded storage-origin returns, and decodes. The copied accepted aggregate validator marks traffic unavailable when completeness cannot be established; a truncated point-key map is never called complete. Encoded provider-return bytes are not physical disk bytes, network bytes, or a billable request count. Full reply JSON is retained as derived serialization of parsed replies; pipe-response byte counts measure the bytes actually received before parsing. No request vectors, source vectors, GT files, compressed code payload, or store objects enter the retrieval archive.

## Admission, limits, and evidence

The controller validates package members, exact binary and build receipt, source-manifest hash, original selection and lock, recovered inference, all three snapshots and dense maps, every overlay file, prior evaluation result descriptors, and the 256-query order. It writes and fsyncs a full cost-plan lock before starting readers. Original store inventories, selection, overlays, and query hashes must remain unchanged after the experiment. Full hashing is logical host read work and warms the OS cache; it is outside per-request timers but inside the scientific bound.

A future externally guarded window is at most 900 seconds and $0.15. There is no build. The controller allows at most 120 scientific seconds, 30 seconds per arm, and 90 seconds of shared reader time, while preserving at least 180 external seconds for evidence and shutdown. A Linux alarm enforces the scientific bound. Each parsed reply is capped by the existing client at 16 MiB; each derived-reply stream is capped at 150 MiB; all retained runtime metadata including the final formatted result must fit 512 MiB. Observed cumulative child RSS must remain within 8 GiB. Failure preserves partial derived replies, a per-arm failure receipt when a reader starts, and a failed final result. There is no retry.

The smallest meaningful decision is whether per-query and whole-child cost descriptions differ materially at these frozen observed policies, and which measured work or provider traffic accompanies them. Different beams and independently built trees still perform unequal work. No speedup, physical-owner fanout, network, generalization, or 100B throughput claim follows. A failed numerical/work pin invalidates the cost comparison rather than allowing a replacement policy.

## Local verification and execution interface

The focused local test uses real imported admission, overlay, reader, counter, traffic, and summary modules. Fake files validate all three snapshot admissions and full closure checks, including corrupted overlay rejection. A bounded fake subprocess emits a retained native-shaped response for 1,024 persistent requests. The actual summary CLI serializes its output file and stdout. Tests also reject changed IDs, reject an accepted-quality substitution, and check the operational CLI fails closed without Linux runtime admission. No native build or real query-vector input is used locally.

The operator fills only the externally supplied absolute deadline and a fresh output directory in the frozen template. The concrete command is `python3 run-cost.py --spec /absolute/path/filled-spec.json`. The template already specifies the exact retained remote paths. The package does not start machines, upload files, install dependencies, alter lifecycle guards, or grant its own execution admission. Python's standard library is sufficient. The exact native binary already exists at the path pinned by the template.

The cohort IDs use the exact `canonical-doc:<row>` strings from the retained evaluation results. The local admission fixture binds the complete 256-ID sequence to that retained evidence and rejects numeric-only IDs. The controller explicitly sets Tokio and Rayon to four threads, and OpenBLAS, OpenMP and MKL to one thread, matching the accepted quality-reader environment. The plan lock records these exact values and the host logical CPU count. Every native child inherits this same fixed environment; configured threads do not demonstrate useful query concurrency.
