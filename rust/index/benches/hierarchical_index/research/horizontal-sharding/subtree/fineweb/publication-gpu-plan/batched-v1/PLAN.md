# Batched conservative reference epoch

The new engine batches interval construction and candidate selection across at most 32 queries while keeping each query's exact answer independent. It preserves the tested engines and their entry points. This epoch has CPU proof tests only; no CUDA runtime, GPU timing, new reference pool or infrastructure launch is claimed.

The engine uploads each source block once, scores one bounded query batch, constructs float64 outward endpoints, and updates each query's kth upper endpoint using every current row before filtering. It retains all coordinates whose lower endpoint is less than or equal to that query's threshold. Equal distances remain uncapped. One coordinate matrix transfers to the CPU for the batch, and exact float64 reranking processes one query at a time with distance/global-ID ordering. No vector tensor grows with the full query pool or with all queries' retained candidates. Source mappings close at the end of each chunk.

The numerical argument is row-wise. For each query, the kth upper endpoint over the processed prefix is at least the final kth true distance. A row with a greater lower endpoint cannot enter the global top-k. Retaining equality preserves all cutoff ties. Batching changes how independent rows of this calculation execute, not the intervals or cutoff. The certified scalar bound is computed for every query in one vectorized CPU call using the symmetric norm product and the existing overflow gate. All device endpoint and selection operations remain float64. Strict FP32 score arithmetic, subnormal rejection, overflow rejection and full-score checks on rejected rows remain required.

The new source files are `reference_batched_filter.py`, `reference_batched_engine.py` and `test_reference_batched.py` under the existing tools directory. The callable scan is `batched_reference(..., expected_rows=..., query_block=32, corpus_block=32768)`. The CUDA adapter initializes the unchanged strict scoring runtime and then compares complete batched endpoint/threshold/selection histories against CPU and scalar contracts. It does not replace the existing command-line engine or publication launcher. Independent source review and a separately bound launch wrapper remain prerequisites to hardware execution.

Twelve new CPU tests compare complete outputs to the full float64 corpus oracle and to the preserved scalar engine. They cover multiple source chunks, query-batch tails, processed prefixes smaller than k, all ties, signed near-bound errors, cancellation, precision probes, wrong shapes, nonfinite bounds, subnormal inputs and overflow. An all-tie case retains every row and checks the batch transfer count. The complete numeric suite has 32 passing tests. These tests establish the CPU algorithm contract; CUDA conformance remains untested.

For 11,000 queries, dimension 768, 32,768 corpus rows per block and top-100, the device planning allowance is 2,742,754,304 bytes. It includes all-tie coordinate output, simultaneous float64 matrices, persistent upper state, doubled visible allocations and a two-GiB workspace allowance. It is not a vendor workspace bound. Hardware admission must keep it below half the currently free device memory, then record actual Torch and device-memory peaks and preserve any OOM failure. The old 200-query path remains the fallback.

# Future hardware gate

Linux owns any new sandbox GPU. No terminated GPU is restarted, and no existing timed worker supplies data. A future single L4 slot uses the verified sandbox account, a freshly checked compatible AMI/runtime, the pinned wheel lock, encrypted root storage of at least 150 GiB and private version-bound S3 inputs. It uses a fixed 60-minute instance deadline, an independent stop/termination guard, a five-minute final preservation reserve, a 16-GiB process RSS cap and at least 64 GiB free scratch. The 10M canonical source is restored once; the 1M input references its byte-identical first-million chunks. There are no owner-vector replicas and no embedding/model installation. The source restore limit is 34 GiB of unique declared object payload; retries receive a separate at-most-one-complete-retry allowance of 34 GiB. SDK request/retry counts must be recorded separately, and these logical payload caps must not be described as measured physical wire traffic.

The planned compute ceiling is one hour. The last verified L4 rate is $0.9776/hour, and the prior 150-GiB/500-MiBps root adds about $0.03699/hour; reverify prices before provisioning. A future launch requires a defensible staging/install estimate below 900 seconds. Failed attempts retain distinct reports and count against the unchanged absolute deadline. If staging or installation exceeds that allowance, decline further work, preserve and terminate rather than extend the node.

1. **Verify immutable inputs before CUDA.** Bind exact source files, prepared manifests, all source chunk hashes and counts, both old 200-query CPU references, the 11,000 embedding chunks/JSON, frozen text IDs and the runtime lock. Verify that the 1M chunks are an exact prefix of the same 10M bytes. Keep the 1,000 calibration and 10,000 test identities disjoint from the 200 integration queries and from each other.
2. **Establish arithmetic and workspace.** Run the unchanged strict FP32 precision/pathology probes and the new complete batched endpoint/threshold conformance histories. Fail closed on any discrepancy. Admit projected device memory before scan, then record actual peaks. Bound initialization/probes to 180 seconds. Report initialization, hashing and source staging separately from scan time.
3. **Compare both engine epochs on known answers.** Run the preserved scalar and new batched scans against all 200 independent 1M and 10M references with identical k, blocks, queries and cache policy. Every ID and float64 distance must match; each engine still validates three complete score queries, including rejected rows. Bound this stage to 600 seconds and retain separate reports for every completed scan. Kernel-only time does not establish an end-to-end improvement.
4. **Measure fixed and incremental costs.** Run the frozen new-query prefix at 32, 128 and 256 queries only while deadline admission permits. Keep full-score checks enabled on the same first three queries in each recorded correctness pilot. Record full-validation wall time separately from scan, source-copy/bounds, synchronized scoring, filter-plus-coordinate-transfer and CPU reranking. Do not infer that the difference between two pilots is entirely per-query cost; report all phase boundaries and memory peaks. No claim follows before actual CUDA measurements.
5. **Admit larger exact pools from measured costs.** Reserve full-source independent float64 oracles for at least three queries in every separately published pool. Preserved oracles may be reused only if their corpus, query-vector and method bytes are fully hash-bound. A new pool's selected-query answers must come from this independent full-prefix oracle, not its own candidate filter. Admit remaining work only when the larger of two measured per-query rates, multiplied by the remaining query count and a 1.5 margin, plus independent-oracle cost, source/input validation, output/archive cost and the five-minute reserve fits the original deadline. Complete 1,000 calibration queries first if admitted; 10,000 test references remain explicitly pending until a separately admitted complete run passes. Calibration tuning must not inspect held-out test results.
6. **Publish only complete proven outputs.** Require every corpus row scored, no candidate cap, exact query coverage, finite distances, stable global IDs and complete output hashes. Preserve runtime flags, numerical probes, retained counts, stage timings and both memory measures. Fully restore the compact evidence and output archive, then terminate only the new GPU and verify its root volume is deleted. No incomplete pool receives a completion marker.

This plan requests no launch. The current campaign's archive/capacity schedule and independent review control the next hardware slot. The exact 1,000-query calibration and 10,000-query test references remain incomplete.
