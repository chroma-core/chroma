# Canonical ten-million-row append gate

The append adds the next 100,000 real source rows to the existing ten-million-row tree. It keeps the 128 frozen ownership centroids, preserves every existing local-to-global ID prefix, and compares one-host and two-host execution of the same append task graph. Preparation and reference work wait for an isolated slot; they do not overlap timed index reads or compaction.

The canonical delta has global IDs 10,000,000 through 10,099,999. All rows lie in the pinned source file `data/00/train-part0__1333.parquet`, at source offsets 197,402 through 297,401. The source file starts at global ID 9,802,598, contains 1,082,319 rows, has 5,029,233,981 bytes, and has publisher SHA-256 `c7c60d068f017e6c5f986ea7c8a41e131e35be132648288aa903083e92368a58`. The retained source receipt pins its ETag and the dataset revision `3aea0b8d5f98741e343d07f067ce0f49dca1ccd2`. These offsets come from actual pinned parquet row counts rather than filename estimates.

Preparation first reads the bounded parquet footer and sums the compressed dense-embedding and UUID columns of every row group intersecting that source interval. It sets a sufficient source payload cap from those actual ranges plus metadata/retry headroom before reading vectors. The provisional maximum is one GiB of public source payload and 180 seconds; if the required verified ranges exceed it, the preflight reports the required cap instead of starting an undersized attempt. It decodes only those row groups, slices the exact source offsets, preserves float16 values exactly in float32 without normalization, and writes 307,200,000 vector bytes with stable original UUIDs. A separate decoder checks sampled boundary/interior rows and UUIDs.

The existing ten-million-row driver bundle supplies the model and 128 explicit maps. The base model SHA-256 is `e644f2af720d6952b9105668773809c7f6719c287aefb3fdaf686efb02016a81`. The append preparation invokes the existing spatial append API with `previous` bound to that input manifest, `start_id=10000000`, and the unchanged source identity, model and construction epoch. It writes only delta vectors and full old-prefix-plus-append maps. A full map audit checks all 10,100,000 IDs exactly once, every old map prefix against its immutable hash, and every delta value and nearest-centroid assignment. The read-only base UUID index is restored from its version-bound S3 descriptor into a new owned copy; inserting delta UUIDs into that copy rejects duplicates against the complete base as well as within the delta.

Preparation needs roughly 307.2 MB of canonical delta vectors, another 307.2 MB of routed vectors, 80.8 MB of full maps, and a 1.28 GB UUID-index copy, plus the bounded source cache and reports. The preparation scope cap is six GiB with a one-GiB stop margin, four GiB RSS with a 512-MiB stop margin, and a 16-GiB filesystem floor with four-GiB headroom. The whole preparation/reference attempt has a 30-minute limit. These caps exclude index snapshots and periodic checkpoint writes. Actual free space is checked on the chosen idle driver or preparation node before admission; no stopped node is restarted by this plan.

The existing pinned 100 calibration and 100 test embeddings remain unchanged. Exact references for the new corpus merge each complete ten-million-row top-100 answer with a fresh exact top-100 over the 100,000 delta rows, ordered by float64 distance and global ID. This union is sufficient because any omitted old or delta row already has at least 100 rows ahead of it in its own population. The result is a full 10.1-million-row reference, not a filtered reference. Three independent complete-corpus checks run on an idle host holding the prepared base owner files: they score every old and delta row in float64, assign scores by the verified explicit IDs, and perform a global distance/ID sort. They do not reuse the screened candidate set.

The index cases start from identical audited generation-one snapshots and use the same 128 append jobs, writer thread policy and checkpoint interval. Only placement changes. Each affected owner publishes a new immutable lower generation; an unchanged owner retains its older generation. The global manifest publishes atomically only after every lower audit and full ID-map check passes. Old readers remain pinned throughout publication. Final evidence distinguishes append computation, periodic checkpoint cost, publication/audit cost and storage amplification, and includes failed attempts and balance warnings. This is an append and recompaction experiment; initial construction timings do not substitute for it.
