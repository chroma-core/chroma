# Streaming preparation for larger real prefixes

The preparer keeps corpus-sized data on worker storage and keeps only a bounded batch and representative sample in memory. It reads the pinned source files in their recorded order, preserves each original UUID and source-row identity, converts float16 values exactly to float32 without normalization, and assigns stable global IDs from the contiguous prefix.

Verified chunks contain vector and UUID files, their digests, and the next source cursor. Atomic checkpoint replacement commits each chunk. Resume verifies actual bytes before using a chunk, adopts only complete verified chunks left between chunk publication and checkpoint replacement, and rejects changed configuration or corrupted data. The source download uses projected byte ranges without a retained source cache. A disk-backed unique UUID index checks duplicates across chunks.

The frozen boundary model uses a seeded sample without replacement across the complete requested prefix. It does not sample only the first source chunk. Routing streams each verified chunk through that model into owner vector files and explicit unsigned 64-bit global-ID maps. The final preparation manifest is published only after the model, UUID audit, routed files, and digests succeed. Logical slot count is configurable and stays fixed throughout a placement comparison.

Resume applies to source ingestion. The UUID audit, model fit, and routing stages restart locally; at most two incomplete routing directories are retained before the tool refuses another restart. The byte cap applies per invocation to fetched source payload, including repeated ranges. The wall limit is checked during source requests and at local-stage boundaries. Use an external process timeout for a hard deadline. A partial source-range audit can omit the final in-flight request after abrupt process termination; it is not a complete physical network counter.

The module is `tools.hierarchical_sharding.fineweb_stream`. Its command accepts `--manifest`, `--output`, `--count`, `--children`, `--epoch`, `--source-id`, `--chunk-rows`, `--batch-rows`, `--sample-size`, `--max-source-bytes`, `--max-wall-s`, and `--resume`. A completed directory is immutable and exposes `input.json` for the existing tree construction path. Defaults are conveniences for a bounded 1M preparation; larger epochs require the capacity and source plan described in SCALE-NEXT.md.

Local tests compare chunked and monolithic preparation byte for byte, interrupt and resume after committed chunks, reject corrupted bytes and changed configuration, and reject duplicate UUIDs across chunks. These tests establish preparation mechanics. They do not establish large-prefix throughput, model quality, query recall, or completed distributed index construction.

The real 1M validation uses a frozen 128-slot epoch, 32,768 representative sample rows, 12 clustering iterations, 100,000-row committed chunks, and 2,048-row streaming batches. Its per-invocation source payload cap is 4 GiB, preparation stage limit is 1,200 seconds, and external process timeout is 1,800 seconds. Existing 100 calibration/100 test embeddings receive newly recomputed exact answers over the entire 1M prefix. The distinct 1,000 calibration/10,000 test pool is frozen separately and remains text-only until its own embedding and reference cost gate.
