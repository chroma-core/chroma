These identities exclude all 200 integration queries and retain their recovered source text and source checksum. All 11,000 pinned texts have complete float32 embeddings with immutable chunk hashes. Exact references for the 1,000 calibration and 10,000 test queries remain pending because the measured scan does not fit the bounded GPU slot. Existing 200-query results and exact references remain a separate integration study.

Generate embeddings with the same pinned multilingual model and remote implementation as the completed integration check: model `Alibaba-NLP/gte-multilingual-base` at `9bbca17d9273fd0d03d5725c7a4b0f6b45142062`, implementation `Alibaba-NLP/new-impl` at `40ced75c3017eb27626c9d4ea981bde21a2662f4`, and query source `microsoft/ms_marco` at `a47ee7aae8d7d466ba15f9f0bfac3b3681087b3a`. Use the existing helper's tested embedding semantics rather than inventing a second pooling implementation.

The next embedding run starts with the preserved 16-query CPU check on the selected runtime. Compare dimensions, finiteness, norms and float32 values against that check with a declared device-specific tolerance. Then process immutable text batches into separately hashed output chunks with an atomic completion record. Resume only verified chunks with the same model, tokenizer, runtime, source and numerical settings; changed settings require a new output epoch. Calibration and test output paths remain separate. A partial run cannot count as a completed pool.

Do not mix embedding with an exact-scoring timing window. A useful GPU slot can run embedding after reference validation only if the pinned model/runtime is staged beforehand and the absolute slot deadline leaves enough measured time. Otherwise run it in a separate bounded sandbox slot. Establish per-batch memory, token counts, elapsed time and output identity on a modest sample before setting the full 11,000-query deadline. No GPU is held idle while deciding this.
