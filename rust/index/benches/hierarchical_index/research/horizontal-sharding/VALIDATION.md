## Remaining gates

The HTTP test uses separate local processes. It does not measure separate EC2 hosts or horizontal scaling. Spatial shard routing, shared remote subtrees, production log integration, updates and deletes, and automatic rebalancing between machines remain outside the implemented milestone.

Large benchmarks require optimized Linux binaries, construction calibration, resource counters, and a scalable exact-reference engine. The included exact scorer is a tiny-corpus oracle. Large shards also need a bounded-memory integrity audit; the worker's complete reachable-ID audit runs only up to 100,000 vectors. Insertions in the initial wrapper are serial, while balancing supports multiple threads.

The hardware plan starts with two r6id.16xlarge workers and a separate load driver, then expands to eight identical workers. The primary experiment keeps 32 logical shards fixed while changing physical placement. The existing Lyon node is busy building the MS MARCO checkpoint toward 99M under the shared benchmark lock, as reported by the Index Memory Optimizations chat on October 14, 2026. No cloud nodes were provisioned, no remote jobs were changed, and no benchmark results were published.


## Rust shared-core validation and scale limits

The Rust tree worker supports one-level remote traversal, selected-leaf candidate scoring, and exact scoring of the coordinator's selected vectors. Seven optimized Linux correctness tests pass, and ten repeated real-index tree smoke runs pass. These checks cover stale and deleted posting copies, distinct candidate budgets, immutable ID-map prefixes, persisted reassignment versions, failed-merge restoration, forced target disappearance, and parallel split/merge coverage after commit and reopen. The read-only diagnostic for the archived large checkpoint remains separate from these passing tests; a balance-limit warning still blocks a successful-compaction claim.

Readers keep their subtree snapshot fixed for the life of the process. A reader opens immutable block IDs and verifies the checksum of its immutable local-row-to-external-ID map. The global tree manifest pins each subtree's own generation and snapshot checksum; its generation does not have to equal the global tree generation. Appends preserve the mapping's existing byte prefix and reject a changed frozen-routing-boundary hash. A lower root can split and change its node ID while its upper routing slot stays fixed. Moving existing rows between routing slots requires a separate rebuild protocol.

The coordinator owns one candidate budget for the whole tree. Each worker removes stale or deleted posting versions and deduplicates live local IDs before candidate selection. Its local result includes every tie at the distance cutoff, then applies the budget using approximate distance followed by stable external ID. The union of these local top-M lists contains the global top M under that same ordering. The coordinator selects that global set before asking workers for exact distances. The rerank factor is a multiplier: k=100 and factor=10 allow 1,000 distinct candidates globally.

The block-cache budget does not bound total process memory. Raw posting, vector, and version-reader block pins are cleared after every operation, including failures, but materialized posting arrays remain in the reader as more leaves are visited. At dimension 1,024, each physical posting uses 149 payload bytes: 144 bytes for its one-bit code and header, four bytes for its local ID, and one byte for its version. Loading 100M postings therefore retains about 14.9 GB before centroids, duplicate copies, container overhead, and allocator overhead. Each process also has a 256-MiB block cache; multiple subtree processes on one host multiply that budget. The response's memory_bytes field estimates owned payload and does not report RSS, which is the operating system's resident-memory measurement.

Structural mutations serialize the period when a child is removed and its parent reference is replaced. That critical section includes vector loading and k-means, which divides a cluster into two groups. Neighbor navigation and distance evaluation run outside that long critical section. Each replacement registration briefly reacquires the lock so its version and target stay consistent. The lock therefore preserves topology but can limit balancing parallelism within one writer. Construction results must report balancing threads per subtree and identify the exact immutable binary used; passing parallel regressions do not establish parallel speedup.

The timed verified-v2 executable audits complete reachable-ID coverage only for subtrees containing at most 100,000 rows. Its larger snapshots reopen metadata without that full coverage proof. The separately tested audited-v3 executable requires full coverage for every published subtree, including those above 100,000 rows; these versions must remain distinct in benchmark evidence.

A bounded full audit can use one membership bit for each expected dense local row ID. Its bitmap needs N/8 bytes: 12.5 MB for 100M rows, or 125 MB for 1B rows. With 16 equal subtrees and 100M rows total, each subtree needs about 0.78 MB. The audit should walk the root-reachable topology, reject repeated or missing child references, read one leaf at a time, compare posting versions with the authoritative snapshot in bounded batches, and set bits only for live current IDs. It should reject IDs outside the expected local range and require every expected bit to be present. It must release that leaf's owned arrays and block pins before reading the next leaf; using the search loader without eviction would retain the whole posting set. Oversized decoded leaves need a declared resource bound. No raw embedding vectors are needed. The audit result must bind the subtree generation, block IDs, and map checksum, and its elapsed time must be included or reported consistently across benchmark placements.

A separate posting-cache policy is needed before broad large-corpus query sweeps. A simple bounded option releases only the selected leaves after candidate scoring and relies on the existing block cache for reuse. A byte-budgeted least-recently-used leaf cache can retain warm leaves while evicting older owned arrays. Both options need cold and warm measurements using the same policy for direct local and HTTP execution. They are proposals; the measured implementation retains visited postings.


The audited-v3 revision implements the streaming membership-bit approach and removes the 100,000-row publication skip. It compiles on Linux and passes ten enabled optimized correctness tests, with one read-only diagnostic ignored. The legacy smoke, remote tree smoke, and 100,001-row audit smoke all pass. The audit checks confirm no raw embedding reads or retained posting arrays, explicit resource failures, invalid topology rejection, missing and stale-row rejection, and publication rollback after a private flush. Its default limits are 256 MiB for membership bits, one million stored nodes, and 262,144 physical entries per leaf. The revision stores the audit result with its subtree generation, block IDs, map checksum, and elapsed time before publication. It remains separate from the timed verified-v2 executable; the pilot uses audited-v3 for the final real-data correctness gate.
