# Versioned writer with finer balancing jobs

The comparison gives both writers a shared queue of leaf jobs so a worker that finishes can take another leaf instead of waiting for a whole subtree. Each round snapshots jobs, sorts by descending physical posting size with node ID as the tie breaker, and uses an atomic cursor to assign jobs once. All workers join before the next round, and the eight-round cap remains.

The versioned writer keeps its existing posting versions, authoritative version metadata, caches, dirty tracking, merge reservations, registration checks, recursive destination balancing, storage format, and clustering code. One existing leaf-balancing reservation now covers the entire balance invocation, including loading, scrubbing, and its size check. This prevents a queued or recursive call from scrubbing a leaf already being split by another balance invocation. A guard releases the reservation on every return. This reservation does not replace the map locks or protect every neighboring scrub; neighbor scans retain the existing versioned mechanisms.

Active versioned rounds queue every leaf, including postings whose physical size lies inside the thresholds. Such a posting can hold stale rows that make its live size smaller. The original subtree scheduler visits and scrubs all leaves during active rounds; retaining that work preserves its cleanup and merge behavior. The version-free scheduler queues only eligible leaves because its physical count equals its live count. This is a representation-dependent maintenance difference, and benchmarks must report both raw and live posting counts rather than treating physical duplicates as corruption in the versioned writer.

A lone undersized root is excluded from merge eligibility and round activation, matching the version-free queue. It has no destination to merge into. Other nonroot eligibility uses the existing physical length; live length is checked after scrubbing. Work created by recursive balancing remains eligible immediately, while jobs created outside recursive paths appear in the next joined round.

This comparison measures the complete versioned and version-free algorithms with finer work distribution. It does not isolate version lookup cost: version-free moves use explicit physical transfers and claims, defer destination balancing to later rounds, and add serial immutable-input preflight checks. The versioned branch retains its original recursive destination balancing and supports stale versioned postings. Both fresh-build outputs require their corresponding reader and audit implementation.

Correctness tests check unique ordered jobs, stale visibility, skipping an already-held balancing invocation, all-leaf cleanup during an active round, concurrent leaf and parent splits plus merges, exact-once live ID coverage, matching current embedding codes, reachable parent/child topology, and persisted lazy reopen before any repair or balancing. Existing regression tests exercise reciprocal merges, arrivals during merges and splits, destination disappearance, version publication, and current parent/root recovery.
